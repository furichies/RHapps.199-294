Ejercicio Guiado
Implementación de varios plays
Escribir y usar un playbook que contiene varios plays.
Resultados
• Usted deberá ser capaz de construir y ejecutar un playbook para gestionar la
configuración y realizar la administración de un host gestionado.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start playbook-multi

Agregue la siguiente línea para indicar que el play se aplica al host gestionado

1.5.
Agregue la siguiente línea para permitir el aumento de privilegios. Aplique una sangría
de dos espacios en la línea (alineada con las palabras claves sobre esta) para indicar
que es parte del primer play.
  become: true
1.6.
Agregue la siguiente línea para definir el comienzo de la lista tasks. Aplique una
sangría de dos espacios en la línea (y alinearla con las palabras claves sobre esta)
para indicar que es parte del primer play.
  tasks:
 2.
Como primera tarea en el primer play, defina una tarea que garantice que los paquetes
httpd y firewalld estén actualizados.
Aplique una sangría de cuatro espacios a la primera línea de la tarea. Bajo la palabra clave
tasks en el primer play, agregue las siguientes líneas.
    - name: Latest version of httpd and firewalld installed 
      ansible.builtin.dnf: 
        name: 
          - httpd
          - firewalld
        state: latest 
Un nombre descriptivo para la tarea.
Aplica una sangría de seis espacios y llama al módulo ansible.builtin.dnf.
La palabra clave name, que es un parámetro del módulo ansible.builtin.dnf,
tiene una sangría de ocho espacios. La palabra clave name especifica qué paquetes
debe garantizar el módulo que estén actualizados. La palabra clave name (que es
diferente del nombre de la tarea) puede tomar una lista de paquetes, que tienen una
sangría de diez espacios en las dos líneas siguientes.
Después de la lista de paquetes, la palabra clave state especifica que el módulo
debe asegurarse de que esté instalada la versión más reciente de los paquetes. La
palabra clave state también es un parámetro del módulo ansible.builtin.dnf y
tiene una sangría de ocho espacios.

Agregue las siguientes líneas para definir el contenido de /var/www/html/index.html.
Aplique una sangría de cuatro espacios a la primera línea.

 4.
Defina dos tareas más en el play para garantizar que se esté ejecutando el servicio
firewalld y que se iniciará en el arranque, y permita conexiones con el servicio httpd.
4.1.
Agregue las siguientes líneas para garantizar que el servicio firewalld esté
habilitado y ejecutándose. Aplique una sangría de cuatro espacios a la primera línea.
    - name: Firewall enabled and running
      ansible.builtin.service:
        name: firewalld
        enabled: true
        state: started
• La primera línea aporta un nombre descriptivo para la tarea.
• La segunda línea tiene una sangría de ocho espacios e invoca al módulo
ansible.builtin.service.
• Las líneas restantes tienen una sangría de diez espacios y envían los argumentos
necesarios para garantizar que el servicio firewalld esté habilitado y se haya
ejecutado.
4.2.
Agregue las siguientes líneas para garantizar que firewalld permita conexiones
HTTP desde los sistemas remotos. Aplique una sangría de cuatro espacios a la
primera línea.
    - name: Firewall permits access to httpd service
      ansible.posix.firewalld:
        service: http
        permanent: true
        state: enabled
        immediate: true
• La primera línea aporta un nombre descriptivo para la tarea.
• La segunda línea tiene una sangría de seis espacios e invoca al módulo
ansible.posix.firewalld.
• Las líneas restantes tienen una sangría de ocho espacios y envían los argumentos
necesarios para garantizar que se permitan conexiones HTTP remotas
permanentemente.

Agregue las siguientes líneas para crear la tarea a fin de verificar el servicio web. Aplique
una sangría de cuatro espacios a la primera línea.
    - name: Connect to intranet web server
      ansible.builtin.uri:
        url: http://servera.lab.example.com
        return_content: true
        status_code: 200
• La primera línea aporta un nombre descriptivo para la tarea.
• La segunda línea tiene una sangría de seis espacios e invoca al módulo
ansible.builtin.uri.
• Las líneas restantes tienen una sangría de ocho espacios y envían los argumentos
necesarios para ejecutar una consulta de contenido web y verifican el código de estado
recibido.
• La palabra clave return_content garantiza que la respuesta del servidor se agregue a
los resultados de la tarea.
 8.
Verifique que el playbook /home/student/playbook-multi/intranet.yml final
refleje el siguiente contenido estructurado y, luego, guarde y cierre el archivo.
---
- name: Enable intranet services
  hosts: servera.lab.example.com
  become: true
  tasks:
    - name: Latest version of httpd and firewalld installed
      ansible.builtin.dnf:
        name:
          - httpd
          - firewalld
        state: latest
    - name: Test html page is installed
      ansible.builtin.copy:
        content: "Welcome to the example.com intranet!\n"
        dest: /var/www/html/index.html
    - name: Firewall enabled and running
      ansible.builtin.service:
        name: firewalld
        enabled: true
        state: started
    - name: Firewall permits access to httpd service
      ansible.posix.firewalld:
        service: http
        permanent: true
        state: enabled
        immediate: true
