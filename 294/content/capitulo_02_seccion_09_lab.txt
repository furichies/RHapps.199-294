Trabajo de laboratorio
Implementación de un playbook de
Ansible
Configurar y realizar tareas administrativas en hosts gestionados usando un playbook.
Resultados
• Usted debe ser capaz de construir y ejecutar un playbook de Ansible para instalar,
configurar y verificar el estado de los servicios web y de bases de datos en un host
gestionado.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start playbook-review
El directorio de trabajo /home/student/playbook-review se ha creado en la
máquina workstation para su proyecto de Ansible. El directorio ya se completó con un
archivo de configuración ansible.cfg y un archivo inventory. El host gestionado,
serverb.lab.example.com, ya está definido en este archivo de inventario.

Cambie al directorio /home/student/playbook-review y cree un nuevo playbook
denominado internet.yml. Agregue las entradas necesarias para iniciar un primer play
denominado Enable internet services y especifique su host gestionado previsto,
serverb.lab.example.com. Agregue la entrada necesaria para permitir el aumento de
privilegios y otra para iniciar una lista de tareas.

internet.yml para definir las tareas de configuración del firewall. Deben asegurarse de
que el servicio firewalld esté habilitado y en ejecución, y que se permita el acceso al

capítulo 2 |  Implementación de un playbook de Ansible
Resumen
• Un play es una lista ordenada de tareas que se ejecutan respecto de hosts seleccionados del
inventario.
• Un playbook es un archivo de texto que contiene una lista de uno o más plays para ejecutar en
orden.
• Los playbooks de Ansible se escriben en formato YAML.
• Los plays de Ansible son idempotentes, lo que significa que evitan realizar cambios si detectan
que el estado actual coincide con el estado final deseado.
• Los archivos YAML están estructurados mediante la sangría de espacio para representar la
jerarquía de datos.
• Las tareas se implementan mediante el código estandarizado incluido como módulos Ansible.
• Los módulos de Ansible se empaquetan en Ansible Content Collections, que son un formato
de distribución para el contenido de Ansible que puede incluir playbooks, roles, módulos y
complementos (plug-ins).
• El comando ansible-navigator doc puede enumerar módulos en sus entornos de
ejecución de automatización y brindar documentación y fragmentos de códigos a modo de
ejemplo de cómo usarlos en playbooks.
• El comando ansible-navigator run se usa para ejecutar playbooks y validar la sintaxis del
playbook.
