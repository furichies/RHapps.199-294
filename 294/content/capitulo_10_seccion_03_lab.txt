Creación de playbooks
Cree tres playbooks. El primer playbook, dev_deploy.yml, instala e inicia el servidor
web. El segundo playbook, get_web_content.yml, garantiza que el servidor web esté
ofreciendo contenido. El tercer playbook, site.yml, ejecuta los otros dos playbooks.
Resultados
• Crear y ejecutar playbooks para realizar tareas en hosts gestionados.
• Usar plantillas, variables y manejadores Jinja2 en playbooks.

El playbook completo incluye el siguiente contenido:
---
- name: Install and configure web servers
  hosts: webservers
  become: true
  tasks:
    - name: Install httpd package
      ansible.builtin.dnf:
        name: httpd
        state: present
    - name: Start httpd service
      ansible.builtin.service:
        name: httpd
        state: started
        enabled: true
    - name: Deploy configuration template
      ansible.builtin.template:
        src: templates/vhost.conf.j2
        dest: /etc/httpd/conf.d/vhost.conf
        owner: root
        group: root
        mode: '0644'
      notify: Restart httpd
    - name: Copy index.html
      ansible.builtin.copy:
        src: files/
        dest: "/var/www/vhosts/{{ ansible_facts['hostname'] }}/"
        owner: root
        group: root
        mode: '0644'
    - name: Ensure web server port is open
      ansible.posix.firewalld:
        state: enabled
        permanent: true
        immediate: true
        service: http
  handlers:
    - name: Restart httpd
      ansible.builtin.service:
        name: httpd
        state: restarted

Trabajo de laboratorio
Administración de hosts de Linux y uso
de roles del sistema
En esta revisión, en hosts gestionados que ejecutan Red Hat Enterprise Linux, escribe
playbooks que usan dos roles del sistema para configurar un nuevo almacenamiento con un
volumen lógico y configurar interfaces de red y usa módulos para configurar un trabajo Cron
y un usuario con privilegios Sudo.
Resultados
• Usar el rol redhat.rhel_system_roles.storage para crear, formatear y montar de
manera persistente un volumen LVM en un host gestionado.
• Crear un usuario con acceso sudo.
• Configurar los ajustes de red en los hosts gestionados y recopilar datos de Ansible
relacionados con la red.
• Programar un trabajo Cron.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start review-cr3
Especificaciones
• Use el directorio del proyecto /home/student/review-cr3 para realizar esta actividad.
• Instale la Ansible Content Collection redhat.rhel_system_roles en el subdirectorio
collections de su directorio de proyecto .
• Escriba un playbook denominado storage.yml que use el rol del sistema
redhat.rhel_system_roles.storage para configurar volúmenes lógicos para los hosts
gestionados en el grupo webservers especificado por el archivo de inventario en el directorio
de su proyecto. El playbook debe configurar los volúmenes lógicos de la siguiente manera:
– Cree un grupo de volúmenes denominado vg_web en el dispositivo de almacenamiento /
dev/vdb.
– Cree un volumen lógico denominado lv_content, de 128 MB, del grupo de volúmenes
vg_web, formatéelo con un sistema de archivos XFS y móntelo en el directorio /var/www/
html/content.
