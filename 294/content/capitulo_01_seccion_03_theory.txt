Ansible y Red Hat Ansible Automation Platform
Puede obtener el software Ansible de diferentes formas, cada una con su propio nivel de soporte.
• De la comunidad upstream
• Como parte de Red Hat Enterprise Linux, con soporte limitado
• Con el producto Red Hat Ansible Automation Platform con soporte completo
Este curso se centra en el último de estos tres y usa las herramientas proporcionadas con Red Hat
Ansible Automation Platform. Sin embargo, el lenguaje de Ansible y los conceptos básicos son los
mismos sin importar cómo obtenga el software.
Ansible comunitario
La comunidad upstream de Ansible desarrolla Ansible y distribuye versiones de este de dos
maneras.
El primero de ellos es Ansible Core. Este es un componente minimalista que consta del tiempo de
ejecución central (core) que puede interpretar el contenido de Ansible y un conjunto de módulos
de Ansible de uso común (incluidos como Ansible Content Collections ansible.builtin). Este
tiempo de ejecución está estructurado para que el nodo de control actúe como el entorno de
ejecución para el código Ansible.
El segundo es el Ansible comunitario. Esta es una distribución de Ansible Core más una selección
de Ansible Content Collections seleccionadas por la comunidad de código abierto, agregando
módulos y roles adicionales de Ansible.
Ambos son proporcionados por los desarrolladores upstream como paquetes pip de Python;
Red Hat no admite ninguna versión de la comunidad.
Ansible Core en Red Hat Enterprise Linux
Red Hat proporciona Ansible Core como un paquete RPM, ansible-core, incluido con Red Hat
Enterprise Linux 9 en el repositorio de AppStream. Su objetivo es permitir el soporte para el
código de automatización proporcionado o generado por Red Hat. Cuenta con soporte, pero el
alcance de este se limita a cualquier playbook, rol o módulo de Ansible que se incluya o se genere
con un producto de Red Hat, como los roles del sistema incluidos en el paquete rhel-system-
roles, los playbooks de corrección de Red Hat Insights y los playbooks de Ansible que cumplen
con OpenSCAP. Otros casos de uso, incluido el uso de otros módulos y complementos de Ansible
incluidos con Ansible Core 2.13, están fuera del alcance del soporte.
Para obtener más información, consulte el artículo de la base de conocimiento "Uso de Ansible en
RHEL 9" [https://access.redhat.com/articles/6393321].

Red Hat Ansible Automation Platform
Red Hat proporciona una versión totalmente compatible de Ansible a través de Red Hat Ansible
Automation Platform. Ansible Automation Platform proporciona una versión soportada del
conjunto de herramientas de Ansible Core, además de contenido, herramientas, componentes y
servicios en la nube adicionales, certificados y soportados. Los clientes con una suscripción válida
pueden usar su repositorio de RPM, instalar las herramientas adicionales y consumir contenido
certificado de los servicios en la nube.
Importante
Este curso usa Red Hat Ansible Automation Platform 2.2, que incluye Ansible
Core 2.13. Esta versión de Ansible Automation Platform es más o menos similar a la
distribución comunitaria de Ansible 6, aunque Ansible Automation Platform incluye
Ansible Content Collections diferentes y herramientas y componentes adicionales.
El curso le enseña cómo escribir y ejecutar el código de automatización de Ansible,
y las habilidades que aprenda aquí también lo ayudarán con el Ansible comunitario.
La instalación de los componentes del servidor de Ansible Automation Platform,
como el controlador de automatización y el centro de automatización, está fuera del
alcance de este curso.
Descripción general de Red Hat Ansible Automation
Platform 2
Red Hat Ansible Automation Platform 2 incluye una serie de componentes distintos que, en
conjunto, proporcionan un conjunto completo e integrado de herramientas y recursos de
automatización.
Ansible Core
Ansible Core proporciona la funcionalidad fundamental que se usa para ejecutar los playbooks
de Ansible. Define el lenguaje de automatización que se usa para escribir playbooks de Ansible
en archivos de texto YAML. Proporciona las funciones clave, como bucles, condicionales y otros
imperativos de Ansible necesarios para el código de automatización. También proporciona
el marco (framework) y las herramientas básicas de la línea de comandos para impulsar la
automatización.
Red Hat Ansible Automation Platform 2.2 proporciona Ansible Core 2.13 en el paquete RPM
ansible-core y en sus entornos de ejecución de automatización ee-minimal-rhel8 y ee-
supported-rhel8.
Ansible Content Collections
Históricamente, Ansible proporcionaba una gran cantidad de módulos como parte del paquete
central (core); un enfoque conocido en la comunidad de Ansible como "baterías incluidas". Sin
embargo, con el éxito y el rápido crecimiento de Ansible, la cantidad de módulos incluidos con
Ansible creció exponencialmente. Esto generó ciertos desafíos con el soporte, especialmente
porque los usuarios a veces querían usar versiones anteriores o posteriores de los módulos que
estaban empaquetados con una versión particular de Ansible.
Los desarrolladores upstream decidieron reorganizar la mayoría de los módulos en Ansible
Content Collections independientes compuestas por módulos, roles y complementos (plug-ins)
relacionados que son soportados por el mismo grupo de desarrolladores. Ansible Core en sí está

Navegador de contenido de automatización
Red Hat Ansible Automation Platform 2 proporciona una nueva herramienta de alto nivel para
desarrollar y probar los playbooks de Ansible, el navegador de contenido de automatización
(ansible-navigator). Esta herramienta reemplaza y amplía la funcionalidad de varias
utilidades de Ansible de la línea de comandos, incluidas ansible-playbook, ansible-
inventory, ansible-config, etc.
Además, separa el nodo de control en el que ejecuta Ansible del entorno de ejecución de
automatización que lo ejecuta, ejecutando sus playbooks en un contenedor. Esto hace que sea
más sencillo proporcionar un entorno de trabajo completo para su código de automatización para
la implementación en producción.
Entornos de ejecución de automatización
Un entorno de ejecución de automatización es una imagen de contenedor que contiene Ansible
Core, Ansible Content Collections y cualquier librería de Python, ejecutable u otras dependencias
necesarias para ejecutar su playbook.
Cuando ejecuta un playbook con ansible-navigator, puede seleccionar un entorno de
ejecución de automatización para que lo use para ejecutar ese playbook. Cuando su código está
funcionando, puede proporcionar el playbook y el entorno de ejecución de la automatización al
controlador de automatización y saber que tiene todo lo necesario para ejecutar correctamente su
playbook.

Controlador de automatización
El controlador de automatización, anteriormente denominado Red Hat Ansible Tower, es el
componente de Red Hat Ansible Automation Platform que proporciona un punto central de
control para ejecutar el código de automatización de su empresa. Proporciona una interfaz de
usuario web y una API REST que se pueden usar para configurar, ejecutar y evaluar sus trabajos de
automatización.

Automation Hub
Un servicio público en console.redhat.com brinda acceso a Ansible Content Collections
certificadas por Red Hat que puede descargar y usar con ansible-galaxy (para ansible-
navigator) y con el controlador de automatización.
Preparación de un nodo de control
Para ejecutar los playbooks de Ansible, instale el navegador de contenido de automatización
(ansible-navigator) en su nodo de control y descargue un entorno de ejecución. Los hosts
gestionados por Ansible no necesitan tener instalado ansible-navigator; solo necesita
instalar esa herramienta en el nodo de control desde el cual ejecuta los playbooks de Ansible.
Es necesario instalar Python 3.8 o posterior en el nodo de control antes de instalar el paquete
ansible-core.
Necesita una suscripción válida a Red Hat Ansible Automation Platform para instalar el navegador
de contenido de automatización en su nodo de control.
Si ha activado el acceso a contenido simple para su organización en el Portal de clientes de
Red Hat, no es necesario que adjunte la suscripción a su sistema.

Preparación de hosts gestionados
Uno de los beneficios de Ansible es que los hosts gestionados no necesitan tener un agente
especial instalado. El nodo de control de Ansible se conecta con los hosts gestionados mediante
un protocolo de red estándar para garantizar que los sistemas tengan el estado especificado.
Los hosts gestionados pueden tener algunos requisitos según el modo en que el nodo de control
se conecte con ellos y los módulos que se ejecuten en ellos.
• Los hosts gestionados Linux y UNIX deben tener instalado Python para que funcione la mayoría
de los módulos. La versión de Python que se debe usar depende de la versión del paquete
ansible-core. Consulte Support Matrix [https://docs.ansible.com/ansible/
latest/reference_appendices/release_and_maintenance.html#ansible-core-
support-matrix] para obtener información sobre los requisitos de la versión de Python para
los nodos de control y los hosts gestionados.
• Si SELinux está habilitado en los hosts gestionados, asegúrese de que el paquete python3-
libselinux esté instalado antes de usar módulos que se relacionen con las funciones de
copia, archivo o plantilla. Si se instalan otros componentes de Python, puede usar módulos de
Ansible, como ansible.builtin.dnf o ansible.builtin.package, para garantizar que
este paquete también esté instalado.
• Ansible debe poder conectarse a la máquina mediante SSH, y si se conecta como un usuario
regular, debe poder usar un mecanismo como sudo para obtener acceso de superusuario.
nota
Algunos módulos pueden tener sus propios requisitos adicionales. Por ejemplo,
el módulo ansible.builtin.dnf, que puede usarse para instalar paquetes en
sistemas Fedora actuales, requiere el paquete python3-dnf.

Hosts administrados de Microsoft Windows
Ansible Content Collection ansible.windows, que forma parte del entorno de ejecución de
automatización predeterminado, incluye varios módulos que están diseñados específicamente
para hosts gestionados de Microsoft Windows.
La mayoría de los módulos específicamente diseñados para hosts gestionados de Microsoft
Windows requiere PowerShell 3.0 o posterior en el host gestionado en lugar de Python. Además,
los hosts gestionados deben tener configurada la conexión remota de Windows PowerShell.
Ansible también requiere que .NET Framework 4.0 o posterior esté instalado en hosts gestionados
de Microsoft Windows.
Este curso usa hosts gestionados basados en Linux en sus ejemplos y no profundiza sobre las
diferencias y los ajustes específicos necesarios cuando se gestionan hosts gestionados de
Microsoft Windows.
Puede encontrar más información sobre la administración de hosts gestionados de Microsoft
Windows está disponible en el sitio web de Ansible en https://docs.ansible.com/ansible/latest/
user_guide/windows.html o en el curso de capacitación de Red Hat Microsoft Windows Automation
with Red Hat Ansible Automation Platform (DO417).
Dispositivos de red administrados
También puede usar la automatización de Ansible para configurar dispositivos de red
administrados, como enrutadores y switches. Ansible incluye muchos módulos diseñados
específicamente para este propósito. Esto incluye soporte para Cisco IOS, IOS XR y NX-OS;
Juniper Junos; Arista EOS; y dispositivos de red basados en VyOS, entre otros.
Puede escribir playbooks de Ansible para dispositivos de red usando las mismas técnicas básicas
que usa al escribir playbooks para servidores. Como la mayoría de los dispositivos de red no
pueden ejecutar Python, Ansible ejecuta módulos de red en el nodo de control, no en los hosts
gestionados. Los métodos de conexión especiales también se usan para comunicarse con
dispositivos de red, generalmente usando CLI sobre SSH, XML sobre SSH o API sobre HTTP(S).
Este curso no profundiza sobre la automatización de la administración de dispositivos de red. Para
obtener más información sobre este tema, consulte  Ansible for Network Automation  [https://
docs.ansible.com/ansible/latest/network/index.html] en el sitio web de la comunidad de Ansible
o el curso de capacitación de Red Hat Network Automation with Red Hat Ansible Automation
Platform (DO457).
