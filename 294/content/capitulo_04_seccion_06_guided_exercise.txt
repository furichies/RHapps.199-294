Ejercicio Guiado
Manejo de fallas de tareas
Explorar diferentes formas de manejar la falla de una tarea en un playbook de Ansible.
Resultados
• Ignorar los comandos fallidos durante la ejecución de playbooks.
• Forzar la ejecución de los manejadores.
• Reemplazar lo que constituye una falla en las tareas.
• Reemplazar el estado changed para las tareas.
• Implementar block, rescue y always en playbooks.

7.2.
Anide la tarea que instala el paquete mariadb-server en una cláusula rescue. Si
la tarea enumerada en la cláusula block falla, esta tarea se ejecuta. La cláusula del
bloque debe incluir el siguiente contenido:
      rescue:
        - name: Install {{ db_package }} package
          ansible.builtin.dnf:
            name: "{{ db_package }}"
            state: present
7.3.
Por último, agregue una cláusula always que iniciará el servidor de base de datos
una vez realizada la instalación usando el módulo ansible.builtin.service. La
cláusula always debe incluir el siguiente contenido:
      always:
        - name: Start {{ db_service }} service
          ansible.builtin.service:
            name: "{{ db_service }}"
            state: started
7.4.
La tarea completa debe contar con el siguiente contenido:
  tasks:
    - name: Attempt to set up a webserver
      block:
        - name: Install {{ web_package }} package
          ansible.builtin.dnf:
            name: "{{ web_package }}"
            state: present
      rescue:
        - name: Install {{ db_package }} package
          ansible.builtin.dnf:
            name: "{{ db_package }}"
            state: present
      always:
        - name: Start {{ db_service }} service
          ansible.builtin.service:
            name: "{{ db_service }}"
            state: started

9.3.
Esa tarea ansible.builtin.command no debería informar changed cada vez que
se ejecuta, ya que no modifica el host gestionado. Dado que sabe que la tarea nunca
modifica un host gestionado, agregue la línea changed_when: false a la tarea
para eliminar la modificación.
  tasks:
    - name: Check local time
      ansible.builtin.command: date
      register: command_result
      changed_when: false

 10. Como ejercicio final, edite el playbook para explorar el modo en que la palabra clave
failed_when interactúa con las tareas.
10.1.
Edite la tarea Install {{ web_package }} package de modo que informe que
falló cuando web_package tenga el valor httpd. Dado que este es el caso, la tarea
informará una falla cuando ejecute el play.
Preste atención a su sangría para asegurarse de que la palabra clave se establezca
correctamente en la tarea.
      block:
        - name: Install {{ web_package }} package
          ansible.builtin.dnf:
            name: "{{ web_package }}"
            state: present
          failed_when: web_package == "httpd"
10.2. Ejecute el playbook.

Observe la salida con atención. La palabra clave failed_when modifica el estado
que informa la tarea después de su ejecución; no modifica el comportamiento de la
tarea en sí.
Sin embargo, la falla informada puede modificar el comportamiento del resto del play.
Dado que esta tarea se encontraba en un bloque e informó una falla, se ejecutó la
tarea Install mariadb-server package en la sección rescue del bloque.
