Ejercicio Guiado
Administración de la configuración de red
Ajustar la configuración de red de un host gestionado y recopilar información sobre él en un
archivo creado por una plantilla.
Resultados
• Deberá ser capaz de configurar los ajustes de red y en los hosts gestionados y recopilar
datos de Ansible relacionados con la red.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start system-network
Instrucciones
 1.
Revise el archivo de inventario del directorio del proyecto /home/student/system-
network.
1.1.
Cambie al directorio /home/student/system-network.
[student@workstation ~]$ cd ~/system-network
[student@workstation system-network]$
1.2.
En el archivo inventory, verifique que servera.lab.example.com sea parte del
grupo de hosts webservers. Este servidor tiene una interfaz de red de repuesto.
[student@workstation system-network]$ cat inventory
[webservers]
servera.lab.example.com
 2.
Instale la Ansible Content Collection redhat.rhel_system_roles desde el archivo
redhat-rhel_system_roles-1.19.3.tar.gz en el directorio collections del
directorio del proyecto.
2.1.
Use el comando ansible-galaxy para instalar la Ansible Content
Collection rhel_system_roles desde el archivo redhat-
rhel_system_roles-1.19.3.tar.gz en el directorio collections del
proyecto.

 3.
Cree un playbook que use el rol redhat.rhel_system_roles.network para
configurar la interfaz de red eth1 en servera.lab.example.com con la dirección IP
172.25.250.30/24 y el prefijo de red.
3.1.
Cree un playbook denominado playbook.yml y agregue un play orientado al grupo
de hosts webservers. Incluya el rol rhel_system_roles.network en la sección
roles del play.
---
- name: NIC Configuration
  hosts: webservers
  roles:
    - redhat.rhel_system_roles.network
3.2.
La documentación para el rol del sistema redhat.rhel_system_roles.network
enumera las variables y opciones que están disponibles para configurar su
funcionamiento.
Ejecute ansible-navigator collections, seleccione la colección
redhat.rhel_system_roles y, luego, seleccione el rol network para ver su
documentación.
Revise la sección Setting the IP configuration: (cerca de la línea 1219 de la
documentación) y determine qué variable se requiere para configurar la interfaz de
red eth1 con una dirección IP estática y un prefijo de red.

3.4.
Cree un nuevo archivo de variable denominado network.yml en el directorio
group_vars/webservers para definir la variable de rol network_connections
para el grupo webservers.
El valor de esa variable debe configurar una conexión de red para la interfaz de red
eth1 que le asigna la dirección IP estática y el prefijo de red 172.25.250.30/24.
Al completarse, el archivo incluye el siguiente contenido:
[student@workstation system-network]$ cat group_vars/webservers/network.yml
---
network_connections:
  - name: eth1
    type: ethernet
    ip:
      address:
        - 172.25.250.30/24

Trabajo de laboratorio
Automatización de tareas de
administración de Linux
Realizar tareas administrativas comunes de Linux en sus hosts gestionados mediante
técnicas que se trataron en este capítulo.
Resultados
• Cree playbooks para configurar un repositorio de software, usuarios y grupos, volúmenes
lógicos, trabajos de cron e interfaces de red adicionales en un host gestionado.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start system-review
Instrucciones
1.
Cree un playbook denominado repo_playbook.yml para que se ejecute en el grupo de
hosts webservers que configure esos hosts gestionados para usar el repositorio interno de
Yum ubicado en http://materials.example.com/yum/repository y luego instale el
paquete rhelver disponible desde ese repositorio en esos hosts gestionados.
La configuración del repositorio debe cumplir con los siguientes requisitos:
• La configuración se encuentra en el archivo /etc/yum.repos.d/example.repo.
• El ID del repositorio es example-internal.
• La URL base es http://materials.example.com/yum/repository.
• El repositorio está configurado para verificar las firmas RPM GPG.
• La descripción del repositorio es Example Inc. Internal YUM repo.
Los paquetes RPM están firmados con un par de claves GPG organizativas. Esa clave pública
de GPG está disponible en http://materials.example.com/yum/repository/RPM-
GPG-KEY-example. Debe asegurarse de que la clave esté configurada en todos los hosts
gestionados en el grupo de hosts webservers.
Ejecute el playbook. Debe confirmar que el playbook instaló el paquete en sus hosts
gestionados después de su ejecución.
2.
Cree un playbook denominado users.yml para ejecutar en el grupo de hosts webservers
que crea el grupo de usuarios webadmin, agrega los usuarios ops1 y ops2 y garantiza que
ambos usuarios tengan webadmin como grupo complementario en esos hosts gestionados.
Ejecute el playbook. Debe confirmar que los usuarios existen en los hosts gestionados y que
tienen webadmin como grupo complementario después de que se ejecute el playbook.
