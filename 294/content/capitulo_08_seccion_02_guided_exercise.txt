Ejercicio Guiado
Solución de problemas de playbooks
Solucionar los problemas de un playbook que le fue dado y que no funciona correctamente.
Resultados
• Debe ser capaz de solucionar problemas y resolver problemas en los playbooks.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start troubleshoot-playbook
Instrucciones
 1.
Cambie al directorio /home/student/troubleshoot-playbook/.
[student@workstation ~]$ cd ~/troubleshoot-playbook/
[student@workstation troubleshoot-playbook]$
 2.
Cree un archivo denominado ansible.cfg en el directorio actual. Configure el parámetro
log_path para escribir registros Ansible en el archivo /home/student/troubleshoot-
playbook/ansible.log. Configure el parámetro inventory para usar el archivo /
home/student/troubleshoot-playbook/inventory implementado por el script de
laboratorio.
El archivo ansible.cfg completo debe incluir el siguiente contenido:
[defaults]
log_path = /home/student/troubleshoot-playbook/ansible.log
inventory = /home/student/troubleshoot-playbook/inventory
 3.
Ejecute el playbook samba.yml. Fallará con un error.
Este playbook configuraría un servidor Samba si todo estuviera correcto. Sin embargo,
la ejecución falla porque la definición de la variable random_var no está entre comillas
dobles. (Si los dos puntos forman parte de un valor, el valor debe estar protegido por
comillas simples o dobles). Lea el mensaje de error para ver cómo ansible-navigator
run informa del problema. Observe que a la variable random_var se le asigna un valor que
contiene dos puntos y no está protegida por comillas dobles.

capítulo 8 |  Solución de problemas de Ansible
Solución de problemas en hosts
gestionados de Ansible
Objetivos
• Solucionar fallas en hosts gestionados cuando se ejecuta un playbook.
Solución de problemas de conexiones
Muchos problemas comunes al usar Ansible para administrar hosts están asociados con
conexiones al host y con problemas de configuración relacionados con el usuario remoto y el
aumento de privilegios.
Problemas de autenticación en hosts gestionados
Si tiene problemas para autenticarse en un host gestionado, asegúrese de tener remote_user
correctamente configurado en el archivo de configuración o en el play.
Por ejemplo, es posible que vea la siguiente salida al ejecutar un playbook diseñado para
conectarse a la cuenta de usuario remota root:
[student@controlnode ~]$ ansible-navigator run \
> -m stdout playbook.yml
PLAY [Install a samba server] **************************************************
TASK [Gathering Facts] *********************************************************
fatal: [host.lab.example.com]: UNREACHABLE! => {"changed": false, "msg":
 "Failed to connect to the host via ssh: developer@host: Permission denied
 (publickey,gssapi-keyex,gssapi-with-mic,password).", "unreachable": true}
PLAY RECAP *********************************************************************
host.lab.example.com    : ok=0    changed=0    unreachable=1    failed=0   
 skipped=0    rescued=0    ignored=0
Please review the log for errors.
En este caso, ansible-navigator está intentando conectarse como la cuenta de usuario
developer, de acuerdo con la salida anterior. Una razón por la que esto puede suceder es si
se ha configurado ansible.cfg en el proyecto para establecer el remote_user en el usuario
developer en lugar del usuario root.
Otra razón por la que puede ver un error de "permiso denegado" como este es si no tiene
configuradas las claves SSH correctas o no proporcionó la contraseña correcta para ese usuario.
[root@controlnode ~]# ansible-navigator run \
> -m stdout playbook.yml
TASK [Gathering Facts] *********************************************************
fatal: [host.lab.example.com]: UNREACHABLE! => {"changed": false, "msg": "Failed
 to connect to the host via ssh: root@host: Permission denied (publickey,gssapi-
keyex,gssapi-with-mic).", "unreachable": true}
