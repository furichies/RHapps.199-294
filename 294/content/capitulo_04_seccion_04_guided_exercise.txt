Ejercicio Guiado
Implementación de manejadores
Implementar manejadores en playbooks.
Resultados
• Debe ser capaz de definir manejadores en playbooks y notificarlos para aplicar cambios de
configuración.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start control-handlers
Instrucciones
 1.
En la máquina workstation, abra un nuevo terminal y cambie al directorio /home/
student/control-handlers.
[student@workstation ~]$ cd ~/control-handlers
[student@workstation control-handlers]$

Edite el archivo del playbook configure_webapp.yml. Este playbook instala y configura
un servidor de aplicaciones web. Cuando cambia la configuración del servidor de
aplicaciones web, el playbook desencadena un reinicio del servicio correspondiente.

packages especifica el nombre de los paquetes que se instalarán para los
servicios de la aplicación web.
web_service especifica el nombre del servicio del servidor web.
app_service especifica el nombre del servicio del servidor de aplicaciones.
firewall_service especifica el nombre del servicio de firewall.
firewall_service_rules especifica una lista de servicios para permitir a
través del firewall.
web_config_src especifica la ubicación del archivo de configuración del
servidor web para instalar.
web_config_dst especifica la ubicación del archivo de configuración del
servidor web instalado en los hosts gestionados.
app_config_src especifica la ubicación del archivo de configuración del
servidor de aplicaciones para instalar.
web_config_dst especifica la ubicación del archivo de configuración del
servidor de aplicaciones instalado en los hosts gestionados.
2.2.
En el archivo configure_webapp.yml, defina una tarea que usa el módulo
ansible.builtin.dnf para instalar los paquetes de base de datos requeridos,
según lo define la variable packages.
La tarea debe decir lo siguiente:
  tasks:
    - name: "{{ packages }} packages are installed"
      ansible.builtin.dnf:
        name: "{{ packages }}"
        state: present
2.3.
Agregue una tarea para iniciar y habilitar los servicios requeridos. Use un bucle para
realizar la acción para los tres servicios definidos:
    - name: Make sure services are running
      ansible.builtin.service:
        name: "{{ item }}"
        state: started
        enabled: true
      loop:
        - "{{ web_service }}"
        - "{{ app_service }}"
        - "{{ firewall_service }}"

Manejo de fallas de tareas
Objetivos
• Controlar lo que sucede cuando falla una tarea y qué condiciones hacen que falle una tarea.
Gestión de errores de tareas en plays
Ansible evalúa los códigos de retorno de cada tarea para determinar si una tarea se realizó
satisfactoriamente o con errores. Generalmente, cuando una tarea falla, Ansible omite
inmediatamente todas las tareas posteriores.
No obstante, algunas veces puede desear continuar la ejecución del play, aunque una tarea falle.
Por ejemplo, puede esperar que una tarea específica falle y tal vez desee recuperarla ejecutando
otra tarea de forma condicional. Pueden usarse varias características de Ansible para gestionar los
errores de tareas.
Fallas de tareas ignoradas
De forma predeterminada, si una tarea falla, se cancela el play. Sin embargo, el comportamiento
puede anularse si se ignoran las tareas fallidas. Puede usar la palabra clave ignore_errors en
una tarea para lograr esto.
En el siguiente fragmento, se muestra cómo usar ignore_errors en una tarea para continuar la
ejecución de un playbook en el host, aun si la tarea falla. Por ejemplo, si el paquete notapkg no
existe, el módulo ansible.builtin.dnf falla, pero si se tiene ignore_errors establecido
como true, la ejecución continuará.
- name: Latest version of notapkg is installed
  ansible.builtin.dnf:
    name: notapkg
    state: latest
  ignore_errors: true
Forzado de la ejecución de manejadores después de la falla de
una tarea
En general, cuando falla una tarea y se cancela el play en ese host, no se ejecutan los manejadores
informados por las tareas anteriores en el play. Si establece la palabra clave force_handlers:
true en el play, se llama a los manejadores notificados incluso si se canceló el play porque falló
una tarea posterior.
Importante
Si ha establecido ignore_errors: true en una tarea o para el play de la tarea,
si esa tarea falla, se ignora la falla. En ese caso, el play continúa ejecutándose y los
manejadores aún se ejecutan, incluso si ha establecido force_handlers: false,
a menos que algún otro error haga que el play falle.
