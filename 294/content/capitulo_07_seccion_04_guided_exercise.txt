Ejercicio Guiado
Creación de roles
Crear un rol de Ansible que usa variables, archivos, plantillas, tareas y manejadores para
implementar un servicio de red.
Resultados
• Crear un rol que use variables y parámetros.
El rol myvhost instala y configura el servicio Apache en un host. Se provee una plantilla
llamada vhost.conf.j2 para generar /etc/httpd/conf.d/vhost.conf.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start role-create
Instrucciones
 1.
Cambie al directorio /home/student/role-create.
[student@workstation ~]$ cd ~/role-create
[student@workstation role-create]$
 2.
Cree la estructura de directorio para un rol denominado myvhost. El rol incluye archivos,
plantillas, tareas y manejadores corregidos. Los directorios defaults, vars y tests no se
usan en este rol, por lo que puede eliminarlos.
[student@workstation role-create]$ mkdir -v roles; cd roles
mkdir: created directory 'roles'
[student@workstation roles]$ ansible-galaxy role init myvhost

 3.
Edite el archivo main.yml en el subdirectorio tasks del rol. El rol debe ejecutar las
siguientes tareas:
• Instale el paquete httpd.
• Habilite e inicie el servicio httpd.
• Instale el archivo de configuración del servidor web, con una plantilla proporcionada por
el rol.
3.1.
Edite el archivo roles/myvhost/tasks/main.yml. Incluya el código para usar el
módulo ansible.builtin.dnf a fin de instalar el paquete httpd. Asegúrese de
que el archivo contenga el siguiente contenido:
---
# tasks file for myvhost
- name: Ensure httpd is installed
  ansible.builtin.dnf:
    name: httpd
    state: latest
3.2.
Agregue un código al archivo roles/myvhost/tasks/main.yml para usar el
módulo ansible.builtin.service para iniciar y habilitar el servicio httpd.
- name: Ensure httpd is started and enabled
  ansible.builtin.service:
    name: httpd
    state: started
    enabled: true
3.3.
Agregue otra estrofa para usar el módulo ansible.builtin.template para crear
/etc/httpd/conf.d/vhost.conf en el host gestionado. El módulo invoca un
manejador para reiniciar el daemon httpd cuando se actualiza este archivo.
- name: vhost file is installed
  ansible.builtin.template:
    src: vhost.conf.j2
    dest: /etc/httpd/conf.d/vhost.conf
    owner: root
    group: root
    mode: 0644
  notify:
    - restart httpd
3.4.
Guarde sus cambios y salga del archivo roles/myvhost/tasks/main.yml.

 5.
El archivo vhost.conf.j2 es una plantilla que se usa para configurar el servidor web
Apache mediante el uso de variables:
# {{ ansible_managed }}
<VirtualHost *:80>
    ServerAdmin webmaster@{{ ansible_fqdn }}
    ServerName {{ ansible_fqdn }}
    ErrorLog logs/{{ ansible_hostname }}-error.log
    CustomLog logs/{{ ansible_hostname }}-common.log common
    DocumentRoot /var/www/vhosts/{{ ansible_hostname }}/
    <Directory /var/www/vhosts/{{ ansible_hostname }}/>
    Options +Indexes +FollowSymlinks +Includes
    Order allow,deny
    Allow from all
    </Directory>
</VirtualHost>
Mueva la plantilla vhost.conf.j2 del directorio del proyecto al subdirectorio templates
del rol.

Implementación de roles desde fuentes
externas de contenido
Objetivos
• Seleccionar y recuperar roles de fuentes externas, como repositorios de Git o Ansible Galaxy, y
usarlos en sus playbooks.
Fuentes de contenido externo
Si está usando roles en sus playbooks de Ansible, debe obtener esos roles de alguna fuente
administrada centralmente. Esta práctica garantiza que todos sus proyectos tengan la versión
actual del rol y que cada proyecto pueda beneficiarse de las correcciones de errores descubiertas
por otros proyectos con los que comparten el rol.
Por ejemplo, si el rol es contenido privado creado y coordinado por su organización, podría
almacenarse en un repositorio de Git administrado por su organización. Alternativamente, podría
distribuirse como un archivo de almacenamiento tar desde un sitio web o por otros medios.
Además, la comunidad de código abierto mantiene algunos roles a través del sitio web de Ansible
Galaxy. Red Hat no son revisa ni respalda oficialmente estos roles, pero pueden contener código
que su organización considere útil.
Importante
Es cada vez más común que los roles se empaqueten como Ansible Content
Collections y que sus autores los ofrezcan a través de distintos métodos:
• En Ansible Content Collections certificadas por Red Hat desde el centro de
automatización alojado de Red Hat en https://console.redhat.com o a
través de un centro de automatización privado
• Como contenido privado empaquetado desde un centro de automatización
privado
• Por la comunidad de Ansible Galaxy en https://galaxy.ansible.com
Esta sección solo cubre cómo obtener roles que no están empaquetados en Ansible
Content Collections.
Lo ideal sería poder descargar la última versión del rol en el directorio roles de su proyecto de
forma sencilla, siempre que sea necesario.
Presentación de Ansible Galaxy
Una librería pública de contenido de Ansible programada por una variedad de administradores y
usuarios de Ansible se encuentra disponible en Ansible Galaxy [https://galaxy.ansible.com]. Esta
librería contiene miles de roles de Ansible y cuenta con una base de datos de búsqueda que lo
ayuda a identificar roles que podrían ayudarlos a realizar una tarea administrativa.
El comando ansible-galaxy que usa para descargar y gestionar roles de Ansible Galaxy
también se puede usar para descargar y gestionar roles de sus propios repositorios de Git.
