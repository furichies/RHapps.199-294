Ejercicio Guiado
Escritura y ejecución de playbooks
Escribir y ejecutar un playbook de Ansible.
Resultados
• Usted deberá ser capaz de escribir un playbook con una sintaxis YAML básica y una
estructura de playbook de Ansible, y ejecutarlo correctamente con el comando ansible-
navigator run.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start playbook-basic
Instrucciones
El directorio del proyecto Ansible /home/student/playbook-basic se ha creado en la
máquina workstation para este ejercicio. Este directorio ya tiene un archivo de configuración
ansible.cfg. También tiene un archivo de inventario denominado inventory que
define un grupo web, que incluye los hosts gestionados serverc.lab.example.com y
serverd.lab.example.com como miembros.
En este ejercicio, crea un playbook denominado site.yml en el directorio del proyecto. Este
playbook contiene un play, que se destina a miembros del grupo de hosts web. El playbook usa
tareas para garantizar que se cumplan las siguientes condiciones en los hosts gestionados:
• El paquete httpd está presente, con el módulo ansible.builtin.dnf.
• El archivo files/index.html local se copia en /var/www/html/index.html en cada host
gestionado, con el módulo ansible.builtin.copy.
• El servicio httpd se inicia y se habilita con el módulo ansible.builtin.service.
Puede usar el comando ansible-navigator doc para poder entender las palabras clave
necesarias para cada uno de los módulos.
Después de que se escriba el playbook, valide su sintaxis y, luego, use el comando ansible-
navigator run para ejecutar el playbook a fin de implementar la configuración.

Implementación de varios plays
Objetivos
• Escribir un playbook que use múltiples plays con aumento de privilegios por play y aprovechar
eficazmente el navegador de contenido de automatización para encontrar nuevos módulos en
Ansible Content Collections disponibles a fin de implementar tareas para un play.
Escritura de varios plays
Un playbook es un archivo YAML que contiene una lista de uno o más plays. Recuerde que un solo
play es una lista ordenada de tareas para ejecutar respecto de hosts seleccionados del inventario.
Por lo tanto, si un playbook contiene varios plays, cada play podría aplicar sus tareas a un conjunto
de hosts diferente.
Esto puede ser muy útil cuando se organiza una implementación compleja que puede involucrar
diferentes tareas en diferentes hosts. Puede escribir un playbook que ejecute un play respecto de
un conjunto de hosts y que, cuando este finaliza, ejecute otro play respecto de otro conjunto de
hosts.
Escribir un playbook que contenga varios plays es muy sencillo. Cada play en el playbook se
escribe como un ítem de lista de nivel superior en el playbook. Cada play es un ítem de una lista
que contiene las palabras clave de plays habituales.
En el siguiente ejemplo se muestra un playbook simple con dos plays. El primer play se ejecuta
respecto de web.example.com y el segunda, respecto de database.example.com.
---
# This is a simple playbook with two plays
- name: First play
  hosts: web.example.com
  tasks:
    - name: First task
      ansible.builtin.dnf:
        name: httpd
        state: present
    - name: Second task
      ansible.builtin.service:
        name: httpd
        enabled: true
- name: Second play
  hosts: database.example.com
  tasks:
    - name: First task
      ansible.builtin.service:
        name: mariadb
        enabled: true
