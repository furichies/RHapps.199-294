capítulo 7 |  Simplificación de playbooks con roles y Ansible Content Collections
Trabajo de laboratorio
Simplificación de playbooks con roles y
Ansible Content Collections
Crear roles de Ansible que usan variables, archivos, plantillas, tareas y manejadores.
Resultados
• Cree roles de Ansible que usen variables, archivos, plantillas, tareas y manejadores para
configurar un servidor web de desarrollo.
• En un playbook, use un rol que esté alojado en un repositorio remoto.
• Use un rol de sistema de Red Hat Enterprise Linux en un playbook.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start role-review
Instrucciones
Su organización debe proporcionar un único servidor web para alojar el código de desarrollo para
todos los desarrolladores web. Tiene la tarea de escribir un playbook para configurar este servidor
web de desarrollo.
El servidor web de desarrollo debe cumplir varios requisitos:
• La configuración del servidor de desarrollo debe coincidir con la configuración del servidor de
producción. El servidor de producción se debe configurar mediante un rol Ansible, desarrollado
por el equipo de infraestructura de la organización.
• Cada desarrollador recibe un directorio en el servidor de desarrollo para alojar el código y el
contenido. Se accede al contenido de cada desarrollador con un puerto asignado no estándar.
• SELinux está configurado en modo de ejecución y está usando la política de destino.
Su playbook debe:
• Usar un rol para configurar directorios y puertos para cada desarrollador del servidor web. Debe
escribir este rol.
Este rol depende de un rol para configurar Apache que fue escrito por su organización. Debe
especificar la versión v1.4 del rol para definir la dependencia. La URL del repositorio de Git de
la dependencia es: git@workstation.lab.example.com:infra/apache.

Por ejemplo, el rol apache.developer_configs que escriba más adelante en este trabajo

Cree un archivo roles/requirements.yml. Este archivo instala el rol desde el repositorio
de Git en git@workstation.lab.example.com:infra/apache, use la versión v1.4 y
asígnele el nombre infra.apache localmente.
Puede suponer que las claves SSH están configuradas para permitirle obtener roles de ese
repositorio automáticamente. Instale el rol con el comando ansible-galaxy.
6.
Inicie un nuevo rol llamado apache.developer_configs en el subdirectorio roles.
Agregue el rol infra.apache como una dependencia para el nuevo rol, usando la misma
información de nombre, fuente, versión y sistema de control de versión del archivo roles/
requirements.yml.
El archivo developer_tasks.yml del directorio del proyecto contiene tareas para el rol.
Mueva este archivo a la ubicación correcta en la jerarquía del directorio del rol para el archivo
de tareas que se usa para este rol y reemplace el archivo existente en esa ubicación.
El archivo developer.conf.j2 del directorio del proyecto es una plantilla de Jinja2 usada
por el archivo de tareas. Mueva este archivo a la ubicación correcta para los archivos de
plantilla usados por este rol.
7.
El rol apache.developer_configs crea una cuenta de usuario y configura una
instancia de servidor web para la lista de usuarios definida en la variable denominada
web_developers.
El archivo web_developers.yml del directorio del proyecto define la variable
web_developers que es la lista de usuarios del rol.
Revise este archivo y colóquelo en la ubicación correcta para definir la variable
web_developers para el grupo de hosts del servidor web de desarrollo de su inventario.
8.
Agregue el rol apache.developer_configs al play en el playbook
web_dev_server.yml.
9.
Verifique la sintaxis del playbook y, luego, ejecútelo. La verificación de la sintaxis debe
aprobarse, pero el playbook debe fallar cuando el rol infra.apache intenta reiniciar
Apache HTTPD.

capítulo 7 |  Simplificación de playbooks con roles y Ansible Content Collections
Resumen
• Los roles de Ansible lo ayudan a volver a usar y compartir el código de Ansible.
• Ansible Content Collections_ distribuye roles, módulos y otros complementos (plug-ins) de
Ansible relacionados que puede usar en proyectos de Ansible y entornos de ejecución de
automatización.
• Use el comando ansible-galaxy para gestionar los roles de Ansible y Ansible Content
Collections.
• Red Hat proporciona Ansible Content Collections certificadas por Red Hat a través de un
centro de automatización de servicios basados en la nube. Red Hat y sus partners admiten estas
Ansible Content Collections.
• Puede distribuir Ansible Content Collections certificadas por Red Hat o sus propias Ansible
Content Collections desde un centro de automatización privado en las instalaciones.
• Ansible Galaxy proporciona una librería de roles de Ansible de terceros y Ansible Content
Collections que son gestionadas por la comunidad y no son admitidas por Red Hat.
• Los roles del sistema (redhat.rhel_system_roles) se proporcionan como un paquete
RPM o como una Ansible Content Collection que consta de varios roles destinados a ayudarlo a
configurar subsistemas de hosts gestionados en varias versiones de Red Hat Enterprise Linux.
• Los roles y Ansible Content Collections que necesita un proyecto se pueden especificar
mediante archivos requirements.yml y se pueden instalar en su proyecto de Ansible
manualmente mediante ansible-galaxy.
