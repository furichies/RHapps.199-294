Introducción a variables de Ansible
Ansible soporta variables que se pueden usar para almacenar valores que, luego, se pueden
volver a usar en todos los archivos de un proyecto Ansible. Esto puede simplificar la creación y el
mantenimiento de un proyecto, así como reducir la cantidad de errores.
Las variables brindan una forma conveniente de gestionar los valores dinámicos para un entorno
dado en su proyecto Ansible. Los ejemplos de valores que pueden contener las variables incluyen:
• Usuarios para crear
• Paquetes para instalar
• Servicios para reiniciar
• Archivos para eliminar
• Colección de archivos para recuperar de Internet
Denominación de variables
Los nombres de las variables deben iniciarse con una letra y solo pueden contener letras, números
y guiones bajos.
En la siguiente tabla, se muestra la diferencia entre nombres de variable no válidos y válidos.

Definición de variables
Las variables se pueden definir en una variedad de lugares en un proyecto Ansible. Si una
variable se establece con el mismo nombre en dos lugares, y esas configuraciones tienen valores
diferentes, la precedencia determina qué valor se usa.

Puede establecer una variable que afecte a un grupo de hosts o solo a hosts individuales. Algunas
variables son datos que Ansible puede establecer en función de la configuración de un sistema. Se
pueden establecer otras variables dentro del playbook y afectar a un play en ese playbook o solo
a una tarea en ese play. También puede establecer variables adicionales en la línea de comandos
ansible-navigator run con la opción --extra-vars o -e y especificar esas variables, que
anulan todos los demás valores para ese nombre de variable.
La siguiente lista simplificada muestra formas de definir una variable, ordenada de menor a mayor
precedencia:
• Variables de grupo definidas en el inventario
• Agrupar variables definidas en archivos en un subdirectorio group_vars en el mismo directorio
que el inventario o el playbook
• Variables de host definidas en el inventario
• Variables de host definidas en archivos en un subdirectorio host_vars en el mismo directorio
que el inventario o el playbook
• Datos del host, descubiertos en tiempo de ejecución
• Variables de play en el playbook (vars y vars_files).
• Variables de tareas
• Variables adicionales definidas en la línea de comandos
Por ejemplo, una variable que está configurada para afectar al grupo de host all se reemplaza
por una variable que tiene el mismo nombre y que está configurada para afectar a un solo host.
Una práctica recomendada es elegir nombres de variables únicos a nivel mundial para que
no tenga que considerar las reglas de precedencia. Sin embargo, a veces tal vez desee usar
la precedencia para hacer que diferentes hosts o grupos de hosts obtengan configuraciones
diferentes a las predeterminadas.
Si el mismo nombre de variable se define en más de un nivel, el nivel con la mayor precedencia
gana. Un alcance limitado, como una variable de host o una variable de tarea, tiene precedencia
sobre un alcance más amplio, como una variable de grupo o una variable de play. Las variables
definidas por el playbook reemplazan las variables definidas por el inventario. Las variables
adicionales definidas en la línea de comandos con la opción --extra-vars o -e, tienen la mayor
precedencia.
Puede encontrar un análisis detallado y más preciso sobre la precedencia de variables en la
documentación de Ansible en "Variable precedence: Where should I put a variable?" [https://
docs.ansible.com/ansible/latest/user_guide/playbooks_variables.html#variable-precedence-
where-should-i-put-a-variable].
Variables en playbooks
Las variables desempeñan un rol importante en los playbooks de Ansible porque facilitan la
administración de datos variables en un playbook.
Definición de variables en playbooks
Cuando se escriben plays, se pueden definir las propias variables y luego invocar esos
valores en una tarea. Por ejemplo, una variable llamada web_package se puede definir
con un valor de httpd. Por lo tanto, una tarea puede llamar a la variable usando el módulo
ansible.builtin.dnf para instalar el paquete httpd.

Usted puede definir variables de playbook de múltiples maneras. Uno de los métodos más
comunes es colocar una variable en un bloque vars al comienzo de un play:
- hosts: all
  vars:
    user: joe
    home: /home/joe
También es posible definir variables de playbooks en archivos externos. En este caso, en lugar de
usar el bloque vars en el playbook, se puede usar la directiva vars_files, seguida de una lista
de nombres para archivos de variables externas, relativos a la ubicación del playbook:
- hosts: all
  vars_files:
    - vars/users.yml
A continuación, las variables del playbook se definen en esos archivos en formato YAML:
user: joe
home: /home/joe
Uso de variables en playbooks
Una vez declaradas las variables, puede usar las variables en tareas. Se hace referencia a las
variables colocando el nombre de la variable entre llaves dobles ({{ }}). Ansible sustituye la
variable con su valor cuando se ejecuta la tarea.
vars:
  user: joe
tasks:
  # This line will read: Creates the user joe
  - name: Creates the user {{ user }}
    user:
      # This line will create the user named Joe
      name: "{{ user }}"

Variables de hosts y variables de grupos
Las variables de inventario que se aplican directamente a los hosts se dividen en dos categorías
amplias: variables de host, que se aplican a un host específico; y variables de grupo, que se aplican
a todos los hosts en un grupo de hosts o en un grupo de grupos de hosts. Las variables de hosts
preceden a las variables de grupos, pero las variables definidas por un playbook preceden a
ambas.
Una forma de definir las variables de hosts y las variables de grupos es hacerlo directamente en el
archivo de inventario.
nota
Este es un enfoque anterior para definir las variables de hosts y grupos, pero es
posible que lo vea en uso porque pone toda la información del inventario y la
configuración de variables para hosts y grupos de hosts en un solo archivo.
• Definición de la variable de host ansible_user para demo.example.com:
[servers]
demo.example.com  ansible_user=joe
• Definición de la variable de grupo user para el grupo de hosts servers.

Uso de directorios para completar variables de host y de grupo
Puede definir variables para host y grupos de hosts al crear dos directorios, group_vars
y host_vars, en el mismo directorio de trabajo como archivo de inventario o playbook.
Estos directorios contienen archivos que definen variables de grupo y variables de host,
respectivamente.
Importante
La práctica recomendada es definir las variables de inventario usando los directorios
host_vars y group_vars, y no definirlas directamente en los archivos de
inventario.
Para definir variables de grupo para el grupo servers, debería crear un archivo YAML
denominado group_vars/servers y, luego, el contenido de ese archivo establecería variables
para valores usando la misma sintaxis que en un playbook:
user: joe
De la misma forma, para definir variables de hosts para un host específico, cree un archivo con un
nombre que coincida con el host que se encuentra en el directorio host_vars para que contenga
las variables de hosts.

Reemplazo de las variables de la línea de comandos
Las variables de inventario son reemplazadas por variables establecidas en un playbook, pero
ambos tipos de variables se pueden reemplazar mediante argumentos enviados al comando
ansible-navigator run en la línea de comando. Las variables establecidas en la línea de
comando se denominan variables adicionales.
Las variables adicionales pueden ser útiles cuando debe reemplazar el valor definido para una
variable para una ejecución única de un playbook. Por ejemplo:
[user@demo ~]$ ansible-navigator run main.yml -e "package=apache"
Uso de diccionarios como variables
En lugar de asignar datos de configuración que se relacionen con el mismo elemento con múltiples
variables, los administradores pueden usar diccionarios. Un diccionario es una estructura de datos
que contiene pares de clave-valor, donde los valores también pueden ser diccionarios.
Por ejemplo, considere el siguiente fragmento:
user1_first_name: Bob
user1_last_name: Jones
user1_home_dir: /users/bjones
user2_first_name: Anne
user2_last_name: Cook
user2_home_dir: /users/acook
Este se puede reescribir como un diccionario denominado users:
users:
  bjones:
    first_name: Bob
    last_name: Jones
    home_dir: /users/bjones

Importante
La notación de punto puede causar problemas si los nombres clave son los mismos
que los nombres de los métodos o atributos de Python, como discard, copy, add
y así sucesivamente. Usar la notación de paréntesis puede ayudar a evitar conflictos
y errores.
Ambas sintaxis son válidas, pero para simplificar la solución de problemas, Red Hat
recomienda usar una sintaxis de manera consistente en todos los archivos en
cualquier proyecto de Ansible.
Captura de salida de comando con variables
registradas
Puede usar la instrucción register para capturar la salida de un comando u otra información
sobre la ejecución de un módulo. La salida se guarda en una variable que puede usarse
posteriormente en el playbook con motivos de depuración u otros motivos, como aplicar una
configuración particular basada en la salida de un comando.
El siguiente play demuestra cómo capturar el resultado de un comando con motivos de
depuración:
---
- name: Installs a package and prints the result
  hosts: all
  tasks:
    - name: Install the package
      ansible.builtin.dnf:
        name: httpd
        state: installed
