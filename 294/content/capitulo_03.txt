Introducción a variables de Ansible
Ansible soporta variables que se pueden usar para almacenar valores que, luego, se pueden
volver a usar en todos los archivos de un proyecto Ansible. Esto puede simplificar la creación y el
mantenimiento de un proyecto, así como reducir la cantidad de errores.
Las variables brindan una forma conveniente de gestionar los valores dinámicos para un entorno
dado en su proyecto Ansible. Los ejemplos de valores que pueden contener las variables incluyen:
• Usuarios para crear
• Paquetes para instalar
• Servicios para reiniciar
• Archivos para eliminar
• Colección de archivos para recuperar de Internet
Denominación de variables
Los nombres de las variables deben iniciarse con una letra y solo pueden contener letras, números
y guiones bajos.
En la siguiente tabla, se muestra la diferencia entre nombres de variable no válidos y válidos.

Definición de variables
Las variables se pueden definir en una variedad de lugares en un proyecto Ansible. Si una
variable se establece con el mismo nombre en dos lugares, y esas configuraciones tienen valores
diferentes, la precedencia determina qué valor se usa.

Puede establecer una variable que afecte a un grupo de hosts o solo a hosts individuales. Algunas
variables son datos que Ansible puede establecer en función de la configuración de un sistema. Se
pueden establecer otras variables dentro del playbook y afectar a un play en ese playbook o solo
a una tarea en ese play. También puede establecer variables adicionales en la línea de comandos
ansible-navigator run con la opción --extra-vars o -e y especificar esas variables, que
anulan todos los demás valores para ese nombre de variable.
La siguiente lista simplificada muestra formas de definir una variable, ordenada de menor a mayor
precedencia:
• Variables de grupo definidas en el inventario
• Agrupar variables definidas en archivos en un subdirectorio group_vars en el mismo directorio
que el inventario o el playbook
• Variables de host definidas en el inventario
• Variables de host definidas en archivos en un subdirectorio host_vars en el mismo directorio
que el inventario o el playbook
• Datos del host, descubiertos en tiempo de ejecución
• Variables de play en el playbook (vars y vars_files).
• Variables de tareas
• Variables adicionales definidas en la línea de comandos
Por ejemplo, una variable que está configurada para afectar al grupo de host all se reemplaza
por una variable que tiene el mismo nombre y que está configurada para afectar a un solo host.
Una práctica recomendada es elegir nombres de variables únicos a nivel mundial para que
no tenga que considerar las reglas de precedencia. Sin embargo, a veces tal vez desee usar
la precedencia para hacer que diferentes hosts o grupos de hosts obtengan configuraciones
diferentes a las predeterminadas.
Si el mismo nombre de variable se define en más de un nivel, el nivel con la mayor precedencia
gana. Un alcance limitado, como una variable de host o una variable de tarea, tiene precedencia
sobre un alcance más amplio, como una variable de grupo o una variable de play. Las variables
definidas por el playbook reemplazan las variables definidas por el inventario. Las variables
adicionales definidas en la línea de comandos con la opción --extra-vars o -e, tienen la mayor
precedencia.
Puede encontrar un análisis detallado y más preciso sobre la precedencia de variables en la
documentación de Ansible en "Variable precedence: Where should I put a variable?" [https://
docs.ansible.com/ansible/latest/user_guide/playbooks_variables.html#variable-precedence-
where-should-i-put-a-variable].
Variables en playbooks
Las variables desempeñan un rol importante en los playbooks de Ansible porque facilitan la
administración de datos variables en un playbook.
Definición de variables en playbooks
Cuando se escriben plays, se pueden definir las propias variables y luego invocar esos
valores en una tarea. Por ejemplo, una variable llamada web_package se puede definir
con un valor de httpd. Por lo tanto, una tarea puede llamar a la variable usando el módulo
ansible.builtin.dnf para instalar el paquete httpd.

Usted puede definir variables de playbook de múltiples maneras. Uno de los métodos más
comunes es colocar una variable en un bloque vars al comienzo de un play:
- hosts: all
  vars:
    user: joe
    home: /home/joe
También es posible definir variables de playbooks en archivos externos. En este caso, en lugar de
usar el bloque vars en el playbook, se puede usar la directiva vars_files, seguida de una lista
de nombres para archivos de variables externas, relativos a la ubicación del playbook:
- hosts: all
  vars_files:
    - vars/users.yml
A continuación, las variables del playbook se definen en esos archivos en formato YAML:
user: joe
home: /home/joe
Uso de variables en playbooks
Una vez declaradas las variables, puede usar las variables en tareas. Se hace referencia a las
variables colocando el nombre de la variable entre llaves dobles ({{ }}). Ansible sustituye la
variable con su valor cuando se ejecuta la tarea.
vars:
  user: joe
tasks:
  # This line will read: Creates the user joe
  - name: Creates the user {{ user }}
    user:
      # This line will create the user named Joe
      name: "{{ user }}"

Variables de hosts y variables de grupos
Las variables de inventario que se aplican directamente a los hosts se dividen en dos categorías
amplias: variables de host, que se aplican a un host específico; y variables de grupo, que se aplican
a todos los hosts en un grupo de hosts o en un grupo de grupos de hosts. Las variables de hosts
preceden a las variables de grupos, pero las variables definidas por un playbook preceden a
ambas.
Una forma de definir las variables de hosts y las variables de grupos es hacerlo directamente en el
archivo de inventario.
nota
Este es un enfoque anterior para definir las variables de hosts y grupos, pero es
posible que lo vea en uso porque pone toda la información del inventario y la
configuración de variables para hosts y grupos de hosts en un solo archivo.
• Definición de la variable de host ansible_user para demo.example.com:
[servers]
demo.example.com  ansible_user=joe
• Definición de la variable de grupo user para el grupo de hosts servers.

Uso de directorios para completar variables de host y de grupo
Puede definir variables para host y grupos de hosts al crear dos directorios, group_vars
y host_vars, en el mismo directorio de trabajo como archivo de inventario o playbook.
Estos directorios contienen archivos que definen variables de grupo y variables de host,
respectivamente.
Importante
La práctica recomendada es definir las variables de inventario usando los directorios
host_vars y group_vars, y no definirlas directamente en los archivos de
inventario.
Para definir variables de grupo para el grupo servers, debería crear un archivo YAML
denominado group_vars/servers y, luego, el contenido de ese archivo establecería variables
para valores usando la misma sintaxis que en un playbook:
user: joe
De la misma forma, para definir variables de hosts para un host específico, cree un archivo con un
nombre que coincida con el host que se encuentra en el directorio host_vars para que contenga
las variables de hosts.

Reemplazo de las variables de la línea de comandos
Las variables de inventario son reemplazadas por variables establecidas en un playbook, pero
ambos tipos de variables se pueden reemplazar mediante argumentos enviados al comando
ansible-navigator run en la línea de comando. Las variables establecidas en la línea de
comando se denominan variables adicionales.
Las variables adicionales pueden ser útiles cuando debe reemplazar el valor definido para una
variable para una ejecución única de un playbook. Por ejemplo:
[user@demo ~]$ ansible-navigator run main.yml -e "package=apache"
Uso de diccionarios como variables
En lugar de asignar datos de configuración que se relacionen con el mismo elemento con múltiples
variables, los administradores pueden usar diccionarios. Un diccionario es una estructura de datos
que contiene pares de clave-valor, donde los valores también pueden ser diccionarios.
Por ejemplo, considere el siguiente fragmento:
user1_first_name: Bob
user1_last_name: Jones
user1_home_dir: /users/bjones
user2_first_name: Anne
user2_last_name: Cook
user2_home_dir: /users/acook
Este se puede reescribir como un diccionario denominado users:
users:
  bjones:
    first_name: Bob
    last_name: Jones
    home_dir: /users/bjones

Importante
La notación de punto puede causar problemas si los nombres clave son los mismos
que los nombres de los métodos o atributos de Python, como discard, copy, add
y así sucesivamente. Usar la notación de paréntesis puede ayudar a evitar conflictos
y errores.
Ambas sintaxis son válidas, pero para simplificar la solución de problemas, Red Hat
recomienda usar una sintaxis de manera consistente en todos los archivos en
cualquier proyecto de Ansible.
Captura de salida de comando con variables
registradas
Puede usar la instrucción register para capturar la salida de un comando u otra información

Presentación de Ansible Vault
Es posible que Ansible necesite acceso a datos confidenciales, como contraseñas o claves API,
para configurar hosts gestionados. En general, esta información se almacena como texto sin
formato en variables de inventario u otros archivos de Ansible. Sin embargo, en ese caso, los
usuarios con acceso a los archivos de Ansible o a un sistema de control de versiones que almacena
los archivos de Ansible tendrían acceso a estos datos confidenciales. Esto representa un riesgo de
seguridad notorio.
Se puede usar Ansible Vault, que está incluido con Ansible, para cifrar y descifrar cualquier archivo
de datos estructurados usado por Ansible. Para usar Ansible Vault, use una herramienta de la línea
de comandos denominada ansible-vault para crear, editar, cifrar, descifrar y ver archivos.
Ansible Vault puede cifrar cualquier archivo de datos usado por Ansible. Esto podría incluir
variables de inventario, archivos de variables incluidos en un playbook, archivos de variables
pasados como argumento al ejecutar el playbook o variables definidas en roles de Ansible.
Importante
Ansible Vault no implementa sus propias funciones criptográficas, sino que
usa un kit de herramientas Python externo. Los archivos están protegidos con
cifrado simétrico mediante el uso de AES256 con una contraseña como clave
secreta. Tenga en cuenta que la forma en la que se realiza esto no ha sido auditada
formalmente por un tercero.
Creación de un archivo cifrado
Para crear un nuevo archivo cifrado, use el comando ansible-vault create filename.
El comando le solicitará la nueva contraseña de Vault y abrirá un archivo con el editor
predeterminado, vi. Puede exportar la variable de entorno EDITOR para especificar un editor
predeterminado diferente. Por ejemplo, para establecer el editor predeterminado en nano,
ejecute el comando export EDITOR=nano.
[student@demo ~]$ ansible-vault create secret.yml
New Vault password: redhat
Confirm New Vault password: redhat
En lugar de ingresar la contraseña de Vault mediante el ingreso estándar, se puede usar un
archivo de contraseña de Vault para almacenar la contraseña. Este archivo se deberá proteger
cuidadosamente mediante permisos de archivo y por otros medios.
[student@demo ~]$ ansible-vault create --vault-password-file=vault-pass secret.yml

Objetivos

Descripción de Datos de Ansible
Los datos de Ansible son variables detectadas automáticamente por Ansible en un host
gestionado. Los datos contienen información específica del host que puede usarse como variables
regulares en plays, condicionales, bucles o cualquier otra declaración que dependa de un valor
recopilado de un host gestionado.
Algunos datos recopilados para un host gestionado pueden incluir los siguientes:
• El nombre del host
• La versión del kernel
• Nombres de interfaz de red
• Direcciones IP de la interfaz de red
• Versiones del sistema operativo
• La cantidad de CPU
• Memoria disponible o libre
• Tamaño y espacio libre de los dispositivos de almacenamiento
Incluso puede crear datos personalizados, que se almacenan en el host gestionado y son
exclusivos de ese sistema.
Los datos son una forma conveniente de recuperar el estado de un host gestionado y de
determinar qué acción tomar en función de ese estado. Por ejemplo:
• Su play puede reiniciar un servidor mediante el uso de una tarea condicional basada en el valor
de un dato que se recopiló, como el estado de un servicio en particular.
• El play puede personalizar un archivo de configuración MySQL según la memoria disponible
informada por un dato.
• La dirección IPv4 usada en un archivo de configuración podría configurarse sobre la base del
valor de un dato.
En general, cada play ejecuta el módulo ansible.builtin.setup de forma automática para
recopilar datos antes de la primera tarea.
Esto se informa como la tarea Gathering Facts en Ansible 2.3 y versiones posteriores o
simplemente como setup en versiones anteriores de Ansible. De forma predeterminada, no es
necesario tener una tarea para ejecutar ansible.builtin.setup en su play. En general, se
ejecuta automáticamente para usted.
Una forma de ver qué datos se recopilan para sus hosts gestionados es ejecutar un playbook
corto que recopile datos y use el módulo ansible.builtin.debug para imprimir el valor de la
variable ansible_facts.

Datos de Ansible inyectados como variables
Antes de Ansible 2.5, los datos siempre se insertaban como variables individuales prefijadas con
la cadena ansible_ en lugar de ser parte de la variable ansible_facts. Por ejemplo, el dato
ansible_facts['distribution'] fue denominado ansible_distribution.
Muchos playbooks aún usan datos inyectados como variables en lugar de la nueva sintaxis, que
usa el espacio de nombre ansible_facts.*.
Una de las razones por las que la comunidad de Ansible desalienta la introducción de datos como
variables es porque se corre el riesgo de colisiones inesperadas entre datos y variables. Un dato
tiene una prioridad muy alta que anula el playbook y las variables de host y grupo de inventario,
por lo que esto puede provocar efectos secundarios inesperados.

ansible_facts.*.

Desactivación de la recopilación de datos
Algunas veces, no deseará recopilar datos para su play. Esto puede deberse a varias razones:
• Es posible que no esté usando los datos y desee acelerar el play o reducir la carga provocada
por el play en los hosts gestionados.
• Es posible que los hosts gestionados no puedan ejecutar el módulo ansible.builtin.setup
por algún motivo o deba instalar algún software de requisito previo antes de recopilar datos.
Para deshabilitar la recopilación de datos para un play, establezca la palabra clave gather_facts
en false:
---
- name: This play does not automatically gather any facts
  hosts: large_datacenter
  gather_facts: false

Recopilación de un subconjunto de datos
Todos los datos se recopilan de forma predeterminada. Puede configurar el módulo
ansible.builtin.setup para recopilar solo un subconjunto de datos, en lugar de todos
los datos. Por ejemplo, para recopilar solo datos de hardware, establezca gather_subset en
hardware:
- name: Collect only hardware facts
  ansible.builtin.setup:
    gather_subset:
      - hardware
Si desea recopilar todos los datos, excepto un subconjunto determinado, agregue un signo de
exclamación (!) delante del nombre del subconjunto. Agregue comillas alrededor de la cadena
porque en YAML el signo de exclamación no puede usarse al comienzo de una cadena sin comillas.
- name: Collect all facts except for hardware facts
  ansible.builtin.setup:
    gather_subset:
      - "!hardware"
Visite https://docs.ansible.com/ansible/latest/collections/ansible/builtin/
setup_module.html#parameter-gather_subset para ver los posibles valores del parámetro
gather_subset.
Creación de datos personalizados
Puede usar datos personalizados para definir ciertos valores para hosts gestionados. Los plays
pueden usar datos personalizados para completar archivos de configuración o ejecutar tareas de
forma condicional.
Los datos personalizados se almacenen localmente en cada host gestionado. Estos datos están
integrados en la lista de datos estándares recopilados por el módulo ansible.builtin.setup
cuando se ejecuta en el host gestionado.
Puede definir datos personalizados estáticamente en un archivo INI o JSON, o puede generarlos
dinámicamente cuando ejecuta un play. Los datos personalizados dinámicos se recopilan a través
de scripts ejecutables, que generan una salida JSON.
De forma predeterminada, el módulo ansible.builtin.setup carga datos personalizados
de archivos y scripts en el directorio etc/ansible/facts.d de cada host gestionado. El
nombre de cada archivo o script debe finalizar en .fact para poder usarse. Los scripts de datos
personalizados dinámicos deben mostrar datos con formato JSON y deben ser ejecutables.

El ejemplo anterior creó datos personalizados en hosts gestionados. En ese ejemplo, puede usar

asociada al host actual. Por ejemplo, puede definir la variable custom_host y usar la variable

ansible_facts['ansible_local']['custom']['users'].
También puede usar el módulo ansible.builtin.set_fact para minimizar la escritura de
datos regulares del sistema o variables registradas. Por ejemplo:

Uso de variables mágicas
Ansible establece algunas variables especiales automáticamente.
Estas variables mágicas pueden ser útiles para obtener información específica de un host
gestionado particular.
Los nombres de las variables mágicas están reservados, por lo que no debe definir variables con
estos nombres.
Cuatro de las variables mágicas más útiles son:
hostvars
Contiene las variables para hosts gestionados y puede usarse para obtener los valores para
las variables de otro host gestionado. No incluye los datos del host gestionado si no se
recopilaron aún para ese host.
group_names
Enumera todos los grupos en los que se encuentra el host gestionado actual.
groups
Enumera todos los grupos y hosts en el inventario.
inventory_hostname
Contiene el nombre de host para el host gestionado actual, según se configuró en el
inventario. Este podría ser diferente del nombre de host informado por los datos por diversos
motivos.

capítulo 3 |  Administración de variables y datos
Resumen
• Las variables de Ansible lo ayudan a volver a usar valores en los archivos de un proyecto
completo de Ansible.
• Puede definir las variables para los hosts y los grupos de hosts en el archivo de inventario.
• Puede definir variables para plays y tareas en el playbook o en archivos externos.
• Se definen variables extra en la línea de comandos y preceden a todas las demás variables.
• Puede usar la palabra clave register para capturar la salida de un comando en una variable.
• Ansible Vault proporciona una manera de proteger los datos confidenciales, como los hash de
contraseñas y las claves privadas que usa sus playbooks de Ansible.
• Los datos de Ansible son variables que Ansible detecta automáticamente desde un host
gestionado.
