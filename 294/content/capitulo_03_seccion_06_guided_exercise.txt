Ejercicio Guiado
Gestión de datos
Recopilar datos Ansible de un host gestionado y usarlos en los plays.
Resultados
Usted deberá ser capaz de realizar lo siguiente:
• Reunir datos de un host.
• Crear tareas que usen los datos recogidos.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start data-facts

 5.
Cree el directorio /etc/ansible/facts.d en servera y, luego, cree el archivo
custom.fact en ese directorio. El archivo de datos define el paquete que se debe instalar
y el servicio que se inicia en servera.
5.1.
Cree el directorio /etc/ansible/facts.d en servera.
[student@workstation data-facts]$ ssh servera
[student@servera ~]$ sudo mkdir -p /etc/ansible/facts.d
[sudo] password for student: student
5.2.
Cree el archivo custom.fact en el directorio /etc/ansible/facts.d en
servera. Necesita privilegios elevados para crear un archivo en ese directorio.
El contenido del archivo debe verse de la siguiente forma:
[general]
package = httpd
service = httpd
state = started
enabled = true

 6.
Cree un playbook denominado playbook.yml en el directorio /home/student/data-
facts que contenga un solo play. Ese play se ejecuta en los hosts gestionados en el grupo
de hosts webserver. Usa datos personalizados para instalar un paquete y garantizar que
un servicio de red se encuentre en un estado particular en cada host del grupo.
6.1.
Cree un play en el playbook playbook.yml con el siguiente nombre y la directiva
hosts:
---
- name: Install Apache and start the service
  hosts: webserver
6.2.
Crea la primera tarea para ese play. Para minimizar la escritura en el play, use el
módulo ansible.builtin.set_fact para definir una nueva variable denominada
custom que use el dato personalizado ansible_facts['ansible_local']
['custom']['general'].
  tasks:
    - name: Set custom variable
      ansible.builtin.set_fact:
        custom: "{{ ansible_facts['ansible_local']['custom']['general'] }}"
6.3.
Cree otra tarea que garantice que esté instalada la última versión del paquete al que
hace referencia la variable custom['package'] para el host gestionado.

6.4.
Cree otra tarea que use la variable custom['service'] para controlar el servicio
especificado.
Esa tarea también debe usar la variable custom['state'] para determinar si iniciar
o detener el servicio, y la variable custom['enabled'] para controlar si se inicia o
no cuando arranca el sistema.

      ansible.builtin.service:
        name: "{{ custom['service'] }}"
        state: "{{ custom['state'] }}"
        enabled: "{{ custom['enabled'] }}"
6.5.
El playbook completo debería incluir el siguiente contenido. Revise el contenido del
playbook y garantice que todas las tareas estén definidas.
---
- name: Install Apache and start the service
  hosts: webserver
  tasks:
    - name: Set custom variable
      ansible.builtin.set_fact:
        custom: "{{ ansible_facts['ansible_local']['custom']['general'] }}"
    - name: Install the required package
      ansible.builtin.dnf:
        name: "{{ custom['package'] }}"
        state: latest
    - name: Start the service
      ansible.builtin.service:
        name: "{{ custom['service'] }}"
        state: "{{ custom['state'] }}"
        enabled: "{{ custom['enabled'] }}"

Escribir y ejecutar un playbook de Ansible que use variables, secretos y datos.
Resultados
• Debe ser capaz de definir variables y usar datos en un playbook, así como usar variables

Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
El host gestionado serverb.lab.example.com está definido en este inventario como
miembro del grupo de hosts webserver. Un desarrollador le ha pedido que escriba un
playbook de Ansible para automatizar la configuración de un entorno de servidor web
en serverb.lab.example.com, que controla el acceso de los usuarios a su sitio web
mediante autenticación básica.
El subdirectorio files contiene los siguientes archivos:
• Un archivo de configuración httpd.conf para el servicio web Apache para autenticación
básica
• Un archivo .htaccess que se usa para controlar el acceso al directorio raíz de
documentos del servidor web.
• Un archivo htpasswd que contiene credenciales para los usuarios permitidos
