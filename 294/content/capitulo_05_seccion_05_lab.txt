capítulo 5 |  Implementación de archivos en hosts gestionados
Trabajo de laboratorio
Implementación de archivos en hosts
gestionados
Ejecutar un playbook que cree un archivo personalizado en sus hosts gestionados mediante
el uso de una plantilla Jinja2.
Resultados
• Crear un archivo de plantilla.
• Usar el archivo de plantilla en un playbook.
Antes De Comenzar
Con el usuario student en la máquina workstation, use el comando lab para preparar su
sistema para este ejercicio.
Este comando prepara su entorno y garantiza que estén disponibles todos los recursos
requeridos.
[student@workstation ~]$ lab start file-review
nota
Todos los archivos usados en este ejercicio están disponibles en
workstation en el directorio /home/student/file-review/files.
Instrucciones
1.
Revise el archivo inventory generado en el directorio /home/student/file-review.
Este archivo de inventario define el grupo servers, el cual tiene asociado el host gestionado
serverb.lab.example.com.
2.
Identifique los datos en serverb.lab.example.com, que muestran la cantidad total de
memoria del sistema y la cantidad de procesadores que tiene.
3.
En el directorio /home/student/file-review, cree el archivo de plantillas Jinja2
templates/motd.j2. Después de implementar esta plantilla, los usuarios que inicien
sesión en serverb.lab.example.com deberían ver un mensaje que muestre el recuento
total de procesadores y memoria del sistema.
El mensaje puede usar el texto que desee, pero la plantilla debe usar los datos
ansible_facts['memtotal_mb'] y ansible_facts['processor_count'] para
proporcionar la información de recursos del sistema para el mensaje.
4.
En el directorio /home/student/file-review, cree un archivo de playbook denominado
motd.yml que contenga un nuevo play que se ejecuta en todos los hosts del inventario.
Debe iniciar sesión con el usuario devops en el host remoto y usar become para habilitar el
aumento de privilegios para todo el play.

El play debe tener una tarea que use el módulo ansible.builtin.template para
implementar el archivo de plantilla motd.j2 Jinja2 en el archivo /etc/motd en los hosts
gestionados. El archivo resultante debe tener el usuario root como su usuario y grupo
propietario, y sus permisos deben ser 0644.
Agregue una tarea adicional que use el módulo ansible.builtin.stat para verificar
que /etc/motd exista en los hosts gestionados y registre sus resultados en una variable.
Esa tarea debe ir seguida de una tarea que use ansible.builtin.debug para mostrar la
información en esa variable registrada.
Agregue una tarea que use el módulo ansible.builtin.copy para colocar files/
issue en el directorio /etc/ del host gestionado; use la misma propiedad y los mismos
permisos que /etc/motd.
Por último, agregue una tarea que use el módulo ansible.builtin.file para asegurarse
de que /etc/issue.net sea un enlace simbólico a /etc/issue en el host gestionado.
5.
Verifique que su playbook no contenga errores de sintaxis.
6.
Ejecute el playbook de Ansible motd.yml.
7.
Confirme que el playbook motd.yml se haya ejecutado correctamente.
Evaluación
Con el usuario student en la máquina workstation, use el comando lab para calificar su
trabajo. Corrija los errores informados y vuelva a ejecutar el comando hasta obtener un resultado
satisfactorio.
[student@workstation ~]$ lab grade file-review
Finalizar
En la máquina workstation, cambie al directorio de inicio de usuario student y use el comando
lab para completar este ejercicio. Este paso es importante para garantizar que los recursos de
ejercicios anteriores no impacten en los siguientes.
[student@workstation ~]$ lab finish file-review

capítulo 5 |  Implementación de archivos en hosts gestionados
Resumen
• Los módulos de gestión de archivos en Ansible Content Collections ansible.builtin y
ansible.posix le permiten realizar la mayoría de las tareas relacionadas con la administración
de archivos, como crear, copiar, editar y modificar permisos y otros atributos de archivos.
• Varios módulos de administración de archivos pueden establecer el modo de permisos y el
contexto de SELinux para los archivos.
• Puede usar plantillas Jinja2 para crear archivos dinámicamente para la implementación.
• Por lo general, una plantilla Jinja2 se compone de dos elementos: variables y expresiones. Estas
variables y expresiones se reemplazan con valores cuando se entrega la plantilla Jinja2.
• Use el módulo ansible.builtin.template para implementar plantillas Jinja2 en hosts
gestionados.
• Los filtros en Jinja2 transforman las expresiones de las plantillas de un tipo o formato de datos a
otro.
