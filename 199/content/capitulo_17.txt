# Capítulo 14. Gestión de la seguridad con SELinux

## 14.1. Operando SELinux

14.1. Operando SELinux 14.1. Operación de SELinux Objetivos Describir cómo funciona SELinux y controlar el modo SELinux predeterminado y actual. SELinux Architecture Security Enhanced Linux (SELinux) es una característica de seguridad crítica de Linux. El acceso a archivos, puertos y otros recursos se controla a nivel granular. A los procesos se les permite acceder solo a los recursos que especifican su política SELinux o su configuración booleana. Los permisos de archivos controlan el acceso a los archivos para un usuario o grupo específico. Sin embargo, los permisos de archivos no impiden que un usuario autorizado con acceso a archivos utilice un archivo para un fin no deseado. Por ejemplo, con acceso de escritura a un archivo, otros editores o programas aún pueden abrir y modificar un archivo de datos estructurados que está diseñado para que escriba únicamente un programa específico. Estas operaciones podrían provocar daños en los archivos o un problema de seguridad de los datos. Los permisos de archivos no impiden dicho acceso no deseado, porque no controlan cómo se utiliza un archivo, sino sólo quién puede leerlo, escribirlo o ejecutarlo. SELinux consta de políticas específicas de la aplicación que los desarrolladores de la aplicación definen para declarar qué acciones y accesos están permitidos para cada ejecutable binario, archivo de configuración y archivo de datos que utiliza la aplicación. Esta política se conoce como política dirigida porque una política define las actividades de una aplicación. Las políticas declaran las etiquetas predefinidas que se configuran en programas, archivos y puertos de red individuales. Uso de SELinux SELinux impone un conjunto de reglas de acceso que definen explícitamente acciones permitidas entre procesos y recursos. No se permite ninguna acción que no esté definida en una regla de acceso. Como sólo se permiten acciones definidas, las aplicaciones con un diseño de seguridad deficiente siguen estando protegidas contra el uso malicioso. Las aplicaciones o servicios con una política específica se ejecutan en un dominio confinado, mientras que una aplicación sin una política se ejecuta de forma ilimitada y sin ninguna protección SELinux. Las políticas específicas individuales se pueden deshabilitar para ayudar con el desarrollo y la depuración de políticas de seguridad y aplicaciones. SELinux tiene los siguientes modos operativos: Aplicación: SELinux aplica las políticas de seguridad en todo el sistema. El modo de aplicación es el modo predeterminado y recomendado en Red Hat Enterprise Linux. Permisivo: SELinux carga las políticas y está activo, pero en lugar de imponer reglas de control de acceso, registra las violaciones de acceso. Este modo es útil para probar y solucionar problemas de aplicaciones y reglas. Deshabilitado: SELinux está desactivado y las violaciones de SELinux no se implementan ni se registran. Este modo también evita etiquetar archivos o directorios con contextos de seguridad, lo que dificulta la habilitación de SELinux en el futuro. Se desaconseja encarecidamente deshabilitar SELinux. Importante RHEL ya no admite la configuración de la opción SELINUX=disabled en el archivo /etc/selinux/config.





14.1. Operación de SELinux Conceptos de SELinux El objetivo principal de SELinux es proteger los datos del usuario del uso inadecuado por parte de aplicaciones o servicios del sistema comprometidos. La mayoría de los administradores de Linux están familiarizados con el modelo de seguridad estándar de permisos de archivos de usuarios, grupos y mundos, que se conoce como Control de acceso discrecional (DAC) porque los administradores establecen los permisos de archivos según sus necesidades. SELinux proporciona una capa adicional de seguridad basada en objetos, que se define en reglas granulares. Esta capa de seguridad se conoce como Control de acceso obligatorio (MAC). Las políticas MAC se aplican a todos los usuarios y no se pueden omitir para usuarios específicos mediante ajustes de configuración discrecionales. Por ejemplo, el puerto de firewall abierto de un servidor web permite el acceso anónimo remoto a un cliente web. Sin embargo, un usuario malintencionado que acceda a ese puerto podría intentar comprometer un sistema a través de una vulnerabilidad existente. Si una vulnerabilidad compromete los permisos del usuario y grupo de Apache, entonces un usuario malintencionado podría acceder directamente al contenido raíz del documento /var/www/html, o a los directorios /tmp y /var/tmp del sistema, u otros archivos y directorios accesibles. Las políticas de SELinux son reglas de seguridad que definen cómo procesos específicos acceden a archivos, directorios y puertos relevantes. Cada entidad de recurso, como un archivo, proceso, directorio o puerto, tiene una etiqueta de contexto SELinux. La etiqueta de contexto coincide con una regla de política SELinux definida para permitir que un proceso acceda al recurso etiquetado. De forma predeterminada, una política SELinux no permite ningún acceso a menos que una regla explícita lo otorgue. Cuando no se define ninguna regla de permiso, no se permite ningún acceso. Las etiquetas SELinux tienen campos de usuario, rol, tipo y nivel de seguridad. La política dirigida, que está habilitada en RHEL de forma predeterminada, define reglas utilizando el contexto de tipo. Los nombres de contexto de tipo normalmente terminan con _t. Figura 17. Conceptos de reglas de acceso a políticas de contexto de archivo SELinux Por ejemplo, un proceso de servidor web está etiquetado con el contexto de tipo httpd_t. Los archivos y directorios del servidor web en el directorio /var/www/html/ y otras ubicaciones están etiquetados con el contexto de tipo httpd_sys_content_t. Los archivos temporales en los directorios /tmp y /var/tmp tienen contextos de tipo tmp_t como etiqueta. Los puertos del servidor web tienen como etiqueta el contexto de tipo http_port_t. Un proceso del servidor web Apache se ejecuta con el contexto de tipo httpd_t. Una regla de política permite que el servidor Apache acceda a archivos y directorios etiquetados con el contexto de tipo httpd_sys_content_t. De forma predeterminada, los archivos en el directorio /var/www/html tienen el contexto de tipo httpd_sys_content_t. De forma predeterminada, una política de servidor web no permite reglas para el uso de archivos etiquetados como tmp_t, como en los directorios /tmp y /var/tmp, por lo que no permite el acceso. Con SELinux habilitado, un usuario malintencionado que utilice un proceso Apache comprometido aún no tendría acceso a los archivos del directorio /tmp. Un proceso del servidor MariaDB se ejecuta con el contexto de tipo mysqld_t. De forma predeterminada, los archivos en el directorio /data/mysql tienen el contexto de tipo mysqld_db_t. Un servidor MariaDB puede acceder a los archivos etiquetados mysqld_db_t, pero no tiene reglas para permitir el acceso a archivos para otros servicios, como los archivos etiquetados httpd_sys_content_t.

14.3. Controlar los contextos de archivos SELinux 14.3. Control de contextos de archivos SELinux Objetivos Controlar los contextos de archivos SELinux en la política del sistema para cambiar los contextos de los archivos según la configuración de la política y establecer manualmente contextos no estándar. Contexto SELinux inicial Todos los recursos, como procesos, archivos y puertos, están etiquetados con un contexto SELinux. SELinux mantiene una base de datos basada en archivos de políticas de etiquetado de archivos en el directorio /etc/selinux/targeted/contexts/files. Los archivos nuevos obtienen una etiqueta predeterminada cuando su nombre de archivo coincide con una política de etiquetado existente. Cuando el nombre de un archivo nuevo no coincide con una política de etiquetado existente, el archivo hereda la misma etiqueta que el directorio principal. Con la herencia de etiquetado, todos los archivos siempre se etiquetan cuando se crean, independientemente de si existe una política explícita para un archivo. Cuando los archivos se crean en ubicaciones predeterminadas que tienen una política de etiquetado existente, o cuando existe una política para una ubicación personalizada, los archivos nuevos se etiquetan con un contexto SELinux correcto. Sin embargo, si un archivo se crea en una ubicación inesperada sin una política de etiquetado existente, es posible que la etiqueta heredada no sea correcta para el propósito previsto del nuevo archivo. Además, copiar un archivo a una nueva ubicación puede hacer que el contexto SELinux de ese archivo cambie, donde el nuevo contexto está determinado por la política de etiquetado de la nueva ubicación, o por la herencia del directorio principal si no existe ninguna política. El contexto SELinux de un archivo se puede conservar durante la copia para conservar la etiqueta de contexto que se determinó para la ubicación original del archivo. Por ejemplo, el comando cp -p conserva todos los atributos del archivo durante la copia cuando sea posible, y el comando cp --

preserve=context command preserves only SELinux contexts.

El comando ls -Z muestra el contexto SELinux de un archivo o directorio. Nota Copiar un archivo siempre crea un inodo de archivo, y los atributos de ese inodo, incluido el contexto SELinux, deben configurarse inicialmente, como se analizó anteriormente. Sin embargo, mover un archivo normalmente no crea un inodo si el movimiento ocurre dentro del mismo sistema de archivos, sino que mueve el nombre del archivo del inodo existente a una nueva ubicación. Debido a que no es necesario inicializar los atributos del inodo existente, un archivo que se mueve con el comando mv conserva su contexto SELinux a menos que establezca un nuevo contexto en el archivo con la opción -Z. Después de copiar o mover un archivo, verifique que tenga el contexto SELinux apropiado y configúrelo correctamente si es necesario. El siguiente ejemplo demuestra cómo funciona este proceso. Cree dos archivos en el directorio /tmp.

root@host:~# touch /tmp/file1 /tmp/file2

Ambos archivos reciben el tipo de contexto user_tmp_t debido a la herencia del contexto del directorio principal.

root@host:~# ls -Z /tmp/file*
unconfined_u:object_r:user_tmp_t:s0 /tmp/file1
unconfined_u:object_r:user_tmp_t:s0 /tmp/file2

El directorio /var/www/html tiene el contexto httpd_sys_content_t.

root@host:~# ls -Zd /var/www/html/
system_u:object_r:httpd_sys_content_t:s0 /var/www/html/

Mueva un archivo del directorio /tmp al directorio /var/www/html.

root@host:~# mv /tmp/file1 /var/www/html/

Copie el otro archivo al mismo directorio.

root@host:~# cp /tmp/file2 /var/www/html/

El archivo movido conservó su etiqueta original y el archivo copiado heredó la etiqueta del directorio de destino. La función de usuario de SELinux es unconfined_u, la función de SELinux es object_r y el nivel de sensibilidad (el más bajo posible) es s0. Las configuraciones y funciones avanzadas de SELinux utilizan estos valores.

root@host:~# ls -Z /var/www/html/file*
unconfined_u:object_r:user_tmp_t:s0 /var/www/html/file1
unconfined_u:object_r:httpd_sys_content_t:s0 /var/www/html/file2

Cambiar el contexto de SELinux Puede administrar el contexto de SELinux en los archivos utilizando los comandos semanage fcontext, recoverycon y chcon. El método recomendado para cambiar el contexto de un archivo es crear una política de contexto de archivo mediante el comando semanage fcontext y luego aplicar el contexto especificado en la política al archivo mediante el comando restaurarcon. Este método garantiza que pueda volver a etiquetar el archivo en su contexto correcto con el comando restaurarcon siempre que sea necesario. La ventaja de este método es que no necesita recordar cuál se supone que es el contexto y puede corregir el contexto en un conjunto de archivos. El comando chcon cambia el contexto SELinux directamente en los archivos, sin hacer referencia a la política SELinux del sistema. El comando chcon es útil para probar y depurar; sin embargo, cambiar contextos manualmente con este método es temporal. Aunque los contextos de archivos que puede cambiar manualmente sobreviven al reinicio, es posible que se reemplacen si ejecuta el

restorecon command to relabel the contents of the file system.

Importante Cuando se produce un cambio de etiqueta del sistema SELinux, todos los archivos de un sistema se etiquetan con sus valores predeterminados de política. Cuando utiliza el comando restaurarcon en un archivo, cualquier contexto que cambie manualmente en el archivo se reemplaza si no coincide con las reglas de la política SELinux. Ajuste de la política de SELinux ajustando los objetivos booleanos Ajuste el sistema cambiando el comportamiento de la política del sistema SELinux activando y desactivando los booleanos de SELinux. SELinux Booleanos Un desarrollador de aplicaciones o servicios escribe una política específica de SELinux para definir el comportamiento permitido de la aplicación específica. Un desarrollador puede incluir un comportamiento de aplicación opcional en la política de SELinux que se puede habilitar cuando el comportamiento está permitido en un sistema específico. Los booleanos de SELinux habilitan o deshabilitan el comportamiento opcional de la política de SELinux. Con los booleanos, puedes ajustar selectivamente el comportamiento de una aplicación. Estos comportamientos opcionales son específicos de la aplicación y deben descubrirse y seleccionarse para cada aplicación de destino. Los valores booleanos específicos del servicio están documentados en la página de manual de SELinux de ese servicio. Por ejemplo, el servicio httpd del servidor web tiene su página de manual httpd(8) y una página de manual httpd_selinux(8) para documentar su política SELinux, incluidos los tipos de procesos admitidos, contextos de archivos y los comportamientos booleanos disponibles. Las páginas de manual de SELinux las proporciona el paquete selinux-policy-doc. Utilice el comando getsebool para enumerar los booleanos disponibles para las políticas específicas en este sistema y el estado booleano actual. Utilice el comando setsebool para habilitar o deshabilitar el estado de ejecución de estos comportamientos. El

setsebool -P command makes the setting persistent by writing to the policy file. Only privileged users can set

Booleanos de SELinux. En el siguiente ejemplo, utilice el comando getsebool para enumerar todos los booleanos disponibles junto con el estado:

root@host:~# getsebool -a

abrt_anon_write --> desactivado abrt_handle_event --> desactivado abrt_upload_watch_anon_write --> activado ... salida omitida... Ejemplo de política Httpd booleana La política de servicio httpd incluye el booleano httpd_enable_homedirs, que permite compartir directorios personales con el servicio httpd. Normalmente, el usuario solo puede acceder al directorio de inicio local de un usuario cuando inicia sesión en el sistema local. Alternativamente, los directorios principales se comparten y se accede a ellos mediante un protocolo de intercambio remoto de archivos, como NFS. En ambos escenarios, los directorios principales no se comparten mediante el servicio httpd de forma predeterminada y no están disponibles para el usuario a través de un navegador. En el siguiente ejemplo, enumere el estado del booleano httpd_enable_homedirs:

root@host:~# getsebool httpd_enable_homedirs

Cuando está habilitado, el servicio httpd comparte directorios de inicio que están etiquetados con el contexto del archivo user_home_dir_t. Luego, los usuarios pueden acceder y administrar los archivos de su directorio de inicio desde un navegador.

14.7. Investigación y resolución de problemas de SELinux 14.7. Investigación y resolución de problemas de SELinux Objetivos Investigar problemas que potencialmente se relacionen con SELinux mediante el uso de herramientas de análisis de registros de SELinux e interpretando sus resultados. Solucionar problemas de SELinux Cuando las aplicaciones inesperadamente no funcionan debido a denegaciones de acceso a SELinux, hay métodos y herramientas disponibles para resolver estos problemas. Es útil comenzar por comprender algunos conceptos y comportamientos fundamentales cuando SELinux está habilitado. SELinux consta de políticas específicas que definen explícitamente acciones permitidas. Una entrada de política define un proceso etiquetado y un recurso etiquetado que interactúan. La política establece el tipo de proceso y el contexto del archivo o puerto mediante etiquetas. La entrada de política define un tipo de proceso, una etiqueta de recurso y la acción explícita que se permitirá. Una acción puede ser una llamada al sistema, una función del núcleo u otra rutina de programación específica. Si no se crea ninguna entrada para una relación proceso-recurso-acción específica, entonces se deniega la acción. Cuando se rechaza una acción, el intento se registra con información de contexto. Red Hat Enterprise Linux proporciona una política SELinux específica y estable para casi todos los servicios de la distribución. Por lo tanto, es inusual tener problemas de acceso de SELinux con servicios comunes de RHEL cuando están configurados correctamente. Los problemas de acceso a SELinux ocurren cuando los servicios se implementan incorrectamente o cuando las nuevas aplicaciones tienen políticas incompletas. Considere estos conceptos de solución de problemas antes de realizar cambios amplios en la configuración de SELinux. La mayoría de las denegaciones de acceso indican que SELinux está funcionando correctamente al bloquear acciones inadecuadas. La evaluación de acciones denegadas requiere cierta familiaridad con las acciones de servicio normales y esperadas. El problema más común de SELinux es un contexto incorrecto en archivos nuevos, copiados o movidos. Los contextos de archivos se pueden arreglar cuando una política existente hace referencia a su ubicación. Las características opcionales de la política booleana están documentadas en las páginas del manual de _selinux. La implementación de funciones booleanas generalmente requiere establecer una configuración adicional que no sea SELinux. Las políticas de SELinux no reemplazan ni eluden los permisos de archivos ni las restricciones de la lista de control de acceso. Cuando falla una aplicación o servicio común y se sabe que el servicio tiene una política SELinux funcional, primero consulte la página de manual _selinux del servicio para verificar la etiqueta de tipo de contexto correcta. Vea el proceso afectado y los atributos del archivo para verificar que estén configuradas las etiquetas correctas. Monitorear violaciones de SELinux El servicio de resolución de problemas de SELinux, del paquete setroubleshoot-server, proporciona herramientas para diagnosticar problemas de SELinux. Cuando SELinux niega una acción, se registra un mensaje de Access Vector Cache (AVC) en el archivo de registro de seguridad /var/log/audit/audit.log. El servicio de resolución de problemas de SELinux monitorea los eventos AVC y envía un resumen del evento al archivo /var/log/messages. El resumen de AVC incluye un identificador único de evento (UUID). Utilice el comando sealert -l UUID para ver detalles completos del informe para el evento específico. Utilice el comando sealert -a /var/log/audit/audit.log

14.10. Resumen 14.10. Resumen En esta lección, aprendió sobre SELinux y cómo puede mejorar la seguridad de un sistema Linux. SELinux tiene tres modos: obligatorio, permisivo y deshabilitado, y puede alternar entre ellos para afectar el comportamiento de SELinux. Las políticas de SELinux definen las reglas para el control de acceso obligatorio en un sistema. Los contextos SELinux imponen políticas de seguridad. El comando chcon cambia el contexto de archivos y directorios independientemente de la política de SELinux. El comando semanage fcontext administra la política para modificar los contextos de archivos SELinux, y el comando restaurarcon aplica estos contextos a archivos y directorios. Los booleanos de SELinux habilitan o deshabilitan la configuración opcional de la política de SELinux para ajustar selectivamente el comportamiento de una aplicación. El comando getsebool ve los booleanos de SELinux y su estado actual, y el comando setsebool los habilita o deshabilita, ya sea de manera temporal o persistente. El archivo /var/log/audit/audit.log almacena eventos SELinux en formato sin formato, y el archivo /var/log/messages almacena mensajes genéricos del demonio setroubleshootd. Esos archivos de registro, junto con el comando sealert, pueden analizar eventos de SELinux y brindar sugerencias para resolver problemas.
