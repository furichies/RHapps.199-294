4.1. Usuarios y grupos de Linux 4.1. Objetivos de usuarios y grupos de Linux Describir el propósito de los usuarios y grupos en un sistema Linux. Usuarios de Linux Una cuenta de usuario proporciona límites de seguridad entre personas y programas que pueden ejecutar comandos. Los usuarios tienen nombres de usuario para identificarlos ante los usuarios humanos y para facilitar el trabajo. Internamente, el sistema distingue las cuentas de usuario por el número de identificación único, el ID de usuario (UID), que se les asigna. En la mayoría de los escenarios, si un humano usa una cuenta de usuario, el sistema asigna una contraseña secreta al usuario para demostrar que es el usuario autorizado para iniciar sesión. Las cuentas de usuario son fundamentales para la seguridad del sistema. Cada proceso (programa en ejecución) en el sistema se ejecuta como un usuario específico. Cada archivo tiene un usuario específico como propietario. Con la propiedad de los archivos, el sistema aplica el control de acceso a los usuarios de los archivos. El usuario asociado con un proceso en ejecución determina los archivos y directorios a los que puede acceder ese proceso. Tipos de usuarios en sistemas Linux Los tres tipos principales de cuentas de usuario son el superusuario, los usuarios del sistema y los usuarios normales. Superusuario La cuenta de superusuario administra el sistema. El nombre del superusuario es root y el UID de la cuenta es 0. El superusuario tiene acceso total al sistema. Usuario del sistema Las cuentas de usuario del sistema son utilizadas por procesos que proporcionan servicios de soporte. Estos procesos, o demonios, normalmente no necesitan ejecutarse como superusuario y no tienen una sesión de terminal de control. A menudo se les asignan cuentas de usuario del sistema sin privilegios para proteger sus archivos y otros recursos entre sí y de los usuarios habituales del sistema. Los usuarios no inician sesión interactivamente con una cuenta de usuario del sistema. Usuario habitual La mayoría de los usuarios tienen cuentas de usuario habituales para su trabajo diario. Al igual que los usuarios del sistema, los usuarios habituales tienen acceso limitado al sistema. Utilice el comando id para mostrar información sobre el usuario que ha iniciado sesión actualmente:

user01@host:~$ id
uid=1000(user01) gid=1000(user01) groups=1000(user01) context=unconfined_u:unconfined_r:unconfined_t:s0-
s0:c0.c1023

Comandos de ejemplo que muestran información del usuario Utilice el comando ls -l para mostrar el usuario propietario de un archivo. Utilice el comando ls -ld para mostrar al usuario propietario de un directorio, en lugar del contenido de ese directorio. En el siguiente resultado, la tercera columna muestra el nombre de usuario del propietario.

user01@host:~$ ls -l mytextfile.txt

-rw-rw-r--. 1 usuario01 usuario01 0 5 de febrero 11:10 mytextfile.txt

user01@host:~$ ls -ld Documents
drwxrwxr-x. 2 user01 user01 6 Feb  5 11:10 Documents

Utilice el comando ps para ver la información del proceso. De forma predeterminada, el comando ps solo muestra los procesos que se ejecutan con el mismo UID que el usuario actual y que están asociados con el terminal en el que se ejecutó el comando ps. Puede agregar diferentes opciones para cambiar este comportamiento. Si usa las opciones awwu juntas, entonces el comando ps enumera los procesos que son propiedad de cualquier usuario asociado con una terminal (a), proporciona más información orientada al usuario para cada proceso (u) y no trunca cada línea de salida (ww). En el siguiente resultado, la primera columna muestra el nombre de usuario del usuario propietario de cada proceso.

more details.

Cuentas de usuarios locales La salida de la mayoría de los comandos muestra a los usuarios por nombre, pero internamente, el sistema operativo utiliza UID para rastrear a los usuarios. Las asignaciones de nombres de usuario a UID se definen en bases de datos de información de cuentas. De forma predeterminada, los sistemas utilizan el archivo /etc/passwd para almacenar información sobre los usuarios locales. Cada línea del archivo /etc/passwd contiene información sobre un usuario. El archivo está dividido en siete campos separados por dos puntos. Una línea de ejemplo del archivo /etc/passwd proporciona información sobre el usuario user01:

user01@host:~$ cat /etc/passwd

...salida omitida...

user01:x:1000:1000:User One:/home/user01:/bin/bash

Considere cada parte del bloque de código, separada por dos puntos:

user01 : The username for this user.
x : The user's encrypted password was historically stored here; it is now a placeholder.

1000: el número UID de esta cuenta de usuario. 1000: el número GID para el grupo principal de esta cuenta de usuario. Los grupos se analizan más adelante en esta sección. Usuario uno: un breve comentario, descripción o el nombre real de este usuario.

/home/user01: The user's home directory, and the initial working directory when the login shell starts.
/bin/bash : The default shell program for this user that runs at login. Some accounts use the /sbin/nologin

shell para no permitir inicios de sesión interactivos con esa cuenta. Grupos de Linux Un grupo es una colección de usuarios que deben compartir el acceso a archivos y otros recursos del sistema. Al utilizar grupos, puede otorgar acceso a archivos a un conjunto de usuarios en lugar de a un solo usuario. Al igual que los usuarios, los grupos tienen nombres de grupo para un reconocimiento más sencillo. Internamente, el sistema distingue los grupos por el número de identificación único, el ID de grupo (GID), que se les asigna. La asignación de nombres de grupos a GID se define en las bases de datos de gestión de identidades de información de cuentas de grupos. De forma predeterminada, los sistemas utilizan el archivo /etc/group para almacenar información sobre grupos locales. Cada línea del archivo /etc/group contiene información sobre un grupo. Cada entrada de grupo se divide en cuatro campos separados por dos puntos. Una línea de ejemplo del archivo /etc/group proporciona información sobre el grupo group01:

user01@host:~$ cat /etc/group

...salida omitida...

group01:x:10000:user01,user02,user03

Considere cada parte del bloque de código, separada por dos puntos:

group01 : The name for this group.
x : Obsolete group password field; it is now a placeholder.

10000: el número GID para este grupo (10000).

user01,user02,user03 : A list of users that are members of this group as one of their supplementary groups.

Grupos primarios y grupos suplementarios Cada usuario tiene exactamente un grupo primario. Para los usuarios locales, este grupo aparece listado por GID en el archivo /etc/passwd. El grupo principal posee los archivos que crea el usuario. Cuando se crea un usuario normal, se crea un grupo con el mismo nombre que el usuario, que será el grupo principal del usuario. El usuario es el único miembro de este Grupo Privado de Usuarios. Este diseño de pertenencia a grupos simplifica la gestión de permisos de archivos al separar los grupos de usuarios de forma predeterminada. Los usuarios también pueden tener grupos suplementarios. La membresía en grupos suplementarios se almacena en el archivo /etc/group. Por ejemplo, si el usuario user01 tiene un grupo primario user01 y grupos suplementarios wheel y webadmin, entonces ese usuario puede leer archivos que cualquiera de esos tres grupos puede leer. El comando id puede mostrar la pertenencia a un grupo de un usuario. En el siguiente ejemplo, el usuario usuario01 tiene el grupo usuario01 como su grupo principal (gid). El elemento de grupos enumera todas las membresías de grupo para este usuario, y el usuario también tiene los grupos rueda y grupo01 como grupos suplementarios.

user01@host:~$ id
uid=1001(user01) gid=1003(user01) groups=1003(user01),10(wheel),10000(group01)
