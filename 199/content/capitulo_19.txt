# Capítulo 16. Gestión del almacenamiento con Logical Volume Manager

## 16.1. Crear volúmenes lógicos

16.1. Creación de volúmenes lógicos 16.1. Creación de volúmenes lógicos Objetivos Describir cómo funciona Logical Volume Manager y utilizar LVM para crear un volumen lógico, formatear el volumen con un sistema de archivos y montar el volumen. Descripción general del Administrador de volúmenes lógicos Utilice el sistema LVM para crear volúmenes de almacenamiento lógicos como una capa en el almacenamiento físico. Este sistema de almacenamiento proporciona mayor flexibilidad que utilizar el almacenamiento físico directamente. LVM oculta la configuración de almacenamiento de hardware del software y le permite cambiar el tamaño de los volúmenes sin detener aplicaciones ni desmontar sistemas de archivos. LVM proporciona herramientas integrales de línea de comandos para administrar el almacenamiento. Dispositivos físicos Los volúmenes lógicos utilizan dispositivos físicos para almacenar datos. Estos dispositivos pueden ser particiones de disco, discos completos, dispositivos de matriz redundante de discos independientes (RAID) o discos de redes de área de almacenamiento (SAN). Debe inicializar un dispositivo como un volumen físico LVM. Un volumen físico LVM debe utilizar todo el dispositivo físico. Volúmenes físicos (PV) LVM utiliza el dispositivo físico subyacente como volumen físico LVM. Las herramientas LVM segmentan los volúmenes físicos en extensiones físicas (PE) para formar pequeños fragmentos de datos que actúan como el bloque de almacenamiento más pequeño en un PV. Grupos de volúmenes (VG) Un grupo de volúmenes es un grupo de almacenamiento formado por uno o más PV. Es el equivalente funcional de un disco completo en almacenamiento físico. Un PV debe asignarse únicamente a un único VG. LVM establece el tamaño del PE automáticamente, aunque es posible especificarlo. Un VG puede constar de espacio no utilizado y varios volúmenes lógicos. Volúmenes lógicos (LV) Los volúmenes lógicos se crean a partir de extensiones físicas libres en un VG y se proporcionan como dispositivo de almacenamiento para aplicaciones, usuarios y sistemas operativos. Los LV son una colección de extensiones lógicas (LE), que se asignan a

extents. By default, each LE is mapped to one PE. Setting specific LV options changes this mapping; for

Por ejemplo, la duplicación hace que cada LE se asigne a dos PE. Flujo de trabajo de Logical Volume Manager La creación de almacenamiento LVM requiere la construcción de estructuras en un flujo de trabajo lógico. Determine los dispositivos físicos que se convertirán en volúmenes físicos e inicialice estos dispositivos como volúmenes físicos LVM. Cree un grupo de volúmenes a partir de varios volúmenes físicos. Cree los volúmenes lógicos a partir del espacio disponible en el grupo de volúmenes. Formatee el volumen lógico con un sistema de archivos y móntelo, actívelo como espacio de intercambio o pase el volumen sin formato a una base de datos o servidor de almacenamiento para estructuras avanzadas.

root@host:~# udevadm settle

Crear volúmenes físicos Utilice el comando pvcreate para etiquetar la partición física como un volumen físico LVM. Etiquete varios dispositivos simultáneamente utilizando nombres de dispositivos delimitados por espacios como argumentos para el comando pvcreate. Este ejemplo etiqueta los dispositivos /dev/sdb1 y /dev/sdb2 como PV que están listos para crear grupos de volúmenes.

root@host:~# pvcreate /dev/sdb1 /dev/sdb2
  Physical volume "/dev/sdb1" successfully created.
  Physical volume "/dev/sdb2" successfully created.
  Creating devices file /etc/lvm/devices/system.devices

Crear un grupo de volúmenes El comando vgcreate crea uno o más volúmenes físicos en un grupo de volúmenes. El primer argumento es el nombre de un grupo de volúmenes, seguido de uno o más volúmenes físicos para asignar a este VG. Este ejemplo crea el VG vg01 utilizando los PV /dev/sdb1 y /dev/sdb2.

root@host:~# vgcreate vg01 /dev/sdb1 /dev/sdb2
  Volume group "vg01" successfully created

Crear un volumen lógico El comando lvcreate crea un volumen lógico a partir de los PE disponibles en un grupo de volúmenes. Utilice el comando lvcreate para configurar el nombre y el tamaño de LV y el nombre de VG para contener este volumen lógico. Este ejemplo crea el LV lv01 con 300 MiB en el VG vg01.

root@host:~# lvcreate -n lv01 -L 300M vg01
  Logical volume "lv01" created.

Este comando puede fallar si el grupo de volúmenes no tiene suficientes extensiones físicas libres. El tamaño LV se redondea al siguiente valor de tamaño PE cuando el tamaño no coincide exactamente. La opción -L del comando lvcreate requiere tamaños en bytes, mebibytes (megabytes binarios) y gibibytes (gigabytes binarios), o similares. La -l minúscula requiere tamaños que se especifican como una cantidad de extensiones físicas. Los siguientes comandos son dos opciones para crear el mismo LV con el mismo tamaño:

lvcreate -n lv01 -L 128M vg01 : Create an LV of size 128 MiB, rounded to the next PE.
lvcreate -n lv01 -l 32 vg01 : Create an LV of size 32 PEs at 4 MiB each, total 128 MiB.

Cree un sistema de archivos en el volumen lógico Especifique el volumen lógico utilizando el nombre tradicional /dev/vgname/lvname o el nombre del asignador de dispositivos del kernel /dev/mapper/vgname-lvname.

16.3. Ampliación de un volumen lógico 16.3. Ampliación de un volumen lógico Objetivos Aumentar el almacenamiento disponible en un volumen lógico y ampliar su sistema de archivos o espacio de intercambio para utilizar el almacenamiento adicional. Aumente la capacidad de almacenamiento en un volumen lógico Un beneficio de utilizar volúmenes lógicos es aumentar su tamaño sin experimentar tiempo de inactividad. Agregue extensiones físicas gratuitas al LV desde el VG para ampliar la capacidad del LV y ampliar el sistema de archivos. Utilice el comando vgdisplay para confirmar que el grupo de volúmenes tiene suficiente espacio libre para la extensión LV. Utilice el comando lvextend para extender el LV:

root@host:~# lvextend -L +500M /dev/vg01/lv01
  Size of logical volume vg01/lv01 changed from 512.00 MiB (128 extents) to 1012.00 MiB (253 extents).
  Logical volume vg01/lv01 successfully resized.

Este comando aumenta el tamaño del volumen lógico lv01 en 500 MiB. El signo más (+) delante del tamaño significa

adding this value to the existing size; otherwise, without the plus sign, the value defines the final size of the LV.

16.3. Ampliación de un volumen lógico El comando resize2fs expande el sistema de archivos para ocupar el nuevo LV extendido. Puede continuar usando el sistema de archivos al cambiar el tamaño.

root@host:~# resize2fs /dev/vg01/lv01

resize2fs 1.47.1 (20 de mayo de 2024) Cambiar el tamaño del sistema de archivos en /dev/vg01/lv01 a 259072 (4k) bloques. El sistema de archivos en /dev/vg01/lv01 ahora tiene 259072 (4k) bloques de largo. El comando xfs_growfs expande un sistema de archivos XFS. Este comando normalmente toma el punto de montaje como argumento o, de lo contrario, puede usar indirectamente un nombre de dispositivo montando el dispositivo y luego especificando el punto de montaje. Por el contrario, el comando resize2fs cambia el tamaño de los sistemas de archivos ext2, ext3 o ext4 y toma el nombre del dispositivo como argumento. El comando xfs_growfs solo admite el cambio de tamaño en línea, mientras que el comando resize2fs admite el cambio de tamaño tanto en línea como fuera de línea. Aunque puede cambiar el tamaño de un sistema de archivos ext4 hacia arriba o hacia abajo, solo puede cambiar el tamaño de un sistema de archivos XFS hacia arriba. Ampliar volúmenes lógicos del espacio de intercambio Puede ampliar los LV que se utilizan como espacio de intercambio; sin embargo, el proceso difiere de expandir el sistema de archivos ext4 o XFS. Los volúmenes lógicos que se utilizan como espacio de intercambio deben estar fuera de línea para poder ampliarlos. Utilice el comando swapoff para desactivar el espacio de intercambio en el LV:

root@host:~# swapoff -v /dev/vg01/swap

swapoff /dev/vg01/swap Utilice el comando lvextend para extender el LV:

root@host:~# lvextend -L +300M /dev/vg01/swap
  Size of logical volume vg01/swap changed from 500.00 MiB (125 extents) to 800.00 MiB (200 extents).
  Logical volume vg01/swap successfully resized.

Utilice el comando mkswap para formatear el LV como espacio de intercambio:

root@host:~# mkswap /dev/vg01/swap
mkswap: /dev/vg01/swap: warning: wiping old swap signature.

Configurando swapspace versión 1, tamaño = 800 MiB (838856704 bytes)

no label, UUID=690ef204-9d59-4b3c-b145-eb8ba591ead8

Utilice el comando swapon para activar el espacio de intercambio en el LV:

root@host:~# swapon /dev/vg01/swap

Importante Tenga en cuenta los posibles problemas al realizar esta operación en un sistema en vivo. A veces, no hay suficiente espacio de memoria física disponible para liberarlo vaciando y reubicando páginas en la memoria cuando el espacio de intercambio está desactivado. En esos escenarios, puede encontrarse con errores de falta de memoria (OOM) y el sistema podría comportarse inesperadamente. Asegúrese de que el espacio de intercambio no se utilice de forma agresiva al realizar esta operación. Alternativamente, puede crear un espacio de intercambio basado en LV adicional con el tamaño objetivo, habilitarlo y luego deshabilitar el volumen anterior. Una vez que el LV anterior esté completamente deshabilitado, puede eliminar el LV para recuperar las extensiones del VG.

LVM proporciona herramientas de línea de comandos para realizar esta operación de forma segura, incluso con LV activos y montados. Ampliar el almacenamiento del grupo de volúmenes Es posible que necesite agregar más espacio en disco para ampliar un VG. Puede agregar volúmenes físicos a un VG para ampliar su tamaño disponible. root@host:~# pvcreate /dev/sdb3
  Physical volume "/dev/sdb3" successfully created.

root@host:~# vgextend vg01 /dev/sdb3
  Volume group "vg01" successfully extended

Reducir el almacenamiento del grupo de volumen Reducir el almacenamiento de un VG implica eliminar los PV no utilizados del VG. El comando pvmove mueve datos de extensiones en un PV a extensiones en otro PV con suficientes extensiones libres en el mismo VG. Puede continuar usando el LV del mismo VG al reducir el almacenamiento. Utilice el comando pvmove -Una opción para realizar una copia de seguridad automática de los metadatos del VG después de un cambio. Esta opción utiliza el comando vgcfgbackup para realizar una copia de seguridad de los metadatos automáticamente.

root@host:~# pvmove -A y /dev/sdb1
  /dev/sdb1: Moved: 2.74%
  ...output omitted...
  /dev/sdb1: Moved: 100.00%

Advertencia Antes de usar el comando pvmove, haga una copia de seguridad de los datos almacenados en todos los LV del VG. Una pérdida de energía inesperada durante la operación podría dejar el VG en un estado inconsistente, lo que podría causar una pérdida de datos en los LV. Utilice el comando vgreduce para eliminar un PV de un VG.

16.8. Resumen 16.8. Resumen En esta lección, aprendió sobre Logical Volume Manager y cómo utiliza volúmenes físicos, grupos de volúmenes y volúmenes lógicos para proporcionar espacio de almacenamiento flexible. Cada componente tiene comandos específicos para su gestión. El comando pvcreate crea los PV; el comando vgcreate crea los VG; y el comando lvcreate crea los LV. El comando vgextend agrega un PV a un VG existente y el comando lvextend aumenta el tamaño de un LV. Los comandos resize2fs y xfs_growfs cambian el tamaño del sistema de archivos en un LV después de modificar su tamaño. El comando pvmove mueve datos de un PV a otro, lo que libera espacio en el PV original y permite eliminarlo o reutilizarlo. El comando lvremove elimina los LV; el comando vgremove elimina los VG; y el comando pvremove elimina los PV.
