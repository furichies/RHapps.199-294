Configuración de nombres de host y objetivos de resolución de nombres Configure el nombre de host estático de un servidor y su resolución de nombres, y pruebe los resultados. Actualización del nombre de host del sistema El nombre de host de dominio completo (FQDN) identifica de forma única cada servidor de la red. El comando hostname muestra o modifica temporalmente el FQDN del sistema. En el siguiente ejemplo, cambia temporalmente el nombre de host host.example.com a web1.example.com:

root@host:~# hostname

host.ejemplo.com

root@host:~# hostname web1.example.com
root@host:~# hostname

web1.example.com El uso del comando hostname da como resultado un cambio temporal de nombre de host. Si reinicia el sistema, el FQDN vuelve a su definición anterior. Para establecer un nombre de host persistente, se debe especificar en el archivo /etc/hostname, que se lee cuando se inicia el sistema. Puede agregar manualmente el nombre de host requerido al archivo o puede usar el comando hostnamectl. El

hostnamectl command offers a convenient way to both modify this file and to display the system's fully qualified
hostname.

Puede usar el comando hostnamectl hostname para ver el nombre de host actual, o usar el mismo comando con un argumento para actualizar el nombre de host al nombre proporcionado. En el siguiente ejemplo, cambia persistentemente el

host.example.com hostname to db1.example.com:
root@host:~# hostnamectl hostname

host.ejemplo.com

root@host:~# hostnamectl hostname db1.example.com
root@host:~# hostnamectl hostname

db1.example.com Puede verificar que el archivo /etc/hostname esté actualizado con el nuevo nombre de host:

root@host:~# cat /etc/hostname

db1.example.com Nota En estos ejemplos, el mensaje muestra el nombre de host anterior incluso después de una actualización, porque el shell utiliza las variables de entorno que se establecieron cuando se inició por primera vez. Para ver el nuevo nombre de host reflejado en su mensaje, puede abrir una nueva sesión de terminal o actualizar manualmente las variables de entorno de su shell. En situaciones donde el archivo /etc/hostname no existe o está vacío, el sistema establece automáticamente un archivo transitorio.

Configuración de la resolución de nombres Un solucionador de código auxiliar es un cliente DNS liviano que se ejecuta en su máquina local. Su trabajo principal es recibir consultas DNS de aplicaciones y reenviar esas consultas a un servidor de nombres DNS recursivo si el solucionador auxiliar no puede resolver la consulta. El orden de resolución de nombres se configura en el archivo /etc/nsswitch.conf. De forma predeterminada, el sistema intenta resolver la consulta utilizando primero el archivo /etc/hosts.

root@host:~# cat /etc/hosts

127.0.0.1 localhost localhost.localdomain localhost4 localhost4.localdomain4 ::1 localhost localhost.localdomain localhost6 localhost6.localdomain6 172.25.254.254 Classroom.example.com Classroom 172.25.254.254 content.example.com contenido Si el archivo /etc/hosts no contiene una entrada coincidente, entonces el solucionador de código auxiliar consulta un servidor de nombres DNS para buscar

the hostname. The /etc/resolv.conf file controls how this DNS query is performed:
search : A list of domain names to append when short hostnames are looked up.
nameserver : The IP address of a name server to query. Up to three name server directives can be given to

root@host:~# nmcli con mod static-ens4 +ipv6.dns 2001:4860:4860::8888

En un sistema de doble pila, asegúrese de incluir al menos un servidor de nombres IPv4 accesible y un servidor de nombres IPv6 para mantener la conectividad durante problemas con cualquiera de las pilas de protocolos. Importante NetworkManager reescribe automáticamente el archivo /etc/resolv.conf en conexiones habilitadas para DHCP a menos que configure la opción ignore-auto-dns yes en el perfil de conexión mediante el comando nmcli.

root@host:~# nmcli con mod "static-ens3" ipv4.ignore-auto-dns yes
