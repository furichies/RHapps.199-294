Especificaciones Usted es administrador de sistemas Linux en Quasar Technologies, una empresa de servicios de TI que proporciona alojamiento administrado e infraestructura de nube a los clientes. Usted es responsable de implementar cambios críticos de seguridad y configuración para garantizar un acceso remoto seguro, un montaje adecuado del sistema de archivos y generación de informes basados ​​en la web. La empresa requiere acceso seguro y sin contraseña desde la máquina del servidor a la máquina del servidor para realizar transferencias de datos automatizadas. El usuario estudiante en la máquina del servidor debe poder iniciar sesión en la máquina del servidor a través de SSH sin ingresar una contraseña. En la máquina del servidor, genere un par de claves SSH para el usuario estudiante. No proteja la clave privada con una frase de contraseña. Envíe la clave pública del par de claves SSH recién generado al usuario estudiante en la máquina del servidor. Verifique que el usuario estudiante pueda iniciar sesión en la máquina del servidor desde la máquina del servidor sin ingresar una contraseña.





21.4. Práctica de laboratorio Configurar y administrar la seguridad del servidor Está investigando posibles problemas de permisos con el directorio /user-homes/production5 en la máquina del servidor. Ha decidido relajar SELinux para la depuración. Verifique los permisos del directorio /user-homes/production5. Configure SELinux para que se ejecute en modo permisivo de forma predeterminada. Reinicie la máquina del servidor y confirme que el modo SELinux sea permisivo. La máquina servera exporta el directorio de inicio del usuario de producción5 como exportación NFS servera:/user-homes/production5. Configure el servicio autofs para montar el recurso compartido de red en el directorio /localhome/production5 en la máquina serverb. Instale el paquete requerido para configurar el servicio autofs. Configure el servicio autofs para montar la exportación NFS servera.lab.example.com:/user-homes/production5 en el directorio /localhome/production5 de la máquina serverb. En la máquina del servidor, ajuste el booleano SELinux apropiado para que el usuario de producción5 pueda usar el directorio de inicio montado en NFS después de autenticarse con una clave SSH. Utilice redhat como contraseña del usuario de producción5. En la máquina del servidor, como usuario de producción5, genere un nuevo par de claves SSH para la autenticación. Utilice redhat como contraseña para el usuario de producción5. Transfiera la clave pública del par de claves SSH al usuario de producción5 en la máquina del servidor. Utilice redhat como contraseña para el usuario de producción5. Utilice la autenticación basada en clave pública SSH en lugar de la autenticación basada en contraseña para iniciar sesión en la máquina del servidor como usuario de producción5. Verifique que el comando falle. Ajuste el booleano SELinux use_nfs_home_dirs en la máquina del servidor para permitir que NFS use directorios de inicio. Utilice redhat como contraseña. Verifique y confirme que ahora puede utilizar la autenticación basada en clave pública SSH en lugar de la autenticación basada en contraseña para iniciar sesión en la máquina del servidor como usuario de producción5. Por razones de seguridad, debe bloquear todas las solicitudes de conexión desde la máquina del servidor a la máquina del servidor. En la máquina del servidor, ajuste la configuración del firewall para bloquear todas las solicitudes de conexión que se originen en la máquina del servidor. Utilice la dirección IPv4 del servidor (172.25.250.10) para configurar la regla del firewall. Un administrador junior configuró el servidor HTTP Apache en la máquina del servidor para escuchar las conexiones en el puerto 30080/TCP. Sin embargo, el servicio no se inicia. Se le ha pedido que investigue y solucione este problema. También se le pedirá que ajuste la configuración del firewall adecuadamente para que el puerto 30080/TCP esté abierto para conexiones entrantes. Intente reiniciar el servicio web. Inspeccione los archivos de registro apropiados para determinar el motivo de la falla del servicio, incluidas posibles violaciones de la política de SELinux. Cuando lo identifique, solucione el problema y asegúrese de que se inicie el servicio. Agregue el puerto 30080/TCP a la zona pública predeterminada para permitir conexiones entrantes.
