14.7. Investigación y resolución de problemas de SELinux 14.7. Investigación y resolución de problemas de SELinux Objetivos Investigar problemas que potencialmente se relacionen con SELinux mediante el uso de herramientas de análisis de registros de SELinux e interpretando sus resultados. Solucionar problemas de SELinux Cuando las aplicaciones inesperadamente no funcionan debido a denegaciones de acceso a SELinux, hay métodos y herramientas disponibles para resolver estos problemas. Es útil comenzar por comprender algunos conceptos y comportamientos fundamentales cuando SELinux está habilitado. SELinux consta de políticas específicas que definen explícitamente acciones permitidas. Una entrada de política define un proceso etiquetado y un recurso etiquetado que interactúan. La política establece el tipo de proceso y el contexto del archivo o puerto mediante etiquetas. La entrada de política define un tipo de proceso, una etiqueta de recurso y la acción explícita que se permitirá. Una acción puede ser una llamada al sistema, una función del núcleo u otra rutina de programación específica. Si no se crea ninguna entrada para una relación proceso-recurso-acción específica, entonces se deniega la acción. Cuando se rechaza una acción, el intento se registra con información de contexto. Red Hat Enterprise Linux proporciona una política SELinux específica y estable para casi todos los servicios de la distribución. Por lo tanto, es inusual tener problemas de acceso de SELinux con servicios comunes de RHEL cuando están configurados correctamente. Los problemas de acceso a SELinux ocurren cuando los servicios se implementan incorrectamente o cuando las nuevas aplicaciones tienen políticas incompletas. Considere estos conceptos de solución de problemas antes de realizar cambios amplios en la configuración de SELinux. La mayoría de las denegaciones de acceso indican que SELinux está funcionando correctamente al bloquear acciones inadecuadas. La evaluación de acciones denegadas requiere cierta familiaridad con las acciones de servicio normales y esperadas. El problema más común de SELinux es un contexto incorrecto en archivos nuevos, copiados o movidos. Los contextos de archivos se pueden arreglar cuando una política existente hace referencia a su ubicación. Las características opcionales de la política booleana están documentadas en las páginas del manual de _selinux. La implementación de funciones booleanas generalmente requiere establecer una configuración adicional que no sea SELinux. Las políticas de SELinux no reemplazan ni eluden los permisos de archivos ni las restricciones de la lista de control de acceso. Cuando falla una aplicación o servicio común y se sabe que el servicio tiene una política SELinux funcional, primero consulte la página de manual _selinux del servicio para verificar la etiqueta de tipo de contexto correcta. Vea el proceso afectado y los atributos del archivo para verificar que estén configuradas las etiquetas correctas. Monitorear violaciones de SELinux El servicio de resolución de problemas de SELinux, del paquete setroubleshoot-server, proporciona herramientas para diagnosticar problemas de SELinux. Cuando SELinux niega una acción, se registra un mensaje de Access Vector Cache (AVC) en el archivo de registro de seguridad /var/log/audit/audit.log. El servicio de resolución de problemas de SELinux monitorea los eventos AVC y envía un resumen del evento al archivo /var/log/messages. El resumen de AVC incluye un identificador único de evento (UUID). Utilice el comando sealert -l UUID para ver detalles completos del informe para el evento específico. Utilice el comando sealert -a /var/log/audit/audit.log

Investigación y resolución de problemas de SELinux Importante El resultado del comando sealert incluye una calificación de confianza, que indica el nivel de confianza en que el consejo proporcionado mitiga la denegación. Sin embargo, es posible que ese consejo no sea apropiado para su situación. Por ejemplo, si la denegación de AVC se debe a un archivo colocado en una ubicación incorrecta, entonces el comando sealert podría recomendar ajustar la etiqueta de contexto del archivo o crear una política para esta ubicación y acción. Aunque técnicamente es precisa, no es la solución correcta para su situación. Si la causa principal es una ubicación o un nombre de archivo incorrectos, la solución correcta es mover o cambiar el nombre del archivo y luego restaurar un contexto de archivo correcto.

root@host:~# sealert -l a0bca4b2-46a9-4252-b0cd-6de0dfcdd454

# /sbin/restorecon -v /var/www/html/mypage
