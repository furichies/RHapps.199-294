Exploración del proceso de inicio y selección de un destino de inicio Objetivos Describir cómo se inicia un sistema Red Hat Enterprise Linux, cambiar el destino de inicio predeterminado e iniciar manualmente el sistema en un destino distinto al predeterminado. Inicialización del sistema en Red Hat Enterprise Linux 10 Una vez que se enciende el sistema y se inicia el cargador de arranque, comienza el proceso de inicialización del sistema. La siguiente lista ofrece una descripción general de alto nivel del proceso de inicialización del sistema en Red Hat Enterprise Linux 10. El cargador de arranque carga el kernel y la imagen initramfs desde el disco y los coloca en la memoria. La imagen initramfs es un archivo con los módulos del kernel para todo el hardware requerido en el arranque, scripts de inicialización y más. En RHEL 10, la imagen initramfs contiene un sistema de archivos raíz de arranque con un kernel en ejecución y una unidad systemd. Puede utilizar el comando lsinitrd para inspeccionar la imagen initramfs y extraer su contenido. El cargador de arranque pasa el control al kernel, junto con las opciones especificadas en la línea de comando del kernel y la ubicación de la imagen initramfs en la memoria. El kernel inicializa todo el hardware para el cual puede encontrar un controlador en la imagen initramfs y luego ejecuta el

/sbin/init script from the initramfs image as PID 1. You can override this script by using the init= kernel

parámetro. En RHEL 10, el script /sbin/init es un enlace simbólico a la unidad systemd. La unidad systemd de la imagen initramfs ejecuta todas las unidades para el objetivo initrd.target. Esta unidad incluye el montaje del sistema de archivos raíz en el directorio /sysroot, que aparece en el archivo /etc/fstab del disco. El kernel cambia (pivota) el sistema de archivos raíz desde la imagen initramfs al sistema de archivos raíz en el directorio /sysroot. Luego, la unidad systemd se vuelve a ejecutar utilizando la copia instalada de la unidad systemd en el disco. Entonces, la unidad systemd tiene el control total del proceso de arranque. La unidad systemd busca un destino predeterminado, que está configurado en el sistema o se pasa desde la línea de comandos del kernel. Luego, la unidad systemd inicia (y detiene) las unidades para cumplir con la configuración para ese objetivo y resuelve automáticamente las dependencias entre unidades. Estos objetivos normalmente inician un inicio de sesión basado en texto o una pantalla de inicio de sesión gráfica, completando así el proceso de inicio. Selección de un objetivo systemd Un objetivo systemd es un conjunto de unidades systemd que el sistema debe comenzar para alcanzar el estado deseado. 17.3. Exploración del proceso de inicio y selección de un destino de inicio El destino de emergencia monta el sistema de archivos raíz en modo de solo lectura. En este punto, el usuario root no puede cambiar el archivo /etc/fstab hasta que la unidad se vuelva a montar en modo lectura/escritura usando el comando mount -o remount,rw /. Por el contrario, el objetivo de rescate espera a que se complete la unidad sysinit.target, de modo que se inicialice una mayor parte del sistema, como el servicio de registro o el montaje de sistemas de archivos con acceso de lectura/escritura. Los administradores pueden utilizar estos shells para solucionar problemas que impiden que el sistema se inicie como se esperaba, por ejemplo, un bucle de dependencia entre servicios o una entrada incorrecta en el archivo /etc/fstab. Después de salir de estos shells, el sistema continúa con el proceso de inicio estándar. Seleccione un destino diferente en el momento del arranque Para seleccionar un destino diferente en el momento del arranque, agregue la opción systemd.unit=target.target a la línea de comando del kernel desde el cargador de arranque. Por ejemplo, para iniciar el sistema en un shell de rescate donde puede cambiar la configuración del sistema casi sin

services running, append the following option to the kernel command line from the boot loader:
systemd.unit=rescue.target

Este cambio de configuración afecta solo a un inicio y es una herramienta útil para solucionar problemas del proceso de inicio. Para utilizar este método para seleccionar un destino diferente, siga estos pasos: Apagar y reiniciar Para apagar o reiniciar un sistema en ejecución desde la línea de comandos, puede utilizar el comando systemctl. El comando systemctl poweroff detiene todos los servicios en ejecución, desmonta todos los sistemas de archivos (o los vuelve a montar como de solo lectura cuando no se pueden desmontar) y luego apaga el sistema. El comando systemctl reboot detiene todos los servicios en ejecución, desmonta todos los sistemas de archivos y luego reinicia el sistema. También puede utilizar la versión más corta de estos comandos, poweroff y reboot, que son enlaces simbólicos al

systemctl unit equivalents.

Nota Los comandos systemctl halt y halt también están disponibles para detener el sistema. A diferencia del apagado

command, these commands do not power off the system; they bring down a system to a point where it is safe

para apagarlo manualmente. Inicie o reinicie el sistema. 1. En el menú de GRUB2, interrumpa la cuenta regresiva presionando cualquier tecla (excepto Enter, que inicia un inicio normal). 2. Mueva el cursor a la entrada del kernel para comenzar. 3. Presione E para editar la entrada actual. 4. Mueva el cursor a la línea que comienza con Linux, que es la línea de comando del kernel. 5. Agregue systemd.unit=target.target; por ejemplo, systemd.unit=emergency.target. 6. Presione Ctrl+X para iniciar con estos cambios. 7.
