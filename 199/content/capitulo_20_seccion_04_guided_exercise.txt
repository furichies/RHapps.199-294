17.5. Reparación de sistemas de archivos dañados en el momento del arranque 17.5. Reparación de sistemas de archivos dañados en el momento del arranque Objetivos Reparar sistemas de archivos que están mal configurados o dañados y que hacen que el proceso de arranque se detenga prematuramente. Problemas con el sistema de archivos Durante el proceso de arranque, la unidad systemd monta los sistemas de archivos persistentes que están definidos en el archivo /etc/fstab. Los errores en el archivo /etc/fstab o sistemas de archivos dañados pueden impedir que un sistema complete el proceso de inicio. En algunos escenarios de falla, el sistema sale del proceso de inicio y abre un shell de emergencia que requiere la contraseña del usuario root. La siguiente lista describe algunos problemas comunes de montaje del sistema de archivos al analizar el archivo /etc/fstab durante el proceso.

boot process:

Sistema de archivos dañado La unidad systemd intenta reparar el sistema de archivos. Si el problema no se puede reparar automáticamente, el sistema abre un shell de emergencia. Dispositivo de almacenamiento, UUID de dispositivo o punto de montaje inexistente. La unidad systemd agota el tiempo de espera a que el dispositivo de almacenamiento esté disponible. Si el dispositivo no responde, el sistema abre un caparazón de emergencia. Comprobación y reparación de daños en el sistema de archivos Red Hat Enterprise Linux 10 proporciona herramientas para comprobar y reparar problemas del sistema de archivos. En el caso de problemas menores que se detectan durante el arranque, estas utilidades intentan reparar el sistema de archivos automáticamente. Para los sistemas de archivos de diario, como XFS y ext4, puede que solo sea necesario reproducir el diario, lo que suele ser una operación rápida. En el caso de problemas de corrupción más graves del sistema de archivos, un administrador del sistema puede utilizar las herramientas para comprobar y reparar los sistemas de archivos manualmente. La herramienta que ayuda a mantener los sistemas de archivos en buen estado durante el arranque se conoce genéricamente como herramienta de verificación del sistema de archivos o comando fsck. Sin embargo, la herramienta que repara el sistema de archivos XFS no sigue la misma convención de nomenclatura. Aunque hay un archivo binario fsck.xfs en el sistema, su único propósito es satisfacer los requisitos de arranque y sale inmediatamente con un código de salida de 0. El comando xfs_repair puede verificar y reparar problemas con los sistemas de archivos XFS que una reparación automática no soluciona.

root@host:~# xfs_repair block-device

Para realizar operaciones de verificación y reparación en sistemas de archivos ext4, use el comando fsck.ext4, que es un enlace físico al comando e2fsck que también cubre los sistemas de archivos ext3 y ext2 heredados. Utilice la opción -p para reparar automáticamente problemas menores sin intervención del usuario.
