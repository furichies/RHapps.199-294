13.3. Interpretación y gestión de eventos Syslog La siguiente tabla enumera las prioridades estándar de Syslog en orden descendente: Tabla 19. Descripción general de las prioridades de Syslog 0 emerg El sistema no se puede utilizar 1 alerta Se debe tomar acción inmediatamente 2 crítico Condición crítica 3 err Condición de error no crítico 4 advertencia Condición de advertencia 5 aviso Evento normal pero significativo 6 información Evento informativo 7 depuración Mensaje de nivel de depuración El servicio Rsyslog El servicio rsyslog implementa syslog registro. El servicio rsyslog utiliza la función y la prioridad de los mensajes de registro para determinar cómo manejarlos. Las reglas especifican la instalación y la prioridad en el archivo /etc/rsyslog.conf y en cualquier archivo en el directorio /etc/rsyslog.d con la extensión .conf. Los paquetes de software pueden agregar reglas instalando un archivo apropiado en el directorio /etc/rsyslog.d. Cada regla de rsyslog consta de un filtro, seguido de una acción. Los filtros seleccionan un subconjunto de los mensajes de syslog mediante varios métodos. Por ejemplo, el método de filtro basado en instalaciones/prioridades indica la instalación y la prioridad de los mensajes de syslog con los que coincide la regla. Un asterisco (*) puede actuar como comodín para hacer coincidir todos los valores posibles de una instalación o prioridad. Las acciones indican cómo manejar los mensajes que coinciden con el filtro especificado. Hay muchas acciones posibles disponibles y una regla puede tener más de una acción. Por ejemplo, una acción puede indicar en qué archivo guardar el mensaje de registro. La siguiente regla en el archivo /etc/rsyslog.conf guarda los mensajes que se envían a la función authpriv de cualquier

priority to the /var/log/secure file:

authpriv.* /var/log/secure Si especifica una prioridad para el selector de una regla, todos los mensajes a esa instalación con la prioridad especificada o superior se registran en la acción asociada con la regla. Código Prioridad Descripción de prioridad





13.3. Interpretación y gestión de eventos Syslog La siguiente regla en el archivo /etc/rsyslog.conf guarda los mensajes que se envían a la función authpriv con un

priority of warning or higher (including the err, crit, alert, and emerg priorities) to the /var/log/secure file:

authpriv.warning /var/log/secure A veces, los mensajes de registro coinciden con más de una regla en el archivo rsyslog.conf. En tales casos, el mensaje se almacena en

more than one log file. The none keyword in the priority field indicates that no messages for the indicated facility are

almacenado en el archivo dado, para limitar los mensajes almacenados. En lugar de registrarse en un archivo, los mensajes de syslog también se pueden imprimir en los terminales de todos los usuarios que hayan iniciado sesión. El

rsyslog.conf file has a setting to print all the syslog messages with the emerg priority to the terminals of all

usuarios registrados. Reglas de muestra del servicio Rsyslog #### REGLAS ####

# Log all kernel messages to the console.
# Logging much else clutters up the screen.

#kern.* /dev/consola

# Log anything (except mail) of level info or higher.
# Don't log private authentication messages!

*.info;mail.none;authpriv.none;cron.none /var/log/messages

# The authpriv file has restricted access.

authpriv.* /var/log/secure

# Log all the mail messages in one place.

correo.* -/var/log/maillog

# Log cron stuff

cron.* /var/log/cron

# Everybody gets emergency messages

*.emerg :omusrmsg:*

# Save news errors of level crit and higher in a special file.

uucp,noticias.crit /var/log/spooler

# Save boot messages also to boot.log

local7.* /var/log/boot.log Nota El subsistema syslog tiene muchas más funciones que van más allá del alcance de este curso. Para explorar más, consulte la página de manual rsyslog.conf(5) y la extensa documentación HTML en /usr/share/doc/rsyslog/html/index.html que proporciona el paquete rsyslog-doc. Rotación de archivos de registro El comando logrotate es activado por una unidad de temporizador systemd y rota los archivos de registro para evitar que ocupen demasiado espacio en el directorio /var/log. Cuando se rota un archivo de registro, se le cambia el nombre con una extensión que indica la fecha de rotación.





13.3. Interpretación y gestión de eventos Syslog Por ejemplo, se cambió el nombre del archivo /var/log/messages a /var/log/messages-20250620 cuando se rotó el 2025-06-20. Después de rotar el archivo de registro anterior, se crea un nuevo archivo de registro y se notifica al servicio asociado al archivo de registro. Después de aproximadamente cuatro semanas de rotaciones de archivos de registro, el archivo de registro más antiguo se descarta para recuperar espacio en el disco. Un trabajo programado ejecuta el comando logrotate diariamente para verificar los requisitos de rotación de varios archivos de registro. La mayoría de los archivos de registro se rotan semanalmente. El comando logrotate puede rotar los archivos de registro más rápidamente, más lentamente o cuando los archivos de registro alcanzan un tamaño específico. De forma predeterminada, el comando logger envía el mensaje del tipo de usuario con la prioridad de aviso (user.notice) a menos que se especifique lo contrario con la opción -p. El comando logger es útil para probar cambios en la configuración del servicio rsyslog. Por ejemplo, los mensajes de registro que coinciden con la función local7.* o el filtro de prioridad se guardan en el archivo /var/log/boot.log, según una regla establecida en el archivo predeterminado /etc/rsyslog.conf. Por lo tanto, para enviar un mensaje al servicio rsyslog

and to record the message in the /var/log/boot.log log file, execute the following logger command:
root@host:~# logger -p local7.notice "Log entry created on host"

Nota El comando logger también puede enviar entradas de diario estructuradas al diario del sistema. Para obtener más información, consulte la documentación de la opción --journald en la página del manual de logger(1).
