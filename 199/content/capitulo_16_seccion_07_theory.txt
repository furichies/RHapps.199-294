13.7. Configuración de un diario del sistema persistente 13.7. Configuración de un diario del sistema persistente Objetivos Configurar un diario del sistema para almacenar de manera persistente los eventos de registro después de un reinicio y rotar los eventos de registro automáticamente. Almacenamiento del diario del sistema De forma predeterminada, Red Hat Enterprise Linux almacena los archivos del diario del sistema en el directorio /run/log/journal y el sistema borra el diario del sistema después de reiniciar. Puede configurar el servicio systemd-journald para mantener los archivos del diario de forma persistente, de modo que pueda revisar los eventos del diario al reiniciar el sistema. Configurar un diario persistente del sistema Configure el servicio systemd-journald de la siguiente manera para conservar los diarios del sistema de manera persistente durante un reinicio: Importante Este servicio funciona porque la configuración predeterminada del parámetro Almacenamiento en la configuración del diario está establecida en Almacenamiento=auto. Este parámetro significa que si el directorio /var/log/journal existe, entonces el almacenamiento persistente se habilita automáticamente, pero si el almacenamiento no se habilita, entonces se usa el almacenamiento volátil en el directorio /run/log/journal. Los archivos de configuración del diario se analizan con más detalle más adelante en esta sección. Revisar las entradas del diario en relación con el tiempo de inicio Aunque los diarios del sistema persisten después de un reinicio, la salida del comando journalctl incluye entradas del inicio actual del sistema así como de los inicios anteriores del sistema. Para limitar la salida a un inicio del sistema específico, use Crear el directorio /var/log/journal.

root@host:~# mkdir /var/log/journal

1. Ejecute el comando journalctl --flush para vaciar el diario actual en el almacenamiento. Si el servicio systemd-journald vacía con éxito el diario actual, entonces el servicio crea subdirectorios en el directorio /var/log/journal.

root@host:~# journalctl --flush

2. El subdirectorio del directorio /var/log/journal tiene caracteres hexadecimales en su nombre largo y contiene archivos con la extensión .journal.

root@host:~# ls /var/log/journal

4ec03abd2f7b40118b1b357f479b3112 3. Los archivos binarios .journal almacenan entradas de diario estructuradas e indexadas.

root@host:~# ls /var/log/journal/4ec03abd2f7b40118b1b357f479b3112

Rotación de diarios del sistema La ventaja de los diarios persistentes del sistema es que los datos históricos están disponibles inmediatamente en el arranque. Sin embargo, incluso con un diario persistente, el sistema no conserva todos los datos para siempre. El diario tiene un mecanismo de rotación de registros incorporado que se activa mensualmente. Además, el sistema no permite que las revistas ocupen más del 10% del sistema de archivos en el que se encuentran, ni dejen menos del 15% del sistema de archivos libre. Puede modificar estos valores tanto para el tiempo de ejecución como para los diarios persistentes en el archivo de configuración /etc/systemd/journald.conf. El proceso systemd-journald registra los límites actuales del tamaño del diario cuando se inicia. Localización de archivos de configuración del diario Los administradores del sistema normalmente configuran los ajustes del diario editando el archivo de configuración /etc/systemd/journald.conf o agregando archivos de configuración con un sufijo .conf al directorio /etc/systemd/journald.conf.d. Sin embargo, es posible que un sistema RHEL no tenga esos archivos o ese directorio. En ese caso, se verifican las configuraciones en las ubicaciones de menor prioridad que están documentadas en la página del comando man journal.conf(5), y si ninguno de esos archivos o directorios existe, entonces se utilizan las configuraciones predeterminadas compiladas. Importante A partir de RHEL 10, el archivo /etc/systemd/journald.conf no está presente en el momento de la instalación. El servicio systemd-journald lee su configuración predeterminada del archivo de configuración /usr/lib/systemd/journald.conf. Para cambiar el comportamiento del diario, no edite el archivo de configuración /usr/lib/systemd/journald.conf directamente. En su lugar, copie el archivo /usr/lib/systemd/journald.conf al directorio /etc/systemd y luego descomente y cambie la configuración apropiada en el archivo /etc/systemd/journald.conf resultante. Los ajustes de configuración en el archivo /etc/systemd/journald.conf tienen prioridad sobre los ajustes predeterminados en el archivo /usr/lib/systemd/journald.conf. Configurar la rotación automática de diarios Para configurar la rotación automática de diarios para diarios persistentes o de solo tiempo de ejecución, establezca los siguientes parámetros en el archivo /etc/systemd/journald.conf. Prefije la configuración con Sistema para diarios persistentes en el directorio /var/log/journal. Prefije la configuración con Runtime para diarios volátiles en el directorio /run/log/journal. SystemMaxUse y RuntimeMaxUse La cantidad máxima de espacio del sistema de archivos que el diario puede utilizar. Este valor es el 10 % del espacio total del sistema de archivos de forma predeterminada y tiene un límite de 4 GB.





13.7. Configuración de un diario del sistema persistente SystemMaxFileSize y RuntimeMaxFileSize El tamaño máximo de archivo de un diario antes de que rote. Este valor es un octavo del valor SystemMaxUse/RuntimeMaxUse de forma predeterminada, tiene un límite de 128 M y normalmente permite mantener siete archivos de diario rotados como historial. Si el modo compacto de diario está habilitado (el valor predeterminado), este valor tiene un límite de 4 GB. SystemKeepFree y RuntimeKeepFree El espacio libre mínimo en el sistema de archivos que debe permanecer antes de que se eliminen los diarios archivados. Al menos el 15% del espacio total del sistema de archivos siempre se mantiene libre de forma predeterminada. Este valor tiene un límite de 4 GB. Importante Sólo los archivos con los sufijos .journal o .journal~ se consideran archivos de diario. Después de editar el archivo de configuración /etc/systemd/journald.conf, reinicie el servicio systemd-journald para aplicar los cambios de configuración.

root@host:~# systemctl restart systemd-journald
