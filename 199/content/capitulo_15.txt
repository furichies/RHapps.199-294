12.1. Gestión de trabajos repetidos mediante el uso de unidades de temporizador Systemd 12.1. Gestión de trabajos repetidos mediante el uso de unidades de temporizador Systemd Objetivos Investigar, interpretar y gestionar tareas recurrentes del sistema que están programadas como unidades de temporizador systemd. Temporizador Systemd A partir de Red Hat Enterprise Linux 10, el demonio y administrador de servicios systemd reemplaza al demonio cron tradicional para la mayoría de las tareas del sistema de programación, a través de las unidades de temporizador systemd. Una unidad de temporizador systemd se define mediante un archivo de configuración de unidad con un nombre de archivo que termina en .timer. Las unidades temporizadoras activan una unidad de otro tipo, que suele ser un servicio. De forma predeterminada, el nombre de la unidad coincide con el nombre de la unidad del temporizador. Las unidades de temporizador permiten la activación basada en temporizador de otras unidades y describen cuándo ejecutar otra unidad. La unidad de temporizador systemd registra los eventos del temporizador en los diarios del sistema para facilitar la depuración. Nota Una discusión más completa sobre las unidades de temporizador systemd está fuera del alcance de esta sección. Para obtener más información, consulte la página del comando man systemd(1). Listar unidades de temporizador Para enumerar todas las unidades de temporizador que están cargadas en la memoria, utilice el comando systemctl list-units. Este comando enumera las unidades de temporizador que están activas, pendientes o fallidas. Puede utilizar la opción --all para incluir unidades de temporizador inactivas.

Gestión de trabajos repetidos mediante unidades de temporizador Systemd En este ejemplo, la opción OnCalendar=*:00/10 significa que esta unidad de temporizador activa la unidad de servicio sysstat-collect.service correspondiente cada 10 minutos. Puede especificar intervalos de tiempo más complejos. Por ejemplo, cuando la opción OnCalendar se establece en un valor de 2025-07- * 12:35,37,39:16, la unidad de temporizador activa la unidad de servicio correspondiente a las 12:35:16, 12:37:16 y 12:39:16, todos los días de julio de 2025. También puede especificar temporizadores relativos utilizando la opción OnUnitActiveSec. Por ejemplo, cuando la opción OnUnitActiveSec se establece en un valor de 15 minutos, la unidad del temporizador activa la unidad de servicio correspondiente para que se inicie 15 minutos después de la última vez que se activó la unidad de servicio. Para obtener más información sobre las opciones de la unidad del temporizador, consulte la página del comando man systemd.timer(5). Importante No modifique ningún archivo de configuración de la unidad en el directorio /usr/lib/systemd/system. La unidad systemd anula todos los cambios de configuración que se realizan en el directorio /usr/lib/systemd/system. Para modificar la configuración de una unidad systemd, copie su archivo de configuración de unidad desde el directorio /usr/lib/systemd/system al directorio /etc/systemd/system y luego modifique el archivo copiado para evitar que cualquier actualización del paquete del proveedor anule los cambios. Si existen dos archivos con el mismo nombre en los directorios /usr/lib/systemd/system y /etc/systemd/system, entonces la unidad de temporizador systemd analiza el archivo en el directorio /etc/systemd/system. Después de cambiar el archivo de configuración de la unidad del temporizador, use el comando systemctl daemon-reload para asegurarse de que la unidad del temporizador systemd cargue los cambios.

root@host:~# systemctl daemon-reload

Después de recargar la configuración del demonio systemd, use el comando systemctl para habilitar y activar inmediatamente la unidad del temporizador.

root@host:~# systemctl enable --now UNITNAME.timer

12.3. Gestión de archivos temporales 12.3. Gestión de archivos temporales Objetivos Configurar software que utilice una unidad de temporizador para programar tareas para borrar archivos temporales en el sistema o para garantizar que existan ciertos archivos o directorios. La herramienta Systemd-tempfiles La mayoría de las aplicaciones y servicios críticos utilizan archivos y directorios temporales. Algunas aplicaciones y usuarios usan el directorio /tmp para almacenar datos de trabajo transitorios, mientras que otras aplicaciones usan ubicaciones específicas de tareas, como directorios volátiles específicos de demonios y usuarios bajo el directorio /run, que existen solo en la memoria. Cuando el sistema se reinicia o se corta la energía, los sistemas de archivos basados ​​en memoria se limpian automáticamente. Normalmente, los demonios y scripts funcionan correctamente sólo cuando existen los archivos y directorios temporales esperados. Además, es necesario eliminar archivos temporales en el almacenamiento persistente para evitar problemas de espacio en disco o datos de trabajo obsoletos. Red Hat Enterprise Linux incluye la herramienta systemd-tmpfiles, que proporciona un método estructurado y configurable para administrar directorios y archivos temporales. Al iniciar el sistema, una de las primeras unidades de servicio systemd que se inicia es el servicio systemd-tmpfiles-setup. Este servicio ejecuta el comando systemd-tmpfiles, que lee las instrucciones de los archivos de configuración /usr/lib/tmpfiles.d/*.conf, /run/tmpfiles.d/*.conf y /etc/tmpfiles.d/*.conf. Estos archivos de configuración enumeran archivos y directorios que el servicio systemd-tmpfiles-setup debe crear, eliminar o proteger con permisos. Limpiar archivos temporales con un temporizador Systemd Para evitar que los sistemas de larga ejecución llenen sus discos con datos obsoletos, una unidad de temporizador systemd llamada systemd-tmpfiles-clean.timer activa a intervalos regulares la unidad systemd-tmpfiles-clean.service, que ejecuta el comando systemd-tmpfiles --clean. La configuración de una unidad de temporizador systemd tiene una sección [Temporizador] para indicar cómo iniciar el servicio con el mismo nombre que el temporizador. Este campo acepta un valor entero o macro. Por ejemplo, la macro @daily equivale al número entero 1, que ejecuta el trabajo diariamente. De manera similar, la macro @weekly equivale al número entero 7, que ejecuta el trabajo semanalmente. Retraso en minutos Define el tiempo que el demonio crond debe esperar antes de comenzar el trabajo. Identificador de trabajo Identifica el nombre exclusivo del trabajo en los mensajes de registro. Comando El comando que se ejecutará. El archivo /etc/anacrontab también contiene declaraciones de variables de entorno con la sintaxis NOMBRE=valor. La variable START_HOURS_RANGE especifica el intervalo de tiempo para que se ejecuten los trabajos. Los trabajos no comienzan fuera de este rango. Si un trabajo no se ejecuta dentro de este intervalo de tiempo en un día determinado, entonces el trabajo debe esperar hasta el día siguiente para su ejecución. 12.8. Resumen 12.8. Resumen En esta lección, aprendió sobre los métodos que se utilizan para ejecutar tareas recurrentes del sistema automáticamente. La mayoría de las tareas recurrentes del sistema ahora utilizan unidades de temporizador systemd. Las unidades temporizadoras activan otros tipos de unidades, generalmente unidades de servicio, para realizar tareas en fechas y horas o intervalos específicos. La herramienta systemd-tmpfiles proporciona una forma estructurada de administrar directorios y archivos temporales. Limpiar y mantener archivos temporales es crucial para ayudar a prevenir problemas de espacio en disco y mantener actualizados los datos de trabajo. El demonio crond monitorea los archivos crontab para ejecutar tareas recurrentes y urgentes en sistemas que siempre están en ejecución. El demonio crond también está configurado para usar el comando anacron para ayudar a garantizar que los trabajos programados no se omitan debido a que el sistema no se ejecuta en un momento específico y, en general, para ejecutar trabajos estandarizados del sistema en un cronograma preestablecido.
