## 6.1. Investigación de paquetes de software RPM

6.1. Investigación de paquetes de software RPM 6.1. Investigación de paquetes de software RPM Objetivos Explicar cómo Red Hat y otras fuentes proporcionan software como paquetes RPM e investigar los paquetes del sistema instalados. Paquetes de software RPM El Administrador de paquetes RPM, desarrollado originalmente por Red Hat, proporciona una forma estándar de empaquetar software para su distribución. Administrar software en forma de paquetes RPM es más sencillo que trabajar con software extraído a un sistema de archivos desde un archivo. Con los paquetes RPM, los administradores pueden rastrear qué archivos instala el paquete de software, qué archivos elimina el paquete de software si lo desinstala y verifica que los paquetes de soporte estén presentes cuando lo instala. La base de datos RPM local de su sistema almacena la información sobre los paquetes instalados. Red Hat proporciona todo el software para Red Hat Enterprise Linux como un paquete RPM. Los nombres de los archivos del paquete RPM constan de cuatro elementos (más el sufijo .rpm): nombre-versión-lanzamiento.arquitectura: Figura 11. Elementos del nombre del archivo RPM El nombre es una o más palabras para describir el contenido (coreutils). La versión es el número de versión del software original (9.5). La versión es el número de versión del paquete según esa versión y la establece el empaquetador, que puede no ser el desarrollador del software original (6.el10). Arch es la arquitectura del procesador en la que se compila el paquete para ejecutarse. El valor x86_64 indica que este paquete está creado para la versión de 64 bits del conjunto de instrucciones x86 (a diferencia de aarch64 para ARM de 64 bits, etc.). Los paquetes RPM suelen descargarse de repositorios. Un repositorio es una ubicación central para almacenar y mantener paquetes de software RPM. Solo necesita el nombre del paquete para instalar paquetes RPM desde los repositorios. Si existen varias versiones, el Administrador de paquetes RPM instala el paquete con el número de versión posterior. Si existen varias versiones de una sola versión, el Administrador de paquetes RPM instala el paquete con el número de versión posterior. Cada paquete RPM es un archivo con los siguientes componentes: Los archivos que el paquete instala en su sistema. Información sobre el paquete (metadatos), como el nombre, la versión, la versión y la arquitectura; un resumen y

description of the package; whether it requires other packages to be installed; licensing; a package change log;





6.1. Investigación de paquetes de software RPM y otros detalles. Scripts que pueden ejecutarse al instalar, actualizar o eliminar el paquete. Estos scripts también pueden ejecutarse al instalar, actualizar o eliminar otros paquetes. Normalmente, los proveedores de software firman digitalmente paquetes RPM con claves GNU Privacy Guard (GPG). Red Hat, por ejemplo, firma digitalmente todos los paquetes que lanza. El sistema RPM verifica la integridad del paquete confirmando que el paquete esté firmado con la clave GPG adecuada. El sistema RPM no puede instalar un paquete si la firma GPG no coincide. Actualización de software con paquetes RPM Red Hat genera un paquete RPM completo para actualizar el software. Un administrador que instala ese paquete obtiene solo la versión más reciente del paquete. No es necesario instalar una versión anterior de un paquete para parchearlo. Para actualizar el software, RPM elimina la versión anterior del paquete e instala la última versión. Las actualizaciones suelen conservar los archivos de configuración, pero el empaquetador de la nueva versión define el comportamiento exacto. Normalmente, sólo se instala una versión de un paquete a la vez. Si un paquete se crea con nombres de archivos que no entran en conflicto, es posible que instale varias versiones. El paquete del kernel es un ejemplo de instalación de múltiples versiones de paquetes. Debido a que usted prueba un nuevo kernel solo iniciando con ese kernel, el paquete está diseñado para admitir la instalación de múltiples versiones. Si el nuevo kernel no arranca, puede volver al kernel anterior. Instalación de paquetes RPM El comando rpm puede instalar paquetes individuales, pero carece de resolución de dependencias. Si intenta instalar un paquete con dependencias no satisfechas, como bibliotecas faltantes, el comando falla. El paquete requiere que todas las dependencias estén preinstaladas. Para solucionar este problema, puede utilizar DNF (Dandified YUM). Como administrador de paquetes de alto nivel, DNF amplía la funcionalidad del Administrador de paquetes RPM conectándose a repositorios de software en línea para localizar e instalar automáticamente todas las dependencias necesarias. El comando rpm de bajo nivel se puede utilizar para instalar paquetes, pero no está diseñado para funcionar con repositorios de paquetes ni para resolver dependencias de múltiples fuentes automáticamente. Con el comando dnf, puede instalar, actualizar, eliminar y obtener información sobre paquetes de software y sus dependencias. Puede obtener un historial de transacciones y trabajar con múltiples repositorios de software de Red Hat y de terceros. Los repositorios de BaseOS y Application Stream Red Hat Enterprise Linux 10 distribuye contenido a través de dos repositorios de software principales: BaseOS y Application Stream (AppStream). Tanto BaseOS como AppStream son partes necesarias de un sistema Red Hat Enterprise Linux 10. El repositorio de BaseOS proporciona el contenido principal del sistema operativo para Red Hat Enterprise Linux como paquetes RPM. Los componentes de BaseOS tienen el mismo ciclo de vida que el contenido de versiones anteriores de Red Hat Enterprise Linux. Application Stream contiene partes necesarias del sistema, así como una amplia gama de aplicaciones que anteriormente estaban disponibles como parte de Red Hat Software Collections y otros productos y programas. Cada flujo de aplicaciones tiene un ciclo de vida que es el mismo que Red Hat Enterprise Linux 10 o más corto. Las versiones anteriores de Red Hat Enterprise Linux distribuyen algunos flujos de paquetes para aplicaciones populares como módulos, como los sistemas de gestión de bases de datos. Los repositorios de BaseOS y Application Stream Red Hat Enterprise Linux 10 distribuye contenido a través de dos repositorios de software principales: BaseOS y Application Stream (AppStream). Tanto BaseOS como AppStream son partes necesarias de un sistema Red Hat Enterprise Linux 10. El repositorio de BaseOS proporciona el contenido principal del sistema operativo para Red Hat Enterprise Linux como paquetes RPM. Los componentes de BaseOS tienen el mismo ciclo de vida que el contenido de versiones anteriores de Red Hat Enterprise Linux. Application Stream contiene partes necesarias del sistema, así como una amplia gama de aplicaciones que anteriormente estaban disponibles como parte de Red Hat Software Collections y otros productos y programas. Cada flujo de aplicaciones tiene un ciclo de vida que es el mismo que Red Hat Enterprise Linux 10 o más corto. Las versiones anteriores de Red Hat Enterprise Linux distribuyen algunos flujos de paquetes para aplicaciones populares como módulos, como los sistemas de gestión de bases de datos. En RHEL 10, Red Hat ya no proporciona módulos DNF en el repositorio de AppStream. Búsqueda de software con DNF El comando de ayuda dnf muestra información de uso. Gestión de repositorios de software De forma predeterminada, los sistemas RHEL incluyen configuración para acceder a los repositorios de Red Hat. En muchas situaciones, debe configurar repositorios adicionales para acceder al software de su organización o de un tercero. Por ejemplo, Adobe proporciona parte de su software para Linux a través de repositorios DNF. En el aula de Red Hat proporcionada para este contenido, el servidor content.example.com aloja repositorios DNF. El comando dnf puede acceder a los repositorios desde un sitio web, un servidor FTP o el sistema de archivos local. Es posible que también necesite habilitar o deshabilitar repositorios para evitar conflictos al instalar paquetes de diferentes fuentes. Puede administrar los repositorios del sistema actualizando manualmente los archivos del repositorio o utilizando DNF. el dnf

repolist all command lists all available repositories and their statuses:
root@host:~# dnf repolist all

ID de repositorio Nombre de repositorio Estado rhel-10-for-x86_64-appstream-rpms RHEL 10: AppStream (RPM) habilitado rhel-10-for-x86_64-baseos-rpms RHEL 10: BaseOS (RPM) habilitado Nota Las suscripciones de Red Hat otorgan acceso a repositorios específicos. En el pasado, los administradores necesitaban adjuntar suscripciones por sistema. Simple Content Access (SCA) simplifica la forma en que los sistemas acceden a los repositorios. Con SCA, los sistemas pueden acceder a cualquier repositorio desde cualquier suscripción que compre, sin adjuntar una suscripción. Puede habilitar SCA en el Portal del cliente de Red Hat dentro de Mis suscripciones › Asignaciones de suscripción o en su servidor Red Hat Satellite. El comando dnf config-manager puede habilitar y deshabilitar repositorios. Por ejemplo, el siguiente comando

enables the rhel-10-for-x86_64-baseos-debug-rpms repository:
root@host:~# dnf config-manager --enable rhel-10-for-x86_64-baseos-debug-rpms

Configuración de repositorios DNF Puede configurar repositorios de Red Hat y de terceros actualizando manualmente un archivo de repositorio o utilizando la línea de comandos. Configuración manual Para configurar manualmente un repositorio DNF, puede crear un archivo .repo en el directorio /etc/yum.repos.d/, o

you can add a [repository] section to the /etc/dnf/dnf.conf file. Red Hat recommends using .repo files, and

reservando el archivo dnf.conf para configuraciones de repositorio adicionales. El comando dnf busca ambas ubicaciones por

default; however, the .repo files take precedence. A .repo file contains the URL of the repository, a name, and

si se deben utilizar claves GPG para verificar las firmas del paquete. Si se requieren claves GPG, el archivo .repo también incluye la URL para apuntar a la clave GPG confiable.
