17.1. Administrar el cargador de arranque y la línea de comandos del kernel 17.1. Administrar el cargador de arranque y la línea de comandos del kernel Objetivos Describir cómo el cargador de arranque selecciona y carga el sistema operativo, reinstala el cargador de arranque y modifica la configuración del cargador de arranque y los argumentos de la línea de comandos del kernel. El cargador de arranque Los sistemas informáticos modernos son combinaciones complejas de hardware y software. Pasar de un estado indefinido y apagado a un sistema en ejecución con un mensaje de inicio de sesión requiere que muchas piezas de hardware y software funcionen juntas. Cuando se enciende una computadora, carga un sistema de arranque de firmware desde un chip ROM en la placa base. En las máquinas x86 modernas, este sistema de arranque de firmware suele ser una interfaz de firmware extensible unificada (UEFI) o un sistema básico de entrada/salida (BIOS). La BIOS era más común en las máquinas fabricadas antes de 2020 y UEFI es el sistema más común presente en las placas base actuales. El trabajo del sistema de arranque del firmware es cargar un cargador de arranque desde un disco y pasar el control del proceso de arranque al cargador de arranque. Los cargadores de arranque son programas diseñados para interactuar con el sistema de arranque del firmware, configurar el sistema para el arranque y luego iniciar el kernel para continuar con la inicialización del sistema. El cargador de arranque predeterminado para Red Hat Enterprise Linux 10 es el GRand Unified Bootloader versión 2 (GRUB2). GRUB2 con UEFI En un sistema UEFI, el firmware de arranque lee la configuración de la RAM no volátil (NVRAM) para determinar qué disco y aplicación de interfaz de firmware extensible (EFI) cargar. El disco normalmente contiene una partición del sistema EFI, que generalmente está montada en el directorio /boot/efi. GRUB2 genera archivos que el sistema UEFI puede cargar. Una vez cargada la aplicación EFI del cargador de arranque GRUB2, el sistema pasa a la siguiente etapa de arranque. GRUB2 con BIOS En un sistema BIOS, el firmware de arranque lee un sector de arranque especialmente formateado en un disco para la imagen del cargador de arranque boot.img. Esta imagen del cargador de arranque carga la imagen core.img desde el espacio MBR sin particiones antes de la primera partición. La imagen core.img carga módulos adicionales que pueden inicializar sistemas de archivos y el sistema pasa a la siguiente etapa de arranque. GRUB2 genera e instala estas imágenes en el espacio MBR del disco. Etapas de inicio adicionales Después de que GRUB2 haya inicializado y cargado completamente los discos, presenta un menú de inicio al usuario.

Para que los cambios sean persistentes en futuras instancias de arranque, puede realizar esos cambios utilizando el comando grubby. Control de GRUB2 desde un sistema iniciado Puede modificar la configuración predeterminada de GRUB2 utilizando el comando grubby. Puede utilizar el comando grubby para realizar diversas tareas, como agregar o eliminar argumentos del kernel, cambiar la entrada predeterminada del menú de inicio y ver información sobre las entradas existentes del menú de inicio. Para ver información sobre una entrada existente, puede usar la opción --info del comando sucio.

user@host:~$ grubby --info 1
index=1 
kernel="/boot/vmlinuz-6.12.0-55.12.1.el10_0.x86_64" 
args="console=tty0 ... crashkernel=2G-64G:256M,64G-:512M $tuned_params" 
root="UUID=15507695-22bb-4c65-94e6-a438e095983f" 
initrd="/boot/initramfs-6.12.0-55.12.1.el10_0.x86_64.img $tuned_initrd" 
title="Red Hat Enterprise Linux (6.12.0-55.12.1.el10_0.x86_64) 10.0 (Coughlan)" 
id="b70d796f931842cb9776f658cd068435-6.12.0-55.12.1.el10_0.x86_64" 

El valor del índice es el número de entrada para la lista del menú de inicio, comenzando en 0. El valor del kernel es la ruta al kernel de Linux que carga GRUB2. El valor args es una lista de argumentos del kernel que se pasan al kernel de Linux. El valor raíz es el dispositivo de bloque en el que existen el kernel y la imagen initramfs. El valor initrd es la ruta a la imagen inicial del sistema de archivos RAM, dentro de la cual arrancan las primeras etapas de Linux. El valor del título es el nombre que se muestra para la entrada de inicio en el menú de inicio de GRUB2. El valor de identificación es un identificador único para esta entrada de inicio.





17.1. Administrar el cargador de arranque y la línea de comandos del kernel Para cambiar la entrada de arranque predeterminada, de modo que GRUB2 la elija automáticamente en el arranque, puede usar la opción del comando grubby --set-default-index.

root@host:~# grubby --set-default-index 0

The default is /boot/loader/entries/ffffffffffffffffffffffffffffffff-6.12.0-55.9.1.el10_0.x86_64.conf with index 0 and kernel /boot/vmlinuz-6.12.0-55.9.1.el10_0.x86_64 Kernel Command-line Arguments You can pass various arguments to the Linux kernel to configurar el sistema en el arranque. En algunos casos, un argumento de línea de comandos es la única forma de cambiar una configuración, como definir cómo se comporta el kernel si falla. Los argumentos de línea de comandos del kernel disponibles y el comportamiento exacto dependen de la versión del kernel de Linux que haya instalado. Para agregar un argumento de línea de comando o realizar otros cambios relacionados con el kernel, puede usar el comando sucio: opción actualizar kernel. El siguiente ejemplo agrega el argumento de línea de comandos rhgb quiet para suprimir los mensajes de inicio del kernel mediante la opción --args:

root@host:~# grubby --update-kernel /boot/vmlinuz-6.12.0-55.9.1.el10_0.x86_64 \

--args="rhgb quiet" Para eliminar el argumento de la línea de comandos, agregue el argumento rhgb quiet usando la opción --remove-args:

root@host:~# grubby --update-kernel /boot/vmlinuz-6.12.0-55.9.1.el10_0.x86_64 \

--remove-args="rhgb quiet" Referencias a las páginas man grubby(8), kernel-command-line(7), bootparam(7) y dracut.cmdline(7) Para obtener más información, consulte el capítulo Configuración de los parámetros de la línea de comandos del kernel en la guía Administración, monitoreo y actualización del kernel en
