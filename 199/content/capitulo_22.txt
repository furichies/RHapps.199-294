# Capítulo 19. Gestión de la seguridad de la red

## 19.1. Administrar firewalls de servidores

19.1. Gestión de firewalls de servidores 19.1. Gestión de firewalls de servidores Objetivos Aceptar o rechazar conexiones a servicios de red local mediante el servicio firewalld. Conceptos de arquitectura del firewall de Linux El kernel de Linux proporciona el marco netfilter para operaciones de tráfico de red, como filtrado de paquetes, traducción de direcciones de red y traducción de puertos. El marco de clasificación de paquetes nftables se basa en el marco netfilter para aplicar reglas de firewall al tráfico de la red. En Red Hat Enterprise Linux 10, el marco nftables es el núcleo del firewall del sistema. Nota El marco nftables es el sucesor de las utilidades iptables e ip6tables, entre otras. Ofrece muchas mejoras en comodidad, funciones y rendimiento con respecto a las herramientas de filtrado de paquetes anteriores. Puede convertir los archivos de configuración de iptables anteriores a sus equivalentes de nftables utilizando las utilidades iptables-translate e ip6tables-translate. El servicio de firewall El servicio firewalld es un administrador de firewall dinámico y es la interfaz recomendada para el marco de nftables. Red Hat Enterprise Linux 10 incluye el paquete firewalld. El servicio firewalld simplifica la gestión del firewall clasificando el tráfico de red en zonas. La zona asignada a un paquete de red depende de criterios como la dirección IP de origen del paquete o la interfaz de red entrante. Cada zona tiene su propia lista de puertos y servicios abiertos o cerrados. Nota Para las máquinas que cambian de red con frecuencia, el servicio NetworkManager puede configurar automáticamente la zona del firewall para una conexión. Este servicio es útil al cambiar entre redes inalámbricas domésticas, laborales o públicas. Un usuario podría querer que se pueda acceder al servicio sshd de su sistema cuando esté conectado a sus redes domésticas o corporativas, pero no cuando esté conectado a una red inalámbrica pública en la cafetería local. El servicio firewalld inspecciona la dirección de origen de cada paquete entrante al sistema. Si la dirección de origen está asignada a una zona específica, se aplican las reglas para esa zona. Si la dirección de origen no está asignada a una zona, entonces el servicio firewalld asocia el paquete con la zona para la interfaz de red entrante y se aplican las reglas para esa zona. Si la interfaz de red no está asociada con una zona, entonces el servicio firewalld envía el paquete a la zona predeterminada. La zona predeterminada no es una zona separada; usted configura una de las zonas existentes para que se asigne como zona predeterminada. Inicialmente, el servicio firewalld designa la zona pública como predeterminada y asigna la interfaz de bucle invertido a la zona confiable. La mayoría de las zonas permiten el tráfico a través del firewall si el destino local del tráfico coincide con una lista de puertos y protocolos, como 631/udp, o una configuración de servicio predefinida, como el servicio ssh. 19.3. Etiquetado de puertos SELinux 19.3. Objetivos del etiquetado de puertos de SELinux Verificar y ajustar las etiquetas de SELinux en puertos de red específicos para que los servicios de red permitidos puedan vincularse a esos puertos para escuchar las conexiones de los clientes. Etiquetado de puertos SELinux Además del contexto de archivos y el etiquetado de tipos de procesos, SELinux etiqueta los puertos de red con un contexto SELinux. SELinux controla el acceso a la red etiquetando los puertos de la red e incluyendo reglas en la política específica de un servicio. Por ejemplo, la política de destino SSH incluye el puerto 22/TCP con la etiqueta de contexto ssh_port_t. En la política HTTP, los puertos predeterminados 80/TCP y 443/TCP utilizan la etiqueta de contexto http_port_t. Cuando un proceso objetivo intenta abrir un puerto para escuchar, SELinux verifica que la política incluya entradas que permitan la vinculación del proceso y el contexto. Luego, SElinux puede impedir que un servicio fraudulento se apodere de los puertos que utilizan otros servicios de red legítimos. Administrar el etiquetado de puertos de SELinux Si un servicio intenta escuchar en un puerto no estándar y el puerto no está etiquetado con el tipo de SELinux correcto, entonces SELinux podría bloquear el intento. Puede corregir este problema cambiando el contexto SELinux en el puerto. Normalmente, la política de destino ya etiqueta todos los puertos esperados con el tipo correcto. Por ejemplo, debido a que el puerto 8008/TCP se usa a menudo para aplicaciones web, ese puerto ya está etiquetado con el contexto http_port_t, que es el tipo de puerto predeterminado para un servidor web. Los puertos individuales se pueden etiquetar con un solo contexto de puerto. Listar etiquetas de puerto Utilice el comando grep para filtrar el número de puerto.

Etiquetado de puertos SELinux Además del contexto de archivos y el etiquetado de tipos de procesos, SELinux etiqueta los puertos de red con un contexto SELinux. SELinux controla el acceso a la red etiquetando los puertos de la red e incluyendo reglas en la política específica de un servicio. Por ejemplo, la política de destino SSH incluye el puerto 22/TCP con la etiqueta de contexto ssh_port_t. En la política HTTP, los puertos predeterminados 80/TCP y 443/TCP utilizan la etiqueta de contexto http_port_t. Cuando un proceso objetivo intenta abrir un puerto para escuchar, SELinux verifica que la política incluya entradas que permitan la vinculación del proceso y el contexto. Luego, SElinux puede impedir que un servicio fraudulento se apodere de los puertos que utilizan otros servicios de red legítimos. Administrar el etiquetado de puertos de SELinux Si un servicio intenta escuchar en un puerto no estándar y el puerto no está etiquetado con el tipo de SELinux correcto, entonces SELinux podría bloquear el intento. Puede corregir este problema cambiando el contexto SELinux en el puerto. Normalmente, la política de destino ya etiqueta todos los puertos esperados con el tipo correcto. Por ejemplo, debido a que el puerto 8008/TCP se usa a menudo para aplicaciones web, ese puerto ya está etiquetado con el contexto http_port_t, que es el tipo de puerto predeterminado para un servidor web. Los puertos individuales se pueden etiquetar con un solo contexto de puerto. Listar etiquetas de puerto Utilice el comando grep para filtrar el número de puerto.

root@host:~# grep gopher /etc/services

19.6. Resumen 19.6. Resumen En esta lección, aprendió a proteger las conexiones de red a los servicios mediante el uso del firewall del sistema y a aplicar la política específica de SELinux para proteger los puertos de servicio mediante el etiquetado de puertos. El servicio firewalld es un administrador de firewall dinámico que funciona como interfaz para el marco netfilter del kernel de Linux. El servicio firewalld gestiona las reglas de tráfico de la red para el filtrado de paquetes, la traducción de direcciones de red y la traducción de puertos. El servicio firewalld clasifica el tráfico de red en zonas. El servicio firewalld se gestiona mediante la herramienta de línea de comandos firewall-cmd o mediante la interfaz gráfica de la consola web. SELinux controla el acceso a la red etiquetando los puertos de red e incluyendo reglas en la política específica de un servicio. Si un servicio intenta escuchar en un puerto no estándar y el puerto no está etiquetado con el tipo de SELinux correcto, entonces SELinux podría bloquear el intento. El comando semanage port gestiona la política de SELinux con respecto al etiquetado de puertos.
