7.3. Gestionando Aplicaciones desde Flatpak 7.3. Administrar aplicaciones desde Flatpak Objetivos Utilice Flatpak para enumerar, buscar, instalar, actualizar, eliminar y obtener información de metadatos de aplicaciones. Administrar aplicaciones con la CLI de Flatpak Al utilizar los comandos de la CLI de Flatpak, puede enumerar, buscar, instalar, actualizar, eliminar y obtener información de metadatos para las aplicaciones de Flatpak y sus dependencias de tiempo de ejecución. Puede utilizar contenido del repositorio de Red Hat y de repositorios remotos de terceros. Red Hat no admite aplicaciones ni tiempos de ejecución de repositorios remotos de terceros. Identificadores de Flatpak Las aplicaciones y los tiempos de ejecución de Flatpak utilizan identificadores únicos que siguen el formato dominio.organización.Aplicación. Este identificador de tres partes permite a una empresa, desarrollador u organización publicar muchas aplicaciones con un prefijo compartido, como com.company. El último segmento (.App) identifica el nombre de la aplicación. Puedes usar el completo o el corto.

object identifier for Flatpak operations: com.company.App or App.

En algunos escenarios, debe especificar la arquitectura o versión de la CPU, como estable o beta. Puede solicitar estas especificaciones adicionales utilizando el identificador triple de un objeto. El formato de un triple identificador es ID/arquitectura/rama, como por ejemplo org.organization.App/x86_64/stable. En Flatpak, rama se refiere a diferentes versiones del mismo objeto. Puedes dejar en blanco algunas partes del identificador triple para especificar parte del objeto. Por ejemplo, org.organization.App/x86_64// especifica solo la arquitectura y org.organization.App//stable especifica solo la rama. Consulta de repositorios remotos para objetos disponibles El comando de búsqueda flatpak enumera las aplicaciones y tiempos de ejecución coincidentes que están disponibles en todos los repositorios remotos que están habilitados en el sistema. Este comando utiliza metadatos de appstream almacenados en caché que ya se descargaron del repositorio remoto. Si los metadatos almacenados en caché tienen más de un día de antigüedad, los metadatos se actualizan automáticamente cuando se ejecuta el comando. El comando utiliza una palabra clave para encontrar una coincidencia en cualquiera de los atributos de metadatos que define el archivo XML de la aplicación: Nombre de la aplicación o tiempo de ejecución Descripción Identificador de la aplicación Palabra clave que define el desarrollador La palabra clave no distingue entre mayúsculas y minúsculas y devuelve información para las aplicaciones y tiempos de ejecución que coinciden con la consulta. El siguiente ejemplo muestra una búsqueda que utiliza la palabra clave Thunderbird para encontrar aplicaciones en Flatpak Remote.

Esta opción se recomienda para solucionar problemas. Flatpak primero verifica si los metadatos del flujo de aplicaciones almacenado en caché están actualizados, tanto en la ruta de instalación del sistema como del usuario. Después de la verificación, Flatpak detecta que los metadatos almacenados en caché para el repositorio remoto rhel son menores que los metadatos ascendentes. La antigüedad (1136) de los datos almacenados en caché es inferior a 86400 ttl (tiempo de vida), por lo que se considera que el caché está actualizado y Flatpak no descargará nuevos metadatos del repositorio. Esto hace que la búsqueda sea más rápida. Flatpak comienza su búsqueda buscando en el directorio predeterminado /var/lib/flatpak donde están instaladas todas las aplicaciones y tiempos de ejecución para todos los usuarios. Flatpak verifica el directorio de instalación local del usuario en busca de aplicaciones y tiempos de ejecución en /home/user/.local/share/. En esta ruta /home/user/.local/share/, Flatpak instala software específicamente para el usuario actual. Una vez verificados o actualizados todos los repositorios remotos, Flatpak muestra la salida coincidente en columnas categorizadas. Si no especifica el repositorio remoto para buscar y hay más de un repositorio configurado para el usuario que está ejecutando el comando, Flatpak busca todos los repositorios remotos con referencias que coincidan con el identificador en la operación. El identificador puede estar completo o abreviado (por ejemplo, org.mozilla.thunderbird o thunderbird). Flatpak resuelve automáticamente los tiempos de ejecución necesarios para la aplicación y solicita permiso para instalarla. Si otra aplicación requiere el mismo tiempo de ejecución en el futuro, utiliza el objeto descargado previamente, lo que evita la duplicación y ahorra ancho de banda. Flatpak mantiene todas las aplicaciones en entornos aislados, que requieren permisos para acceder a los recursos en el sistema host. Los recursos a los que se debe acceder con permisos específicos se detallan en este punto del proceso de instalación. Flatpak resume la operación y enumera los objetos que se instalarán, con información sobre el identificador completo, la rama, el repositorio remoto y el tamaño de descarga estimado. Después de este paso, el proceso continúa sin interrupción hasta su finalización. Instalación de objetos Flatpak desde ramas específicas Es posible que haya varias versiones de un objeto Flatpak disponibles en un repositorio remoto. Esas versiones se identifican como ramas. Las ramas se pueden designar por números de versión, como 1.1 y 1.2, o por términos que representan el ciclo de vida de la aplicación, como estable, beta o nocturno. Descripción de la opción





7.3. Administrar aplicaciones desde Flatpak Utilice el comando flatpak remote-info para verificar qué ramas están disponibles para un objeto específico. Si solo hay una rama disponible para el identificador solicitado, el comando muestra el resultado inmediatamente. Si existe más de una rama para el identificador solicitado, el comando devuelve un error y solicita más información.

user@host:~$ flatpak remote-info rhel com.redhat.Platform
error: Multiple branches available for com.redhat.Platform, you must specify one of: 

com.redhat.Platform/x86_64/el10, com.redhat.Platform/x86_64/el9, com.redhat.Platform/x86_64/el8 Si sabe a qué rama apuntar, puede especificar la versión del objeto utilizando su identificador triple.

user@host:~$ flatpak install com.redhat.Platform/x86_64/el8

...salida omitida... Actualización de objetos Flatpak Utilice el comando de actualización de Flatpak para actualizar todos sus objetos instalados a la última versión en sus respectivas ramas. Este comando actualiza todos los objetos. Para actualizar un solo objeto, agregue el identificador del objeto como argumento.

user@host:~$ flatpak update com.redhat.Platform

Buscando actualizaciones… Nada que hacer. Nota El comando de actualización de flatpak busca actualizaciones dentro de la misma rama desde la que se instaló inicialmente la aplicación. Si existe una versión posterior en una rama diferente, Flatpak no reconoce la actualización. Este

behavior is similar to branches in a Git repository: checking out a branch means that you work only on that

rama. Para evitar la actualización no deseada de ciertos objetos, use el comando de máscara Flatpak. Para enmascarar un solo objeto, agregue el identificador del objeto como argumento.

user@host:~$ flatpak mask com.redhat.Platform

Para desenmascarar un objeto, use el comando flatpak mask --remove con el identificador del objeto.

user@host:~$ flatpak mask --remove com.redhat.Platform

Desinstalación de objetos Flatpak El comando de desinstalación de Flatpak elimina los objetos Flatpak del sistema. Si tiene la intención de desinstalar un objeto de tiempo de ejecución, debe asegurarse de que ninguna aplicación instalada use el objeto como una dependencia, o debe usar la opción --force-remove para ignorar la resolución de dependencia. Cuando desinstala una aplicación, el directorio de datos de la aplicación permanece en el sistema, en el directorio ~/.var/app. Para evitar consumir espacio de almacenamiento con datos obsoletos, puede utilizar la opción --delete-data.

user@host:~$ flatpak uninstall --delete-data thunderbird

También puede utilizar el comando gnome-software para abrir la herramienta de software GNOME. El software GNOME integra paquetes DNF y Flatpak a la perfección independientemente de sus diferentes repositorios de origen. Puede explorar las aplicaciones recomendadas por categoría, eliminar componentes instalados o buscar actualizaciones. Puede buscar aplicaciones específicas utilizando la barra de búsqueda en la esquina superior izquierda. En la barra de búsqueda, escriba la palabra clave que desea buscar y la herramienta de software GNOME devolverá todos los resultados que coincidan, incluidos los paquetes DNF y los objetos Flatpak. Después de seleccionar el objeto deseado, la herramienta de software GNOME muestra los detalles del componente Flatpak. Figura 14. Detalles del objeto Flatpak Para instalar el objeto, seleccione la rama deseada (si hay más de una rama disponible para el objeto) y haga clic en Instalar. La herramienta de software GNOME resuelve todas las dependencias automáticamente y no busca más confirmación. Para desinstalar un objeto Flatpak, haga clic en Desinstalar. Referencias
