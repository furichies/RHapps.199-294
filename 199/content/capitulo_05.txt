## 2.1. Administrar archivos con herramientas de línea de comandos

2.1. Administrar archivos con herramientas de línea de comandos 2.1. Administrar archivos con herramientas de línea de comandos Objetivos Crear, copiar, mover y eliminar archivos y directorios. Gestión de archivos de línea de comandos Crear, copiar, mover y eliminar archivos y directorios son operaciones comunes para un administrador del sistema. Cuando ejecute un comando para administrar archivos, tenga en cuenta las opciones del comando. Sin opciones, algunos comandos se utilizan para interactuar con archivos. O, con el conjunto de opciones adecuado, algunos comandos pueden manipular directorios. Además, el significado de algunas opciones puede diferir entre los comandos. Creación de archivos En Linux, puede utilizar varias herramientas de línea de comandos para crear archivos. Por ejemplo, puede utilizar los comandos cat y echo para dirigir la salida a un nombre de archivo específico. O puede utilizar editores de texto de línea de comandos, como Vim y nano. En algunos casos, es posible que desee crear un archivo vacío para reservar un nombre de archivo para su uso posterior. En este escenario, puede utilizar el comando táctil. El comando táctil crea un nuevo archivo o, si el nombre del archivo existe, el comando táctil actualiza la marca de tiempo del archivo.

user@host:~$ touch mytasklist.txt
user@host:~$ ls mytasklist.txt

mytasklist.txt Creación de directorios El comando mkdir crea uno o más directorios o subdirectorios. Toma como argumento una lista de rutas a los directorios que desea crear. En el siguiente ejemplo, los archivos y directorios se organizan bajo el directorio /home/user/Documents. Utilice el

mkdir command and a space-delimited list of the directory names to create multiple directories.
user@host:~$ cd Documents
user@host:~/Documents$ mkdir ProjectX ProjectY ProjectZ
user@host:~/Documents$ ls

ProjectX ProjectY ProjectZ Si el directorio que está intentando crear ya existe, el comando mkdir falla y muestra un error. El comando mkdir también falla si no existe un directorio principal del directorio solicitado. El comando mkdir y la opción -p (principal) crean los directorios principales que faltan para el destino solicitado. En el siguiente ejemplo, el

mkdir command creates three ChapterN subdirectories with one command. The -p option creates the missing

Directorio de padres de tesis.

El subdirectorio Vigilado se crearía en ese directorio incorrecto. Copiar archivos y directorios El comando cp copia un archivo y crea un archivo en el directorio actual o en un directorio especificado diferente.

user@host:~$ cd Videos

En este escenario, el último argumento debe ser un directorio. Los archivos copiados conservan sus nombres originales en el nuevo directorio. Si existe un archivo con el mismo nombre en el directorio de destino, se sobrescribe el archivo existente. Nota De forma predeterminada, el comando cp no copia directorios; los ignora. En el siguiente ejemplo, se enumeran dos directorios como argumentos, los directorios Thesis y ProjectX. El último argumento, el directorio ProjectX, es el destino y es válido como destino. El argumento de la tesis es ignorado por el

drwxr-xr-x. 2 user user 6 Mar  7 12:37 Chapter2
drwxr-xr-x. 2 user user 6 Mar  7 12:37 Chapter3

Importante Red Hat Enterprise Linux no proporciona una forma de deshacer eliminaciones ni una "papelera" desde la cual pueda restaurar archivos retenidos para su eliminación. Una papelera es un componente de un entorno de escritorio como GNOME, pero no la utilizan los comandos que se ejecutan desde un shell. Una buena práctica es verificar su directorio de trabajo actual antes de eliminar un archivo o directorio utilizando rutas relativas.

user@host:~/Documents$ pwd

ls: cannot access 'thesis*': No such file or directory

Puede utilizar el comando rm con la opción -i para solicitar confirmación de forma interactiva antes de eliminar. Esta opción es lo opuesto al uso de la opción -f del comando rm, que fuerza la eliminación sin pedir confirmación al usuario.

2.3. Crear enlaces entre archivos 2.3. Crear vínculos entre archivos Objetivos Crear y comparar el uso de vínculos físicos y vínculos simbólicos para hacer referencia al mismo archivo. Administrar vínculos entre archivos Puede crear varios nombres de archivos que apunten al mismo archivo. Estos nombres de archivos se denominan enlaces. Puede crear dos tipos de vínculos: un vínculo físico o un vínculo simbólico (a veces llamado vínculo blando). Cada tipo de enlace es útil para diferentes casos de uso. Enlaces físicos a archivos Cada archivo comienza con un único enlace físico, desde su nombre inicial hasta los datos del sistema de archivos. Cuando crea un vínculo físico a un archivo, crea otro nombre que apunta a esos mismos datos. El nuevo enlace físico actúa exactamente como el nombre del archivo original. Una vez creado el vínculo, no podrá notar la diferencia entre el nuevo vínculo físico y el nombre original del archivo. Puede determinar si un archivo tiene varios enlaces físicos utilizando el comando ls -l. Un elemento en el resultado de este comando es el recuento de enlaces de cada archivo, que es el número de enlaces físicos que tiene el archivo. En el siguiente ejemplo, el recuento de enlaces del archivo newfile.txt es 1. Tiene exactamente una ruta absoluta, que es la ubicación /home/user/newfile.txt.

user@host:~$ pwd

/casa/usuario

user@host:~$ ls -l newfile.txt

-rw-r--r--. 1 usuario usuario 0 30 de mayo 19:19 newfile.txt Puede usar el comando ln para crear un enlace físico (otro nombre de archivo) que apunte a un archivo existente. el comando

needs at least two arguments: a path to the existing file, and the path to the hard link that you want to create.

El siguiente ejemplo crea un vínculo físico llamado newfile-hlink2.txt en el directorio /tmp para el archivo newfile.txt existente.

user@host:~$ ln newfile.txt /tmp/newfile-hlink2.txt
user@host:~$ ls -l newfile.txt /tmp/newfile-hlink2.txt

-rw-rw-r--. 2 usuario usuario 12 30 de mayo 19:19 /tmp/newfile-hlink2.txt -rw-rw-r--. 2 usuario usuario 12 30 de mayo 19:19 newfile.txt Para determinar si dos archivos están vinculados de forma física, utilice la opción -i del comando ls para enumerar el número de inodo de cada archivo. Si los archivos están en el mismo sistema de archivos y sus números de inodo son los mismos, entonces los archivos son enlaces físicos que apuntan al mismo contenido del archivo de datos. En el siguiente ejemplo, puede verificar que los archivos newfile.txt y /tmp/newfile-hlink2.txt comparten el número de inodo 8924107 en la primera columna del comando ls -il.

2.3. Creación de enlaces entre archivos Enlaces simbólicos a archivos La opción -s del comando ln crea un enlace simbólico, que también se denomina enlace suave. Un enlace simbólico no es un archivo normal. Es un tipo especial de archivo que apunta a un archivo o directorio existente. Los enlaces simbólicos tienen algunas ventajas sobre los enlaces físicos: los enlaces simbólicos pueden vincular dos archivos en diferentes sistemas de archivos. Los enlaces simbólicos pueden apuntar a un directorio o un archivo especial, además de un archivo normal. En el siguiente ejemplo, el comando ln -s crea un enlace simbólico para el archivo /home/user/newfile-link2.txt. El nombre del enlace simbólico es /tmp/newfile-symlink.txt.

user@host:~$ cat /tmp/newfile-symlink.txt

Hola mundo simbólico En el ejemplo anterior, el primer carácter de la lista larga del archivo /tmp/newfile-symlink.txt es l (la letra "l") en lugar de un guión (-). Este carácter indica que el archivo es un enlace simbólico y no un archivo normal. Cuando se elimina el archivo normal original, el enlace simbólico todavía apunta al archivo pero el destino desaparece. Un enlace simbólico que apunta a un archivo faltante se denomina enlace simbólico colgante.

user@host:~$ rm -f newfile-link2.txt
user@host:~$ ls -l /tmp/newfile-symlink.txt
lrwxrwxrwx. 1 user user 11 May 30 20:59 /tmp/newfile-symlink.txt -> /home/user/newfile-link2.txt
user@host:~$ cat /tmp/newfile-symlink.txt
cat: /tmp/newfile-symlink.txt: No such file or directory

Importante Un efecto secundario del enlace simbólico colgante en el ejemplo anterior es que si crea un archivo con el mismo nombre que el archivo eliminado (/home/user/newfile-link2.txt), el enlace simbólico ya no está "colgante" y apunta al nuevo archivo. Los enlaces físicos no funcionan de esta manera. Si elimina un vínculo físico y luego usa otras herramientas (en lugar del comando ln) para crear un archivo con el mismo nombre, entonces el nuevo archivo no está vinculado al archivo eliminado. Si utiliza el comando cd para cambiar al enlace simbólico, entonces el directorio de trabajo actual se convierte en el directorio vinculado. Si desea actualizar el directorio de trabajo actual utilizando el nombre del directorio real, puede utilizar la opción -P. Los nombres de las variables distinguen entre mayúsculas y minúsculas y no pueden comenzar con un número. Sustitución de comandos La sustitución de comandos permite que la salida de un comando reemplace el comando en sí en la línea de comando. La sustitución de comandos ocurre cuando se incluye un comando entre paréntesis y lo antecede con un signo de dólar ($). El formulario $(comando) puede anidar múltiples expansiones de comando una dentro de otra.

user@host:~/glob$ echo Today is $(date +%A).

Hoy es miércoles.

user@host:~/glob$ echo The time is $(date +%M) minutes past $(date +%l%p).

Son 26 minutos después de las 11 a.m. Nota Una forma anterior de sustitución de comandos utiliza comillas invertidas: `comando`. Aunque el shell Bash todavía acepta este formato, trate de evitarlo porque podría confundir visualmente las comillas invertidas con comillas simples y las comillas invertidas no se pueden anidar. Proteger argumentos de la expansión Muchos caracteres tienen un significado especial en el shell Bash. Para evitar expansiones de shell en partes de su línea de comando, puede citar y escapar caracteres y cadenas. La barra invertida (\) es un carácter de escape en el shell Bash. Protege al siguiente personaje de la expansión.





2.5. Coincidencia de nombres de archivos con expansiones de Shell

user@host:~/glob$ echo The value of $HOME is your home directory.

El valor de /home/user es su directorio de inicio.

user@host:~/glob$ echo The value of \$HOME is your home directory.

El valor de $HOME es su directorio de inicio. En el ejemplo anterior, con el signo de dólar protegido de la expansión, Bash lo trata como un carácter normal y no expande la variable $HOME. Para proteger cadenas de caracteres más largas, puede utilizar comillas simples (') o comillas dobles (") para encerrar cadenas. Tienen efectos ligeramente diferentes. Las comillas simples detienen todas las expansiones del shell. Las comillas dobles detienen la mayor parte de las expansiones del shell. Las comillas dobles impiden que los caracteres especiales distintos del signo de dólar ($), la barra invertida (\), la comillas invertida (`) y el signo de exclamación (!) funcionen dentro del texto citado. Las comillas dobles bloquean la expansión del nombre de ruta, pero aún permiten la sustitución de comandos y la expansión de variables.

user@host:~/glob$ myhost=$(hostname -s); echo $myhost

anfitrión

user@host:~/glob$ echo "***** hostname is ${myhost} *****"

***** el nombre de host es host ***** Utilice comillas simples para interpretar literalmente todo el texto entre comillas.

user@host:~/glob$ echo "Will variable $myhost evaluate to $(hostname -s)?"

¿El host variable se evaluará como host?

user@host:~/glob$ echo 'Will variable $myhost evaluate to $(hostname -s)?'

¿La variable $myhost se evaluará como $(hostname -s)? Importante Asegúrese de no confundir las comillas simples ( ' ) y la comilla grave de sustitución de comandos ( ` ), tanto en la pantalla como en el teclado. El uso de un carácter cuando se pretende utilizar el otro conduce a un comportamiento inesperado del shell.
