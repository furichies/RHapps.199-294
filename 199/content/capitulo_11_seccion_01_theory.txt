Sistemas de archivos y dispositivos de almacenamiento Red Hat Enterprise Linux (RHEL) utiliza el sistema de archivos de extensiones (XFS) como sistema de archivos local predeterminado. RHEL admite el sistema de archivos Extended File System (ext4) para administrar archivos locales. A partir de RHEL 10, el sistema de archivos Extensible File Allocation Table (exFAT) es compatible con el uso de medios extraíbles. Montaje de sistemas de archivos Acceda al contenido de un sistema de archivos montándolo en un directorio vacío. Este directorio se llama punto de montaje. Cuando el directorio esté montado, use el comando ls para enumerar su contenido. Muchos sistemas de archivos se montan automáticamente cuando se inicia el sistema. Un punto de montaje difiere ligeramente de una letra de unidad de Microsoft Windows, donde cada sistema de archivos es una entidad separada. Los puntos de montaje permiten que varios dispositivos de sistema de archivos estén disponibles en una única estructura de árbol. Este punto de montaje es similar a NTFS.

Uso de dispositivos de bloque Un dispositivo de bloque es un archivo que proporciona acceso de bajo nivel a dispositivos de almacenamiento. Un dispositivo de bloque que representa una unidad de disco duro o un dispositivo de estado sólido (SSD) generalmente se divide en varios dispositivos de bloque más pequeños, y una partición debe formatearse con un sistema de archivos antes de que se pueda montar su sistema de archivos. El directorio /dev almacena archivos de dispositivos de bloque, que RHEL crea automáticamente para todos los dispositivos. En los sistemas RHEL, el

first detected Serial ATA (SATA), Serial Attached SCSI (SAS), SCSI, or USB hard drive is called the /dev/sda device;
the second is the /dev/sdb device; and so on. These names represent the entire hard drive.

8.1. Identificación de sistemas de archivos y dispositivos de bloque Particiones de disco Por lo general, un dispositivo de almacenamiento se divide en varias particiones. Con las particiones, puede compartimentar un disco: las distintas particiones pueden formatearse con diferentes sistemas de archivos o usarse para otros fines. Por ejemplo, una partición puede contener directorios de inicio de usuarios, mientras que otra partición puede contener registros y datos del sistema. Incluso cuando la partición del directorio de inicio está cargada con datos, es posible que la partición del sistema aún tenga espacio disponible. Las particiones son dispositivos de bloqueo por derecho propio. Por ejemplo, en el primer almacenamiento conectado a SATA, la primera partición es el disco /dev/sda1. La segunda partición del mismo almacenamiento es el disco /dev/sda2. La tercera partición en el tercer dispositivo de almacenamiento conectado a SATA es el disco /dev/sdc3, y así sucesivamente. Los dispositivos de almacenamiento paravirtualizados tienen un sistema de nombres similar. Por ejemplo, la primera partición del primer dispositivo de almacenamiento es el disco /dev/vda1. La segunda partición del segundo dispositivo de almacenamiento es el disco /dev/vdb2, y así sucesivamente. Un dispositivo SSD conectado a NVMe nombra sus particiones de manera diferente a un dispositivo conectado a SATA. Para los dispositivos de almacenamiento NVMe, la parte nvmeX del nombre se refiere al dispositivo; la parte nY se refiere al espacio de nombres; y la parte pZ se refiere a la partición. Por ejemplo, la primera partición para el primer espacio de nombres en el primer disco es la partición /dev/nvme0n1p1. La tercera partición para el primer espacio de nombres en el segundo disco es la partición /dev/nvme1n1p3, y así sucesivamente. Las tarjetas MultiMediaCard (MMC) o Secure Digital (SD) a veces pueden tener un sistema de nombres similar al de los dispositivos SATA (/dev/sdN). En algunos casos, las tarjetas SD o MMC pueden tener nombres como /dev/mmcblk0p1, donde la parte mmcblkX del nombre se refiere al dispositivo de almacenamiento y la parte pY del nombre se refiere al número de partición de ese dispositivo. Una lista ampliada del archivo de dispositivo /dev/sda1 en la máquina host revela el tipo de archivo b, que significa bloque

device:
user@host:~$ ls -l /dev/sda1
brw-rw----. 1 root disk 8, 1 Jun 12 05:06 /dev/sda1

Volúmenes lógicos Otra forma de organizar discos y particiones es con la gestión de volúmenes lógicos (LVM). LVM agrega dispositivos de bloque en un grupo de volúmenes. El espacio en disco del grupo de volúmenes se separa en volúmenes lógicos, que son el equivalente funcional de una partición en un disco físico. El sistema LVM asigna nombres a grupos de volúmenes y volúmenes lógicos en el momento de su creación. LVM crea un directorio en el directorio /dev que coincide con el nombre del grupo y crea un enlace simbólico dentro de ese nuevo directorio con el mismo nombre que el volumen lógico. Ese archivo de volumen lógico estará entonces disponible para ser montado. Por ejemplo, cuando están presentes un grupo de volúmenes myvg y el volumen lógico mylv, la ruta completa al volumen lógico es el archivo /dev/myvg/mylv. Nota El nombre del dispositivo de volumen lógico mencionado anteriormente establece un vínculo simbólico al archivo del dispositivo que accede a él, que puede variar entre arranques. Otra forma del nombre del dispositivo de volumen lógico, que se vincula desde archivos en el directorio /dev/mapper, se utiliza a menudo para vínculos simbólicos al archivo del dispositivo. Examinar sistemas de archivos Utilice el comando df para mostrar una descripción general de los dispositivos de sistemas de archivos locales y remotos, que incluye el espacio total en disco, el espacio en disco utilizado, el espacio libre en disco y el porcentaje de todo el espacio en disco.

La opción -h informa en KiB (210), MiB (220) o GiB (230), mientras que la opción -H informa en unidades SI: KB (103), MB (106) o GB (109). Los fabricantes de discos duros suelen utilizar unidades SI cuando anuncian sus productos.
