6.1. Investigación de paquetes de software RPM 6.1. Investigación de paquetes de software RPM Objetivos Explicar cómo Red Hat y otras fuentes proporcionan software como paquetes RPM e investigar los paquetes del sistema instalados. Paquetes de software RPM El Administrador de paquetes RPM, desarrollado originalmente por Red Hat, proporciona una forma estándar de empaquetar software para su distribución. Administrar software en forma de paquetes RPM es más sencillo que trabajar con software extraído a un sistema de archivos desde un archivo. Con los paquetes RPM, los administradores pueden rastrear qué archivos instala el paquete de software, qué archivos elimina el paquete de software si lo desinstala y verifica que los paquetes de soporte estén presentes cuando lo instala. La base de datos RPM local de su sistema almacena la información sobre los paquetes instalados. Red Hat proporciona todo el software para Red Hat Enterprise Linux como un paquete RPM. Los nombres de los archivos del paquete RPM constan de cuatro elementos (más el sufijo .rpm): nombre-versión-lanzamiento.arquitectura: Figura 11. Elementos del nombre del archivo RPM El nombre es una o más palabras para describir el contenido (coreutils). La versión es el número de versión del software original (9.5). La versión es el número de versión del paquete según esa versión y la establece el empaquetador, que puede no ser el desarrollador del software original (6.el10). Arch es la arquitectura del procesador en la que se compila el paquete para ejecutarse. El valor x86_64 indica que este paquete está creado para la versión de 64 bits del conjunto de instrucciones x86 (a diferencia de aarch64 para ARM de 64 bits, etc.). Los paquetes RPM suelen descargarse de repositorios. Un repositorio es una ubicación central para almacenar y mantener paquetes de software RPM. Solo necesita el nombre del paquete para instalar paquetes RPM desde los repositorios. Si existen varias versiones, el Administrador de paquetes RPM instala el paquete con el número de versión posterior. Si existen varias versiones de una sola versión, el Administrador de paquetes RPM instala el paquete con el número de versión posterior. Cada paquete RPM es un archivo con los siguientes componentes: Los archivos que el paquete instala en su sistema. Información sobre el paquete (metadatos), como el nombre, la versión, la versión y la arquitectura; un resumen y

description of the package; whether it requires other packages to be installed; licensing; a package change log;





6.1. Investigación de paquetes de software RPM y otros detalles. Scripts que pueden ejecutarse al instalar, actualizar o eliminar el paquete. Estos scripts también pueden ejecutarse al instalar, actualizar o eliminar otros paquetes. Normalmente, los proveedores de software firman digitalmente paquetes RPM con claves GNU Privacy Guard (GPG). Red Hat, por ejemplo, firma digitalmente todos los paquetes que lanza. El sistema RPM verifica la integridad del paquete confirmando que el paquete esté firmado con la clave GPG adecuada. El sistema RPM no puede instalar un paquete si la firma GPG no coincide. Actualización de software con paquetes RPM Red Hat genera un paquete RPM completo para actualizar el software. Un administrador que instala ese paquete obtiene solo la versión más reciente del paquete. No es necesario instalar una versión anterior de un paquete para parchearlo. Para actualizar el software, RPM elimina la versión anterior del paquete e instala la última versión. Las actualizaciones suelen conservar los archivos de configuración, pero el empaquetador de la nueva versión define el comportamiento exacto. Normalmente, sólo se instala una versión de un paquete a la vez. Si un paquete se crea con nombres de archivos que no entran en conflicto, es posible que instale varias versiones. El paquete del kernel es un ejemplo de instalación de múltiples versiones de paquetes. Debido a que usted prueba un nuevo kernel solo iniciando con ese kernel, el paquete está diseñado para admitir la instalación de múltiples versiones. Si el nuevo kernel no arranca, puede volver al kernel anterior. Inspección de paquetes RPM La utilidad rpm es una herramienta de bajo nivel que puede recuperar información detallada sobre el contenido de los paquetes instalados. La herramienta también puede inspeccionar archivos en paquetes descargados antes de la instalación. Consultar la base de datos RPM sobre paquetes instalados De forma predeterminada, la herramienta obtiene información de una base de datos local de paquetes instalados. Recuperar información general sobre los paquetes instalados:

Instalación de paquetes RPM El comando rpm puede instalar paquetes individuales, pero carece de resolución de dependencias. Si intenta instalar un paquete con dependencias no satisfechas, como bibliotecas faltantes, el comando falla. El paquete requiere que todas las dependencias estén preinstaladas. Para solucionar este problema, puede utilizar DNF (Dandified YUM). Como administrador de paquetes de alto nivel, DNF amplía la funcionalidad del Administrador de paquetes RPM conectándose a repositorios de software en línea para localizar e instalar automáticamente todas las dependencias necesarias. El siguiente ejemplo utiliza el comando rpm para instalar un paquete RPM desde un directorio local que no tiene dependencias no satisfechas.
