En los sistemas x86, los dos esquemas de partición principales son Master Boot Record (MBR) y GUID Partition Table (GPT). Esquema de partición del Registro de arranque maestro (MBR) El esquema de partición del Registro de arranque maestro (MBR) es el estándar en los sistemas que ejecutan firmware del Sistema básico de entrada/salida (BIOS). Este esquema admite un máximo de cuatro particiones primarias. En los sistemas Linux, con particiones lógicas y extendidas, puede crear hasta 15 particiones. Con un tamaño de partición de 32 bits, los discos particionados con MBR pueden tener un tamaño de hasta 2 TiB. Figura 20. Partición MBR del dispositivo de almacenamiento /dev/sdb El límite de tamaño de partición y disco de 2 TiB es ahora una limitación común y restrictiva. En consecuencia, el esquema de partición MBR heredado es reemplazado por el esquema de partición GUID Partition Table (GPT). Esquema de partición de tabla de particiones GUID (GPT) Para los sistemas que ejecutan firmware de interfaz de firmware extensible unificada (UEFI), el esquema de partición GUID (GPT) es el estándar para la partición de discos y aborda las limitaciones del esquema MBR. El esquema GPT proporciona un máximo de 128 particiones. El esquema GPT asigna 64 bits para direcciones de bloques lógicos para admitir particiones y discos de hasta ocho zebibytes (ZiB) u ocho mil millones de tebibytes (TiB).

Montar sistemas de archivos manualmente Utilice el comando mount para conectar manualmente un dispositivo a una ubicación de directorio de punto de montaje. El comando de montaje requiere un dispositivo y un punto de montaje, y puede incluir opciones de montaje del sistema de archivos. root@host:~# mount /dev/sdb1 /mnt

También puede utilizar el comando mount para ver los sistemas de archivos actualmente montados, los puntos de montaje y sus opciones. Para mostrar el resultado del comando de montaje, no proporcione una barra diagonal junto a la partición.

root@host:~# mount | grep sdb1
/dev/sdb1 on /mnt type xfs (rw,relatime,seclabel,attr2,inode64,logbufs=8,logbsize=32k,noquota)

Montar sistemas de archivos de forma persistente Montar manualmente un sistema de archivos es una buena manera de verificar que se pueda acceder a un dispositivo formateado y que funcione como se esperaba. Sin embargo, cuando el servidor se reinicia, el sistema no vuelve a montar automáticamente el sistema de archivos.





15.1. Creación y administración de sistemas de archivos en particiones estándar Para configurar el sistema para que monte automáticamente el sistema de archivos durante el inicio del sistema, agregue una entrada al archivo /etc/fstab. Este archivo de configuración enumera los sistemas de archivos que se montarán en el inicio del sistema. El archivo /etc/fstab es un archivo delimitado por espacios en blanco con seis campos por línea.

root@host:~# cat /etc/fstab

UUID=a8063676-44dd-409a-b584-68be2c9f5570 / xfs defaults 0 0 UUID=7a20315d-ed8b-4e75-a5b6-24ff9e1f9838 /dbdata xfs defaults 0 0 El primer campo especifica el dispositivo. Este ejemplo utiliza un UUID para especificar el dispositivo. Los sistemas de archivos crean y almacenan el UUID en el superbloque de partición en el momento de la creación. Alternativamente, puede utilizar el archivo del dispositivo, como /dev/sdb1. El segundo campo es el punto de montaje, que es el directorio especificado donde se puede acceder al dispositivo de bloque. el monte

point must exist; if not, then create it with the mkdir command.

El tercer campo muestra el tipo de sistema de archivos, como xfs o ext4. El cuarto campo es la lista de opciones separadas por comas para aplicar al dispositivo. La opción predeterminada es un conjunto de opciones de uso común. La página del manual de mount(8) documenta las otras opciones disponibles. El quinto campo lo utiliza el comando de volcado para realizar una copia de seguridad del dispositivo. Otras aplicaciones de copia de seguridad no suelen utilizar este campo. El último campo, el campo de orden fsck, determina si se debe ejecutar el comando fsck en el inicio del sistema para verificar que los sistemas de archivos estén limpios. El valor en este campo indica el orden en el que se debe ejecutar el comando fsck. Para los sistemas de archivos XFS, establezca este campo en 0, porque XFS no utiliza el comando fsck para verificar el estado de su sistema de archivos. Para sistemas de archivos ext4, configúrelo en 1 para el sistema de archivos raíz y en 2 para los otros sistemas de archivos ext4. Al utilizar esta notación, el comando fsck procesa primero el sistema de archivos raíz y luego verifica los sistemas de archivos en discos separados al mismo tiempo y los sistemas de archivos en el mismo disco en secuencia. Nota Una entrada incorrecta en el archivo /etc/fstab podría hacer que la máquina no pueda iniciarse. Verifique que una entrada sea válida desmontando manualmente el nuevo sistema de archivos y luego usando el comando mount para leer el archivo /etc/fstab y vuelva a montar el sistema de archivos con las opciones de montaje de esa entrada. Si el comando de montaje devuelve un error, corríjalo antes de reiniciar la máquina. Alternativamente, use la opción --verify del comando findmnt para analizar el archivo /etc/fstab para determinar la usabilidad de la partición. Cuando agregue o elimine una entrada en el archivo /etc/fstab, ejecute el comando systemctl daemon-reload o reinicie el servidor para asegurarse de que el demonio systemd cargue y utilice la nueva configuración.

root@host:~# systemctl daemon-reload

Red Hat recomienda el uso de UUID para montar sistemas de archivos de forma persistente. Los nombres de los dispositivos de bloque pueden cambiar en ciertos escenarios, como si un proveedor de nube cambia la capa de almacenamiento subyacente de una máquina virtual o si los discos se detectan en un orden diferente en el inicio del sistema. El nombre del archivo del dispositivo de bloque puede cambiar, pero el UUID permanece constante en el superbloque del sistema de archivos. Utilice la opción --fs del comando lsblk para escanear los dispositivos de bloque que están conectados a una máquina y recuperar los UUID del sistema de archivos.
