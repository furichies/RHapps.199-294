19.1. Gestión de firewalls de servidores 19.1. Gestión de firewalls de servidores Objetivos Aceptar o rechazar conexiones a servicios de red local mediante el servicio firewalld. Conceptos de arquitectura del firewall de Linux El kernel de Linux proporciona el marco netfilter para operaciones de tráfico de red, como filtrado de paquetes, traducción de direcciones de red y traducción de puertos. El marco de clasificación de paquetes nftables se basa en el marco netfilter para aplicar reglas de firewall al tráfico de la red. En Red Hat Enterprise Linux 10, el marco nftables es el núcleo del firewall del sistema. Nota El marco nftables es el sucesor de las utilidades iptables e ip6tables, entre otras. Ofrece muchas mejoras en comodidad, funciones y rendimiento con respecto a las herramientas de filtrado de paquetes anteriores. Puede convertir los archivos de configuración de iptables anteriores a sus equivalentes de nftables utilizando las utilidades iptables-translate e ip6tables-translate. El servicio de firewall El servicio firewalld es un administrador de firewall dinámico y es la interfaz recomendada para el marco de nftables. Red Hat Enterprise Linux 10 incluye el paquete firewalld. El servicio firewalld simplifica la gestión del firewall clasificando el tráfico de red en zonas. La zona asignada a un paquete de red depende de criterios como la dirección IP de origen del paquete o la interfaz de red entrante. Cada zona tiene su propia lista de puertos y servicios abiertos o cerrados. Nota Para las máquinas que cambian de red con frecuencia, el servicio NetworkManager puede configurar automáticamente la zona del firewall para una conexión. Este servicio es útil al cambiar entre redes inalámbricas domésticas, laborales o públicas. Un usuario podría querer que se pueda acceder al servicio sshd de su sistema cuando esté conectado a sus redes domésticas o corporativas, pero no cuando esté conectado a una red inalámbrica pública en la cafetería local. El servicio firewalld inspecciona la dirección de origen de cada paquete entrante al sistema. Si la dirección de origen está asignada a una zona específica, se aplican las reglas para esa zona. Si la dirección de origen no está asignada a una zona, entonces el servicio firewalld asocia el paquete con la zona para la interfaz de red entrante y se aplican las reglas para esa zona. Si la interfaz de red no está asociada con una zona, entonces el servicio firewalld envía el paquete a la zona predeterminada. La zona predeterminada no es una zona separada; usted configura una de las zonas existentes para que se asigne como zona predeterminada. Inicialmente, el servicio firewalld designa la zona pública como predeterminada y asigna la interfaz de bucle invertido a la zona confiable. La mayoría de las zonas permiten el tráfico a través del firewall si el destino local del tráfico coincide con una lista de puertos y protocolos, como 631/udp, o una configuración de servicio predefinida, como el servicio ssh. 19.1. Administrar firewalls de servidores

root@host:~# firewall-cmd --set-default-zone=dmz

Asigne todo el tráfico de la red 192.168.0.0/24 a la zona interna:

root@host:~# firewall-cmd --permanent --zone=internal --add-source=192.168.0.0/24

Abra los puertos de red para el servicio mysql en la zona interna:

root@host:~# firewall-cmd --permanent --zone=internal --add-service=mysql

Actualice los cambios en el demonio firewalld:

root@host:~# firewall-cmd --reload

Como otro ejemplo, para agregar todo el tráfico entrante desde la dirección IPv4 única 172.25.25.11 a la zona pública,

use the following commands:
root@host:~# firewall-cmd --permanent --zone=public --add-source=172.25.25.11/32

Actualice los cambios en el demonio firewalld:

root@host:~# firewall-cmd --reload
