# Capítulo 11. Gestión de la configuración de red

## 11.1. Configurar redes desde la línea de comandos

11.1. Configuración de redes desde la línea de comandos 11.1. Configuración de redes desde la línea de comandos Objetivos Administrar la configuración de red y los dispositivos desde la línea de comandos mediante el comando nmcli. Administrar conexiones y dispositivos de red En los sistemas RHEL, se utiliza el servicio NetworkManager para monitorear y administrar la configuración de red. El servicio NetworkManager, por ejemplo, proporciona el estado de la red y de la conexión VPN que se muestra en el menú del sistema del entorno gráfico GNOME. El servicio NetworkManager gestiona dispositivos y conexiones de red. Un dispositivo es cualquier interfaz de red física o virtual que maneja el tráfico de red. Una conexión (también conocida como perfil de red) tiene ajustes de configuración relacionados para un único dispositivo de red. Cada conexión debe tener un nombre o ID único, que puede coincidir con el nombre del dispositivo que configura. Los archivos de configuración del servicio se almacenan en el directorio /etc/NetworkManager/system-connections/. Un solo dispositivo puede tener múltiples perfiles de conexión y el usuario puede alternar entre ellos, pero solo puede haber una conexión activa a la vez para el mismo dispositivo. Por ejemplo, puede configurar un dispositivo inalámbrico portátil para usar una dirección IP fija en un lugar de trabajo y usar una segunda conexión con una dirección automatizada para su hogar. Importante En Red Hat Enterprise Linux 10, se elimina por completo la compatibilidad con los archivos de configuración ifcfg y el directorio /etc/sysconfig/network-scripts/. NetworkManager ahora utiliza un formato de archivo de claves estilo INI, que es una estructura de par clave-valor para organizar las propiedades. NetworkManager almacena perfiles de red en el directorio /etc/NetworkManager/system-connections/. Visualización de información de red Utilice la utilidad nmcli para crear y editar archivos de conexión desde la línea de comandos. El estado del dispositivo nmcli

command displays the status of all network devices:
root@host:~# nmcli dev status

TIPO DE DISPOSITIVO ESTADO CONEXIÓN ens3 ethernet conectado ethernet-ens3 lo bucle invertido conectado (externamente) lo En la salida del comando anterior, la interfaz de bucle invertido está marcada como externa, lo que significa que NetworkManager no administra ese dispositivo. Nota El comando nmcli acepta abreviaturas para sus opciones y argumentos. Por ejemplo, puedes abreviar

nmcli device disconnect as nmcli dev dis, and abbreviate nmcli connection modify as nmcli

mod. La abreviatura puede ser tan corta como una sola letra, siempre que utilice suficientes caracteres para identificar de forma única el objeto a gestionar.

El siguiente ejemplo crea una conexión enp9s0 del tipo ethernet para la interfaz de red enp9s0 con una configuración de red IPv4 estática. Este comando configura la dirección IP 192.168.0.5 con un prefijo de red de /24 y una puerta de enlace de red de 192.168.0.254. El comando nmcli connect add falla si el nombre de la conexión que intenta agregar ya existe.

root@host:~# nmcli con add con-name enp9s0 type ethernet ifname enp9s0 \

command configures the 2001:db8:0:1::c000:207 IPv6 address with the /64 network prefix and the

Actualización de la configuración de conexión de red Las conexiones del servicio NetworkManager tienen dos tipos de configuración. Las propiedades de conexión estática las configura el administrador y se almacenan en los archivos de configuración /etc/NetworkManager/system-connections/*.nmconnection. Las propiedades de conexión dinámica se solicitan desde un servidor DHCP y no se almacenan de forma persistente. Para enumerar la configuración actual de una conexión, utilice el comando nmcli connect show. Las configuraciones en minúsculas son propiedades estáticas que el administrador puede cambiar. Las configuraciones en mayúsculas son configuraciones que están activas solo durante el tiempo de ejecución. La opción -p está disponible para imprimir la salida de forma bonita y hacerla más legible.

root@host:~# nmcli -p con show enp8s0

Estos cambios se guardan en el archivo /etc/NetworkManager/system-connections/name.nmconnection. Consulte la página de manual de nm-settings(5) para conocer las configuraciones disponibles. Utilice el siguiente comando para actualizar la conexión enp8s0 y configurar la dirección IPv4 192.0.2.2/24 y la puerta de enlace predeterminada 192.0.2.254. Utilice el parámetro de conexión.autoconnect del comando nmcli para habilitar o deshabilitar automáticamente la conexión en el inicio del sistema.

Importante Para cambiar la configuración de una conexión DHCP para que sea estática, actualice la configuración ipv4.method de auto o dhcp a manual. Para una conexión IPv6, actualice la configuración ipv6.method. Si el método no está configurado correctamente, entonces la conexión podría bloquearse o estar incompleta cuando se active, o podría obtener una dirección de DHCP o SLAAC además de la dirección estática configurada. Algunas configuraciones pueden tener múltiples valores. Se puede agregar un valor específico a la lista o eliminarlo de la configuración de conexión agregando un símbolo más (+) o menos (-) al comienzo del nombre de la configuración. Si no se incluye un más o un menos, entonces el valor especificado reemplaza la lista actual de la configuración. El siguiente ejemplo agrega el servidor DNS 2.2.2.2 a la conexión enp8s0:

root@host:~# nmcli con mod enp8s0 +ipv4.dns 2.2.2.2

Actualización de la configuración de conexión mediante archivos de configuración También puede modificar los perfiles de red editando el archivo de configuración de la conexión en el directorio /etc/NetworkManager/system-connections/. Mientras que los comandos nmcli se comunican directamente con NetworkManager para implementar modificaciones de inmediato, las ediciones del archivo de conexión no se implementan hasta que NetworkManager vuelve a cargar el archivo de configuración. Con la edición manual, puede crear configuraciones complejas en pasos y luego cargar la configuración final cuando esté lista. Después de actualizar manualmente el archivo de configuración de la conexión, use el comando nmcli para recargar todos los perfiles de conexión:

root@host:~# nmcli con reload

El siguiente ejemplo vuelve a leer sólo el perfil de conexión enp8s0 en /etc/NetworkManager/system-

connections/enp8s0.nmconnection:
root@host:~# nmcli con reload enp8s0

Eliminación de una conexión de red El comando de eliminación de conexión nmcli elimina una conexión del sistema. Este comando desconecta el dispositivo y elimina el archivo de configuración de la conexión.

root@host:~# nmcli con del enp8s0

11.3. Edición de archivos de configuración de red 11.3. Edición de archivos de configuración de red Objetivos Modificar la configuración de red editando archivos de configuración. Archivos de configuración de conexión Como alternativa al uso del comando nmcli, puede configurar redes editando directamente los archivos de configuración de conexión. Aunque el comando nmcli es el método preferido para la gestión de perfiles, puede crear o modificar manualmente estos archivos de configuración. Esta alternativa es especialmente útil cuando planeas utilizar archivos de configuración iguales o similares para varios servidores. Los perfiles de conexión de NetworkManager se almacenan en el directorio /etc/NetworkManager/system-connections/. Estos archivos utilizan la sintaxis de archivo de claves, que reemplaza el formato ifcfg obsoleto. Cuando agrega o modifica conexiones mediante el comando nmcli, esos cambios también se almacenan persistentemente en este directorio como archivos que terminan con la extensión .nmconnection. Después de cualquier edición manual, debe utilizar el comando nmcli con reload para recargar los archivos de configuración e informar a NetworkManager de los cambios. Para aplicar los cambios, debe activar manualmente la conexión mediante el comando nmcli con up. Sintaxis de archivos de claves NetworkManager emplea una sintaxis de archivos de claves de estilo INI para sus perfiles de conexión de red. Los elementos de configuración están estructurados en secciones (grupos), y cada configuración se representa como un par clave-valor dentro de estos grupos. Esta sintaxis de configuración ofrece beneficios de legibilidad, como especificar direcciones IP como 192.168.0.1/24 en lugar de matrices de enteros menos intuitivas. 11.8. Resumen 11.8. Resumen En esta lección, aprendió a administrar la configuración de red mediante el demonio NetworkManager y a administrar dispositivos y conexiones de red mediante la interfaz de línea de comandos de NetworkManager (nmcli). RHEL 10 utiliza un formato de archivo de claves estilo INI para almacenar perfiles de red en el directorio /etc/NetworkManager/system-connections. Se elimina por completo la compatibilidad con el formato de archivo ifcfg anterior para conexiones de red. Puede identificar de forma exclusiva servidores con un FQDN, que puede administrar mediante el comando hostnamectl. También aprendió a configurar y probar la resolución de nombres local.
