9.4. Ejercicio guiado Gestionar procesos con control de trabajos 9.4. Ejercicio guiado Administrar procesos con control de trabajos Controle los procesos en primer plano y en segundo plano en el mismo terminal mediante el control de trabajos. Resultados Utilice el control de trabajos para suspender y reiniciar procesos de usuario. Requisitos previos Como usuario estudiante en la máquina de la estación de trabajo, ejecute el siguiente comando de laboratorio para preparar su entorno para este ejercicio y garantizar que todos los recursos necesarios estén disponibles.

student@workstation:~$ lab start processes-control

Instrucciones En la máquina de la estación de trabajo, abra dos ventanas de terminal una al lado de la otra. En esta actividad, estas dos terminales se denominan izquierda y derecha. En cada terminal, inicie sesión en el servidor como usuario estudiante.

student@workstation:~$ ssh student@servera

[estudiante@servera ~]$ 1. En el shell del terminal izquierdo, cree el directorio /home/student/bin. Cree un script de shell llamado control en el directorio /home/student/bin. Cambie los permisos del script para que sea ejecutable. 2. Cree el directorio /home/student/bin.

[student@servera ~]$ mkdir /home/student/bin

2.1. Cree un archivo llamado control en el directorio /home/student/bin con el siguiente contenido: #!/bin/bash

while true; do
  echo -n "$@ " >> ~/control_outfile
  sleep 1

done El script de control agrega argumentos de línea de comandos al archivo ~/control_outfile una vez por segundo. El script se ejecuta hasta que finaliza el proceso. 2.2. Haga que el archivo de control sea ejecutable.

[student@servera ~]$ chmod +x /home/student/bin/control

2.3. Ejecute el script de control. El script agrega continuamente la palabra "técnico" y un espacio al archivo ~/control_outfile en intervalos de un segundo. 3.

9.5. Envío de Señales a Procesos 9.5. Envío de señales a procesos Objetivos Enviar señales a procesos para controlar su actividad o finalizar su ejecución. Control de procesos con señales Una señal es una interrupción de software que se entrega a un proceso. Las señales informan eventos a un programa en ejecución. Los eventos que generan una señal pueden ser un error, un evento externo (una solicitud de E/S o un temporizador expirado) o mediante el uso explícito de un comando de envío de señal o una secuencia de teclado. La siguiente tabla enumera las señales fundamentales que los administradores de sistemas utilizan para la gestión de procesos de rutina. Consulte las señales por su nombre corto (HUP) o propio (SIGHUP). Tabla 11. Señales fundamentales de gestión de procesos 1 HUP Hangup: Informa la terminación del proceso de control de una terminal. También solicita la reinicialización del proceso (recarga de configuración) sin terminación. 2 INT Interrupción del teclado: provoca la terminación del programa. Se puede bloquear o manipular. Enviado presionando la secuencia de teclas INTR (Interrupción) ( Ctrl+C ). 3 SALIR Salir del teclado: similar a SIGINT; agrega un volcado de proceso al finalizar. Enviado presionando la secuencia de teclas SALIR ( Ctrl+\ ). 9 KILL Matar, imbloqueable: Provoca la terminación abrupta del programa. No se puede bloquear, ignorar,

or handled; consistently fatal.

15 predeterminado TERM Terminar: Provoca la terminación del programa. A diferencia de SIGKILL, se puede bloquear, ignorar o manejar. Permite que el programa complete operaciones esenciales y se autolimpie antes de su finalización. 18 CONT Continuar: enviado a un proceso para reanudarlo si se detiene. No se puede bloquear. Incluso si se maneja, siempre reanuda el proceso. 19 STOP Parada, imbloqueable: Suspende el proceso. No se puede bloquear ni manipular. 20 Detención del teclado TSTP: a diferencia de SIGSTOP, se puede bloquear, ignorar o manejar. Enviado presionando la secuencia de teclas suspender ( Ctrl+Z ).
