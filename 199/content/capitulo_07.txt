# Capítulo 4. Gestión de usuarios y grupos locales

## 4.1. Usuarios y grupos de Linux

4.1. Usuarios y grupos de Linux 4.1. Objetivos de usuarios y grupos de Linux Describir el propósito de los usuarios y grupos en un sistema Linux. Usuarios de Linux Una cuenta de usuario proporciona límites de seguridad entre personas y programas que pueden ejecutar comandos. Los usuarios tienen nombres de usuario para identificarlos ante los usuarios humanos y para facilitar el trabajo. Internamente, el sistema distingue las cuentas de usuario por el número de identificación único, el ID de usuario (UID), que se les asigna. En la mayoría de los escenarios, si un humano usa una cuenta de usuario, el sistema asigna una contraseña secreta al usuario para demostrar que es el usuario autorizado para iniciar sesión. Las cuentas de usuario son fundamentales para la seguridad del sistema. Cada proceso (programa en ejecución) en el sistema se ejecuta como un usuario específico. Cada archivo tiene un usuario específico como propietario. Con la propiedad de los archivos, el sistema aplica el control de acceso a los usuarios de los archivos. El usuario asociado con un proceso en ejecución determina los archivos y directorios a los que puede acceder ese proceso. Tipos de usuarios en sistemas Linux Los tres tipos principales de cuentas de usuario son el superusuario, los usuarios del sistema y los usuarios normales. Superusuario La cuenta de superusuario administra el sistema. El nombre del superusuario es root y el UID de la cuenta es 0. El superusuario tiene acceso total al sistema. Usuario del sistema Las cuentas de usuario del sistema son utilizadas por procesos que proporcionan servicios de soporte. Estos procesos, o demonios, normalmente no necesitan ejecutarse como superusuario y no tienen una sesión de terminal de control. A menudo se les asignan cuentas de usuario del sistema sin privilegios para proteger sus archivos y otros recursos entre sí y de los usuarios habituales del sistema. Los usuarios no inician sesión interactivamente con una cuenta de usuario del sistema. Usuario habitual La mayoría de los usuarios tienen cuentas de usuario habituales para su trabajo diario. Al igual que los usuarios del sistema, los usuarios habituales tienen acceso limitado al sistema. Utilice el comando id para mostrar información sobre el usuario que ha iniciado sesión actualmente:

user01@host:~$ id
uid=1000(user01) gid=1000(user01) groups=1000(user01) context=unconfined_u:unconfined_r:unconfined_t:s0-
s0:c0.c1023

Para ver información sobre otro usuario (usuario02 en el siguiente ejemplo), pase el nombre de usuario al comando id como

an argument:

Comandos de ejemplo que muestran información del usuario Utilice el comando ls -l para mostrar el usuario propietario de un archivo. Utilice el comando ls -ld para mostrar al usuario propietario de un directorio, en lugar del contenido de ese directorio. En el siguiente resultado, la tercera columna muestra el nombre de usuario del propietario.

user01@host:~$ ls -l mytextfile.txt

-rw-rw-r--. 1 usuario01 usuario01 0 5 de febrero 11:10 mytextfile.txt

user01@host:~$ ls -ld Documents
drwxrwxr-x. 2 user01 user01 6 Feb  5 11:10 Documents

Utilice el comando ps para ver la información del proceso. De forma predeterminada, el comando ps solo muestra los procesos que se ejecutan con el mismo UID que el usuario actual y que están asociados con el terminal en el que se ejecutó el comando ps. Puede agregar diferentes opciones para cambiar este comportamiento. Si usa las opciones awwu juntas, entonces el comando ps enumera los procesos que son propiedad de cualquier usuario asociado con una terminal (a), proporciona más información orientada al usuario para cada proceso (u) y no trunca cada línea de salida (ww). Cuentas de usuarios locales La salida de la mayoría de los comandos muestra a los usuarios por nombre, pero internamente, el sistema operativo utiliza UID para rastrear a los usuarios. Las asignaciones de nombres de usuario a UID se definen en bases de datos de información de cuentas. De forma predeterminada, los sistemas utilizan el archivo /etc/passwd para almacenar información sobre los usuarios locales. Cada línea del archivo /etc/passwd contiene información sobre un usuario. El archivo está dividido en siete campos separados por dos puntos. Una línea de ejemplo del archivo /etc/passwd proporciona información sobre el usuario user01:

user01@host:~$ cat /etc/passwd

...salida omitida...

user01:x:1000:1000:User One:/home/user01:/bin/bash

Considere cada parte del bloque de código, separada por dos puntos:

user01 : The username for this user.
x : The user's encrypted password was historically stored here; it is now a placeholder.

1000: el número UID de esta cuenta de usuario. 1000: el número GID para el grupo principal de esta cuenta de usuario. Los grupos se analizan más adelante en esta sección. Usuario uno: un breve comentario, descripción o el nombre real de este usuario.

/home/user01: The user's home directory, and the initial working directory when the login shell starts.
/bin/bash : The default shell program for this user that runs at login. Some accounts use the /sbin/nologin

shell para no permitir inicios de sesión interactivos con esa cuenta. Grupos de Linux Un grupo es una colección de usuarios que deben compartir el acceso a archivos y otros recursos del sistema. Al utilizar grupos, puede otorgar acceso a archivos a un conjunto de usuarios en lugar de a un solo usuario. Al igual que los usuarios, los grupos tienen nombres de grupo para un reconocimiento más sencillo. Internamente, el sistema distingue los grupos por el número de identificación único, el ID de grupo (GID), que se les asigna. La asignación de nombres de grupos a GID se define en las bases de datos de gestión de identidades de información de cuentas de grupos. De forma predeterminada, los sistemas utilizan el archivo /etc/group para almacenar información sobre grupos locales. Cada línea del archivo /etc/group contiene información sobre un grupo. Cada entrada de grupo se divide en cuatro campos separados por dos puntos. Una línea de ejemplo del archivo /etc/group proporciona información sobre el grupo group01:

user01@host:~$ cat /etc/group

...salida omitida...

group01:x:10000:user01,user02,user03

Considere cada parte del bloque de código, separada por dos puntos:

group01 : The name for this group.
x : Obsolete group password field; it is now a placeholder.

10000: el número GID para este grupo (10000).

user01,user02,user03 : A list of users that are members of this group as one of their supplementary groups.

Grupos primarios y grupos suplementarios Cada usuario tiene exactamente un grupo primario. Para los usuarios locales, este grupo aparece listado por GID en el archivo /etc/passwd. El grupo principal posee los archivos que crea el usuario. Cuando se crea un usuario normal, se crea un grupo con el mismo nombre que el usuario, que será el grupo principal del usuario. El usuario es el único miembro de este Grupo Privado de Usuarios. Este diseño de pertenencia a grupos simplifica la gestión de permisos de archivos al separar los grupos de usuarios de forma predeterminada. Los usuarios también pueden tener grupos suplementarios. La membresía en grupos suplementarios se almacena en el archivo /etc/group. Por ejemplo, si el usuario user01 tiene un grupo primario user01 y grupos suplementarios wheel y webadmin, entonces ese usuario puede leer archivos que cualquiera de esos tres grupos puede leer. El comando id puede mostrar la pertenencia a un grupo de un usuario. En el siguiente ejemplo, el usuario usuario01 tiene el grupo usuario01 como su grupo principal (gid). El elemento de grupos enumera todas las membresías de grupo para este usuario, y el usuario también tiene los grupos rueda y grupo01 como grupos suplementarios.

Obtención de acceso de superusuario Objetivos Cambie a la cuenta de superusuario para administrar un sistema Linux y conceda acceso de superusuario a otros usuarios mediante Sudo. El superusuario La mayoría de los sistemas operativos tienen un superusuario que tiene todo el poder sobre el sistema. En Red Hat Enterprise Linux, el superusuario es el usuario root. Este usuario tiene el poder de anular los privilegios regulares en el sistema de archivos y usted puede usarlo para gestionar y administrar el sistema. Para tareas como instalar o eliminar software y administrar archivos y directorios del sistema, los usuarios deben escalar sus privilegios al usuario raíz. Por lo general, sólo el usuario root puede controlar la mayoría de los dispositivos, pero se aplican algunas excepciones. Por ejemplo, los usuarios habituales pueden controlar dispositivos extraíbles, como dispositivos USB. Por lo tanto, los usuarios normales pueden agregar y eliminar archivos y administrar un dispositivo extraíble, pero solo el usuario raíz puede administrar los discos duros de forma predeterminada. Este privilegio ilimitado, sin embargo, conlleva responsabilidad. El usuario root tiene poder ilimitado para dañar el sistema: puede eliminar archivos y directorios, eliminar cuentas de usuario, agregar puertas traseras, etc. Si la cuenta de usuario root se ve comprometida, entonces el sistema está en peligro y usted podría perder el control administrativo. Red Hat anima a los administradores de sistemas a iniciar sesión siempre como usuarios normales y a escalar privilegios a root solo cuando sea necesario. Importante En RHEL 10, la cuenta raíz no tiene una contraseña válida de forma predeterminada, por lo que no puede iniciar sesión directamente como usuario raíz con una contraseña. La cuenta raíz en Linux es similar a la cuenta de administrador local en Microsoft Windows. En Linux, la mayoría de los administradores de sistemas inician sesión en el sistema como usuarios sin privilegios y utilizan varias herramientas para obtener privilegios de root temporalmente. Advertencia Los usuarios de Microsoft Windows pueden estar familiarizados con la práctica de iniciar sesión como usuario administrador local.

to perform system administrator duties. Today, this practice is not recommended; users obtain privileges to

realizar la administración por membresía en el grupo de Administradores. De manera similar, en RHEL, Red Hat recomienda que los administradores del sistema nunca inicien sesión directamente como root. En cambio, los administradores del sistema inician sesión como un usuario normal y utilizan mecanismos para obtener temporalmente privilegios de superusuario (su, sudo o PolicyKit, por ejemplo). Cuando se inicia sesión como root, todo el entorno de escritorio se ejecuta innecesariamente con privilegios administrativos. Una vulnerabilidad de seguridad que normalmente podría comprometer sólo una cuenta de usuario normal puede potencialmente comprometer todo el sistema. Cambio de cuentas de usuario Con el comando su, los usuarios pueden cambiar a una cuenta de usuario diferente. Si ejecuta el comando su desde una cuenta de usuario normal con otra cuenta de usuario como parámetro, debe proporcionar la contraseña de la cuenta a la que cambiar.

4.3. Obtención de acceso de superusuario Cuando el usuario root ejecuta el comando su, no es necesario ingresar la contraseña del usuario. Este ejemplo utiliza el comando su de la cuenta usuario01 para cambiar a la cuenta usuario02:

user01@host:~$ su - user02

Contraseña: usuario02_contraseña

user02@host:~$

Si omite el nombre de usuario, entonces el comando su o su - intenta cambiar a root de forma predeterminada.

user01@host:~$ su -

Contraseña: contraseña_raíz

root@host:~#

El comando su inicia un shell interactivo sin inicio de sesión, pero el comando su - (con la opción de guión) inicia un shell de inicio de sesión interactivo. La diferencia entre los dos comandos es que el shell se inicializa de maneras ligeramente diferentes cuando se inicia, dependiendo de si se trata de un shell de inicio de sesión o de un shell sin inicio de sesión.

su -

Inicia una nueva sesión de inicio de sesión interactiva como el usuario al que está cambiando y utiliza la configuración del entorno del usuario de destino. su Inicia un shell interactivo como el usuario al que está cambiando, pero utiliza parcialmente la configuración del entorno del usuario original. Generalmente, los administradores deben ejecutar el comando su - para obtener un shell con la configuración del entorno del usuario de destino. Este enfoque garantiza que el shell resultante se inicialice de la misma manera que lo haría si ese usuario iniciara sesión como de costumbre. Para

more information, refer to the bash(1) man page.

Ejecutar comandos con Sudo En RHEL 10, la cuenta raíz no tiene una contraseña válida de forma predeterminada. En otras palabras, no existe una contraseña que permita a un usuario autenticarse y acceder a la cuenta raíz, ya sea intentando iniciar sesión directamente como raíz o intentando utilizar el comando su. Importante El administrador del sistema podría establecer una contraseña para la cuenta raíz, lo que le permitiría convertirse en usuario raíz con el comando su si conoce esa contraseña. Por razones de seguridad, los administradores del sistema normalmente no establecen una contraseña válida para la cuenta raíz. En ese caso, para obtener acceso a la cuenta raíz, los usuarios deben usar una contraseña normal para iniciar sesión en una cuenta de usuario normal y luego usar la

sudo command to become the root user or to run commands as the root user.

A diferencia del comando su, el comando sudo normalmente requiere que los usuarios ingresen su propia contraseña para la autenticación, no la contraseña de la cuenta de usuario a la que intentan acceder. Es decir, los usuarios que utilizan el comando sudo para ejecutar comandos como usuario root no necesitan conocer la contraseña de root. En cambio, utilizan sus propias contraseñas para autenticar el acceso.





4.3. Obtener acceso de superusuario Importante De forma predeterminada, el comando sudo almacena en caché su contraseña durante cinco minutos después de una autenticación exitosa. Como resultado, no necesita ingresar su contraseña varias veces si ejecuta una serie rápida de comandos sudo. Puede ejecutar el comando sudo -k para eliminar inmediatamente su contraseña del caché. Además, puede configurar el comando sudo para permitir que usuarios específicos ejecuten cualquier comando como otro usuario, o solo algunos comandos como ese usuario. Por ejemplo, si configura el comando sudo para permitir que el usuario user01 ejecute

the usermod command as root, then you can run the following command to lock or unlock a user account:
user01@host:~$ sudo usermod -L user02

[sudo] contraseña para usuario01: usuario01_contraseña

user01@host:~$ su - user02

Contraseña: usuario02_contraseña

su: Authentication failure
user01@host:~$

Si un usuario intenta ejecutar un comando como otro usuario y la configuración de Sudo no lo permite, Sudo bloquea el comando, registra el intento y envía un correo electrónico al usuario raíz de forma predeterminada.

user02@host:~$ sudo tail /var/log/secure

[sudo] contraseña para usuario02: usuario02_contraseña usuario02 no está en el archivo sudoers.  Este incidente será reportado.

user02@host:~$

Otro beneficio del comando sudo es que registra de forma predeterminada todos los comandos ejecutados en el archivo /var/log/secure.

user01@host:~$ sudo tail /var/log/secure

... salida omitida... 9 de marzo 20:45:46 host sudo[2577]: usuario01: TTY=pts/0; PWD=/casa/usuario01; USUARIO=raíz; COMMAND=/sbin/usermod -L user02 ...salida omitida... En Red Hat Enterprise Linux 7 y versiones posteriores, todos los miembros del grupo wheel pueden usar sudo para ejecutar comandos como cualquier usuario, incluido root, usando su propia contraseña. Advertencia Históricamente, los sistemas UNIX utilizan la membresía del grupo de ruedas para otorgar o controlar el acceso de superusuario. RHEL 6 y versiones anteriores no otorgan al grupo de ruedas ningún privilegio especial de forma predeterminada. Los administradores del sistema que anteriormente utilizaron este grupo para un propósito no estándar deben actualizar su configuración anterior para evitar que usuarios inesperados y no autorizados obtengan acceso administrativo en sistemas RHEL 7 y posteriores. Obtener un Shell raíz interactivo con Sudo Para acceder a la cuenta raíz con el comando sudo, utilice el comando sudo -i. Si crea un usuario y a ese usuario se le asigna el UID del usuario eliminado, entonces la nueva cuenta posee esos archivos, lo cual es un riesgo para la seguridad. Normalmente, las políticas de seguridad de la organización no permiten la eliminación de cuentas de usuario y, en su lugar, bloquean su uso para evitar este escenario. El siguiente ejemplo demuestra cómo este escenario puede provocar una fuga de información:

root@host:~# useradd user01

drwx------.  4 user01     user01       93 May  9 17:40 user01
root@host:~# userdel user01
root@host ~# ls -l /home
drwx------.  4       1000       1000   93 May  9 17:40 user01
root@host:~# useradd -u 1000 user02
root@host:~# ls -l /home
drwx------.  4 user02     user02       93 May  9 17:40 user01
drwx------.  4 user02     user02       93 May  9 17:41 user02

Observe que el usuario usuario02 ahora posee todos los archivos que anteriormente poseía el usuario usuario01. root@host:~# passwd user01

Administrar grupos locales Puede administrar grupos usando el menú Cuentas en la consola web de RHEL (si está habilitado) o usando herramientas de línea de comandos. Esta sección se centra en las herramientas de línea de comandos que puede usar desde un símbolo del shell, ya sea localmente, a través de una conexión SSH o en la consola web de RHEL. Crear grupos desde la línea de comando El comando groupadd crea grupos. Sin opciones, el comando groupadd utiliza el siguiente número de ID de grupo (GID) disponible del rango que las variables GID_MIN y GID_MAX especifican en el archivo /etc/login.defs. De forma predeterminada, el comando asigna un valor de GID que es mayor que cualquier otro GID existente, incluso si hay disponible un valor inferior. La opción -g del comando groupadd especifica un GID que utilizará el grupo.

root@host:~# groupadd -g 10000 group01
root@host:~# tail /etc/group

...salida omitida...

group01:x:10000:

Nota Debido a que el comando useradd crea automáticamente grupos privados de usuarios con números GID asignados desde 1000 en adelante, algunos administradores reservan un rango especial de números GID altos para usar cuando crean grupos suplementarios para otros fines. Sin embargo, esta administración adicional es innecesaria porque no es necesario que el UID y el GID principal de un usuario sean el mismo número. La opción groupadd comando -r crea grupos de sistemas. Al igual que con los grupos normales, los grupos del sistema utilizan un GID del rango de GID del sistema válidos enumerados en el archivo /etc/login.defs. Los elementos de configuración SYS_GID_MIN y SYS_GID_MAX en el archivo /etc/login.defs definen el rango de GID del sistema.

root@host:~# groupadd -r group02
root@host:~# tail /etc/group

...salida omitida...

group01:x:10000:
group02:x:988:

Modificación de grupos existentes desde la línea de comando El comando groupmod cambia las propiedades de un grupo existente. La opción -n del comando groupmod especifica un nuevo nombre para el grupo.

Importante No puede eliminar un grupo si es el grupo principal predeterminado de un usuario existente. De manera similar a usar el comando userdel, asegúrese de ubicar primero los archivos que posee el grupo para evitar posibles riesgos de seguridad. Pertenencia a grupos primarios y suplementarios El grupo primario predeterminado de un usuario es el grupo que aparece en la línea que define la cuenta del usuario en el archivo /etc/passwd. Un usuario sólo puede pertenecer a un grupo principal a la vez. Los grupos suplementarios de un usuario son los grupos adicionales que están configurados para el usuario en el archivo /etc/group. Un usuario puede pertenecer a muchos grupos complementarios. Para configurar permisos de archivos basados ​​en grupos, no existe ninguna diferencia entre los grupos primarios y suplementarios de un usuario. Si el usuario pertenece a algún grupo al que se le asigna acceso a archivos específicos, entonces ese usuario tiene acceso a esos archivos. La única distinción entre las membresías principal y complementaria de un usuario es cuando un usuario crea un archivo. Los archivos nuevos deben tener un propietario de usuario y un propietario de grupo, que se asigna cuando se crea el archivo. El grupo principal actual del usuario se utiliza para la propiedad del grupo del nuevo archivo, a menos que las opciones del comando lo anulen. Cambiar la membresía del grupo desde la línea de comando Utilice el comando usermod -g para cambiar el grupo principal predeterminado de un usuario.

root@host:~# id user02
uid=1006(user02) gid=10000(group01) groups=10000(group01)

Importante El uso de la opción -g para cambiar el grupo principal predeterminado de un usuario no agrega automáticamente el grupo principal antiguo a la lista de grupos suplementarios del usuario. Puede ver este comportamiento en el ejemplo anterior. Además, el uso de esta opción no cambia la propiedad del grupo de ningún archivo existente en el directorio de inicio del usuario ni en ninguna otra parte del sistema. Utilice el comando groupmod -aU para agregar una lista de uno o más usuarios a un grupo suplementario. El nombre del grupo es el argumento final del comando.

root@host:~# id user03
uid=1007(user03) gid=1009(user03) groups=1009(user03)
root@host:~# groupmod -aU user03 group01
root@host:~# id user03
uid=1007(user03) gid=1009(user03) groups=1009(user03),10000(group01)

Advertencia La opción -a del comando groupmod habilita el modo de agregar. Sin la opción -a, el comando reemplaza el conjunto existente de usuarios que son miembros del grupo por aquellos que están incluidos en la lista de la opción -U. También puede usar el comando usermod -aG para agregar un usuario a uno o más grupos existentes sin eliminarlo de sus grupos primarios o secundarios actuales. La opción -a agrega el usuario al nuevo grupo sin eliminarlo del grupo existente. La opción -G especifica una lista de grupos suplementarios a los que se debe agregar el usuario.

root@host:~# usermod -aG group01 user03

Cambiar temporalmente su grupo principal El grupo principal actual de un usuario determina el grupo propietario de los archivos recién creados. Sin embargo, puedes cambiar temporalmente tu grupo principal actual a uno de los grupos suplementarios al que perteneces. Puede hacer esto inmediatamente antes de crear un conjunto de archivos que desea que ese grupo posea, en lugar de su grupo principal habitual. Utilice el comando newgrp para cambiar su grupo principal para el símbolo del shell actual. Este cambio temporal no afecta a otros indicadores del shell en el mismo sistema. Puede cambiar su grupo principal actual a cualquiera de los grupos suplementarios a los que pertenece o volver a su grupo principal predeterminado. Sólo un grupo a la vez puede ser su grupo principal actual. Si cierra sesión y vuelve a iniciarla, su grupo principal predeterminado en ese indicador de shell volverá a ser el actual. En este ejemplo, el grupo group01 se convierte temporalmente en el grupo principal de este usuario.

Contraseñas ocultas y política de contraseñas Originalmente, las contraseñas cifradas se almacenaban en el archivo /etc/passwd, legible en todo el mundo. file has nine colon-separated fields:

4.9. Gestión de contraseñas de usuario OuNgGC5Mx2RrCO4JOXtR2VJfTA8dLPxa7NV1tvhziHC: el hash criptográfico de la contraseña del usuario. Este segmento es el resultado de combinar la contraseña salt y de texto sin formato, y luego usar el algoritmo hash criptográfico para generar el hash de la contraseña. La razón principal para combinar un salt con la contraseña es defenderse contra ataques que utilizan listas precalculadas de hashes de contraseñas. Agregar sales amplía la cantidad de posibles hashes que deben verificarse para cada palabra que podría ser una posible contraseña, lo que hace que sea mucho más difícil usar una lista precalculada debido a su tamaño. Si un atacante obtiene una copia de un archivo /etc/shadow que usa sales, entonces necesita adivinar las contraseñas con fuerza bruta, lo que requiere más tiempo y esfuerzo. Nota El algoritmo de hash predeterminado en RHEL 10 es yescrypt, una función de derivación de clave basada en contraseña (KDF) y un esquema de hash de contraseña basado en primitivas criptográficas aprobadas por NIST, desarrollado por Solar Designer. Este algoritmo hash predeterminado es un cambio con respecto a RHEL 9, que utilizaba el algoritmo hash SHA-512 de Ulrich Drepper de forma predeterminada. RHEL 10 todavía reconoce los hash de contraseña SHA-512 ($6$) que pueden estar en el archivo /etc/shadow, pero las contraseñas nuevas y actualizadas se crean usando yescrypt, que Red Hat considera más seguro. Para obtener más información sobre los algoritmos de hash de contraseñas de usuarios locales en RHEL, consulte la página del manual de crypt(5) y el artículo Acerca de los algoritmos de hash de contraseñas de usuarios locales en RHEL. Verificación de contraseña Cuando un usuario intenta iniciar sesión, el sistema busca la entrada del usuario en el archivo /etc/shadow y combina el salt del usuario con la contraseña escrita en texto sin formato. Luego, el sistema codifica criptográficamente la combinación de la contraseña salt y de texto sin formato con el algoritmo de hash especificado. Si el resultado coincide con el hash criptográfico, entonces el usuario escribió la contraseña correcta. Si el resultado no coincide con el hash criptográfico, entonces el usuario escribió la contraseña incorrecta y el intento de inicio de sesión falla. Este método permite que el sistema determine si el usuario escribió la contraseña correcta sin almacenarla en un formato utilizable para iniciar sesión. El shell nologin El shell nologin actúa como un shell de reemplazo para las cuentas de usuario que no están destinadas a iniciar sesión interactivamente en el sistema. Una buena práctica de seguridad es desactivar una cuenta para que no pueda iniciar sesión en el sistema cuando la cuenta no lo requiera. Por ejemplo, un servidor de correo puede requerir una cuenta para almacenar el correo y una contraseña para que el usuario se autentique con un cliente de correo para recuperar el correo. Si el usuario intenta iniciar sesión en el sistema directamente, el shell nologin cierra la conexión.

root@host:~# usermod -s /sbin/nologin newapp

4.12. Resumen 4.12. Resumen En esta lección, aprendió sobre los diferentes tipos de cuentas de usuario de Linux y cómo administrarlas. En Linux, los tipos de cuentas de usuario son superusuario (el usuario raíz), usuarios del sistema y usuarios normales. Los usuarios y grupos se utilizan para proteger y restringir el acceso a archivos, procesos y otros recursos del sistema. Cada usuario tiene un grupo primario y puede pertenecer a uno o más grupos suplementarios. La información de usuarios y grupos está contenida en los archivos /etc/passwd, /etc/group y /etc/shadow. Para administrar cuentas de usuario desde la línea de comando, normalmente se utiliza la cuenta de superusuario del sistema. Puede ejecutar comandos como superusuario con los comandos su y sudo. El superusuario puede configurar una política de administración de contraseñas que requiera que un usuario cambie su contraseña periódicamente. El superusuario también puede bloquear el acceso a una cuenta de usuario en una fecha determinada y puede desactivar el programa shell de una cuenta de usuario para evitar inicios de sesión interactivos. Un usuario del sistema o un usuario normal puede realizar algunos cambios menores en su propia cuenta de usuario, como cambiar la contraseña.
